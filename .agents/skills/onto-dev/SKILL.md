# OntoAgents 开发工作流（立项 → 方案 → 实现 → 交付回写）

> 本 skill 是 [AGENTS.md](../../../AGENTS.md) 硬性纪律的**操作蒸馏**。规则冲突时以 AGENTS.md 为权威——改规则先改 AGENTS.md，本 skill 随轮跟进。四区导览见 [docs/README.md](../../../docs/README.md)。

## 0. 开工前（每次都做）

1. 读 AGENTS.md 头部版本号与「开发前必读」表——版本号不凭记忆，以各档头部为准；
2. 查开放需求：`docs/19_REQ状态索引.md`（机读单点；**禁止对 docs/ 做全库 📋 语义扫描**——首次全量盘点实测 15 分钟，本档查询单点为秒级）；
3. 大档按需读：01/02/03/18/20 先读头部导读与版本号，grep 定位行号后分段读，禁止无目的全文通读。

## 1. 需求立项（新功能 / 行为变更）

- **领号（并发安全后缀制，REQ-605-06e2 起，118 号 §3.2）**：`docs/18_REQ编号注册表.md` 是 REQ 编号唯一分配权威。①`git fetch origin` 核对 main 最新号；②序号段 = 最大 seq+1；③后缀 = 本机 4 位随机（`openssl rand -hex 2`）——完整串如 `REQ-606-a3f9` 即唯一键，**并发撞序号段免顺延**；里程碑随批同后缀（`M<seq>-<rand4>`）；存量 REQ-1~604 纯序号永久有效。正式账本行强制全串；行为级改动仍**全仓 grep 验证语义无撞**（撞的是需求内容而非编号）。
- **领号当轮必须**（缺一即违反纪律 1）：
  - `docs/18` 加注册行（标题＋详设指针＋状态 📋 挂里程碑）；
  - `docs/19` 加行（六列：号/状态/一句话/M/归属/详录）；
  - 归属需求档（01 智能体 / 03 本体 / 11 知识库）需求行＋需求池/件表；
  - 方案档落 `docs/research/<模块子目录>/`——编号沿各模块惯例、目录内顺延；**引用写全路径，禁裸「XX 号」**（跨目录重号是既知病史：双 113 号在案）。
- 评估件合法：零代码评估/专项评审可先于开发立项（REQ-560 先例）；为图而图检查沿 REQ-205。

## 2. 实现（纪律速查）

- **git**：只 add 实际修改的文件路径（禁 `git add .`）；**任务边界即提交**——每完成一个独立任务不留未提交改动；commit message 概述变更要点；commit 后 push origin/main。
- **迁移号**：SQLite 迁移**开工日 `ls migrations/ | max+1`**——预留在案号会让位（079/087 先例）。
- **并发面**（TurnLoop/delegate/runner）：附 `go test -race ./internal/chat/` 结果一行。
- **前端动线**：按 `docs/20_回归冒烟清单.md` 对应模块节 headless 冒烟；截图留本地 `smoke/`（gitignored，勿 `git add -f` 入库）。

## 3. 交付回写清单（交付当轮逐项过，缺一即欠账）

| # | 动作 | 单源边界 |

| 2 | `docs/18` 注册行迁 18A；`docs/19` 删行＋计数顺修 | 人读/机读分层（REQ-499：查「待开发什么」只读 19 号） |

| 5 | AGENTS.md 当前状态窗置顶一行（≤600B 指针式）＋末条滚动移出 | 一行式不超预算（doccheck 校验） |

## 4. 文档归区（30 秒判断「放哪」）

| 要写什么 | 去哪 |
| --- | --- |
| 系统**现在是什么样** | `docs/handbook/<模块>/`（frontmatter 四字段：module/topic/desc/synced） |
| **为什么**这么做（调研/方案/评审） | `docs/research/<模块>/`（编号方案档） |
| 需求 / 进度 / 治理记账 | `docs/` 根级编号档 |
| 教学向浓缩卡 | `docs/learning/`（源指针指向原始档，**内容一律不复制**） |

- 拿不准：过程稿先落 research，成熟后再提炼进 handbook——**现状类宁缺勿滥**，防止 handbook 重蹈膨胀（过程档曾占 58% 实证）。
- **禁入 handbook 的形态**（2026-11-01 三轮梳理清出的历史包袱，勿回潮）：体检结论归档、迭代表/版本表全量行、交付详录、立项期预告、「📋 待领取」式状态列（状态权威=docs/02 §12＋18A）。

## 5. 门禁

- clone 后执行一次 `git config core.hooksPath hooks`；此后 pre-commit 自动跑 doccheck（REQ 引用在册/头部版本一致/handbook 结构项）＋纪律 7 非阻塞提醒（行为面代码改动时 echo 自查提示）。
- 手动：`cd backend && go test -count=1 ./internal/doccheck`。
- 诚实边界：doccheck 只保**结构**（档存在/编号在册/头部一致）——「handbook 与代码一致」靠纪律 7 自觉＋拾补轮。交付时自问一句：**本轮行为改动，对应模块现状档更新了吗？**

## 6. 并行会话防撞车

- 提交注声明基底（`基底 <hash>`）防覆写；号/M 号被并行批占用时顺延并留版本注（沿 18 v6.07 phantom 注先例）。
- push 被拒（fetch first）＝有并行批已推：**先整合再推**——冲突按语义解（账本行并集、本侧行版本号顺延到远端之后、对已迁移文件的远端修改移植到新址），参考 a2adf00 整合轮；整合后重跑 doccheck＋所属模块测试＋docs/20 对应节冒烟再推。
