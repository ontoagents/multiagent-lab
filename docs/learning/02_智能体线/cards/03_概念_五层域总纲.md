**五层域**是平台对五阶段范式的架构落点（02 §6 五层总纲为技术事实源，53~56 号各一档域事实源）：

| 层 | 职责 | 代码承载 |
| --- | --- | --- |
| Model | 推理后端与连接 | internal/inference 注册表（eino-adk 内置+外部 CLI 适配器矩阵） |
| Context | 模型每轮真正看到什么 | internal/chat/context.go（预算/压缩/剪枝/召回） |
| Harness | 一次运行的系统 | assembler 装配+hooks 防护+审批 gating+verify 背压+沙箱 |
| Loop | 跑多久、断了怎么办 | checkpoint+scheduler+max_iteration+usage |
| Graph | 多个智能体怎么组队 | agent_as_tool/transfer/workflow/subagent 事件 |

**层边界是理解代码的钥匙**：审批 gating 的策略归 Harness，但挂起机制的载体（checkpoint）归 Loop；工具装配归 Harness，工具结果要不要进下一轮上下文归 Context。每张实践卡（08~12）按层展开。

**配置聚合口径**：智能体侧板把五层配置并列成页签（REQ-219），但「侧板配置聚合呈现≠层职责混淆」——UI 归组是产品动线，层职责是工程边界；外部 CLI 推理后端不走平台装配链，Harness 层配置对其不生效（诚实边界）。
