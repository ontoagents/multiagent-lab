知识资产在本平台按职责分三个平面，一一对应本体模块的五栏 IA：

- **构建平面**（构建栏）：编辑态事实源。所有变更收敛到 spec 资产上，过版本门禁（If-Match 乐观锁）与校验管线（结构+引用完整性），strict 模式下再过质量门禁——**不变量：进库的 spec 永远通过校验**。六条构建路径（见[实践·六路径构建](09_实践_六路径构建.md)）只是不同的写入入口，写路径唯一。
- **运行平面**（运行栏）：查询态载体。方案把一个或多个本体装载进引擎（Oxigraph named graph 隔离，per-graph 对账 REQ-320），对外暴露 SPARQL 端点——**不变量：运行图是某个已入库版本的投影**（编辑后需重装载才可见，运行面门禁与质量快照 REQ-234 兜底）。
- **消费与审计平面**（消费与审计栏）：消费面=facade MCP 工具面（智能体/外部客户端标准化读，见[消费与审计三件套](11_实践_消费与审计三件套.md)）；审计面=治理动作五事件+PROV-O 溯源导出——**不变量：每次资产变更可溯源到人/动线/版本**。

理解三平面的价值在于定位问题：查询结果「不对」时先分清是**编辑态没写对**（构建平面校验）、**运行图没更新**（运行平面装载滞后）还是**消费面读错了图**（伴生图/默认图路由），三者的修复动作完全不同。
