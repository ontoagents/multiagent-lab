本体资产的消费与审计有三件套，落点各不相同：

**① facade MCP 工具面（21 件，runtime-manager/internal/facade/）**：查询类 7 件（get_concept/list_instances/sparql_query/**check_answerable** 可回答性预检〔REQ-415/M211，2026-10-24〕等）+ 本体操作 13 件（spec CRUD/校验/CQ 基准，REQ-366）+ 时序查询 companion_history（REQ-368）。统一入口 `/mcp`，按 ontology_id 路由到 running 方案引擎；平台智能体挂载本体时自动并入（扩展工具按 `agent.onto_ops` 门控，写类入 danger 档审批）。外部 MCP 客户端直连同一端点——**一致性来源：facade 与 UI 都读同一构建平面/引擎，无第二事实源**。

**② KG 抽取与治理（backend/internal/kg）**：知识库文档抽取的实体/关系/claim 三表+全局问答管线（GraphRAG 语义层），展示与治理在知识库模块（边界 REQ-290：本体侧消费栏不重复承载）。

**③ 决策审计与 PROV-O**：治理动作（PUT spec/import/merge/fork/delete 五事件）经审计代理落 onto_decision 表，前端决策审计页签可查溯源链（32 跳封顶）并导出 PROV-O Turtle（Go 原生模板零依赖）。

实践要点：给外部系统/Agent 接本体，优先给 facade 端点而不是裸 SPARQL（工具面带路由/白名单/时序/基准确语义）；排查「消费数据不对」时先走 [三平面架构](05_三平面架构.md) 的定位法，再查审计链确认最近一次变更。
