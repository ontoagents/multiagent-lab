## 0. 产品核心目标与设计原则

**平台级定位（2026-10-28 Q-23 更新：定位论述=面向专业个人的工作学习助手）**：本产品是**面向专业个人的工作学习助手——以本体为知识底座：知识不是一堆文档，而是可查询、可审计、可出题的结构化资产（单机自部署）**（01 §8 Q-23；用户画像=知识密集型专业个人：工程师/教师/合规/研究者/医生；「迷你版 Coze」对标论述正式放弃；**Q-21 工程化成熟度裁判——可靠性/安全/可运维/性能——与单机边界保留**；「学习动线/示例先行」等 P1~P6 原则保留为交互特征，沿 v0.27 处理先例）——分层叙事：**智能体工程**（Eino ADK 引擎：对话/多智能体协作/知识·技能·本体增强，01）+**本体工程**（差异化知识底座：构建→资产→运行→消费审计全流程，03）双核心，个人助手为产品面；知识库/技能为两线共用的能力扩展，项目/设置为工作空间与配置支撑。下述核心目标表述**限定于本体主线（B 线）的模块内叙事**：

**产品核心目标（B 线·本体）：本体的构建、运行、使用。** 平台一切模块围绕这个目标分工——有的模块生产本体，有的模块让本体跑起来，有的模块消费本体，其余模块为这三段提供工作空间、能力扩展与配置支撑。界面组织的评判标准只有一条：**是否让使用者更快走通「构建→运行→使用」的完整闭环，并理解每一步为什么这样做。**

### 2.3 最终统一：差异只在生成段，收敛在资产段

**所有路径殊途同归**——生成方式不同，生成之后完全相同：

```
六条路径（各自生成/引导方式）          统一收敛层
┌─────────────────────┐
│ 1 手工向导            │──┐
│ 2 OntoChat 对话流      │──┤

└─────────────────────┘      → 版本/源码视图 → 运行方案挂载 → MCP onto_*
                                → 对话消费（REQ-19c）→ 消费与审计（第五栏）
```

这是教学价值的关键设计：**学习者沿任意一条路径走通后，后半程（资产→运行→使用→审计）的技能完全迁移**。学习中心的七阶段理论骨架（REQ-74）即这条统一链路的概念化表达。

### 3.2 与本体的双向关系

- **KB → 本体**（构建方向）：REQ-108——KB 作为本体构建数据源，入口在构建栏第 6 路径。
