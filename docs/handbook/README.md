## 编号口径声明

**编号按目录独立，跨目录同号合法**（如 90 号在 `01_整体设计/` 与 `04_本体/` 两处并存）——引用一律写全路径消歧，**禁止裸「XX 号」**。编号沿用 docs/18 注册表全局号与本地号段现状，**不回收、不重编**；带日期后缀的存量文件名暂不追改（收敛另轮）。`00_` 保留给模块导读页（页面显示「模块导读」）。

## 写作边界：只写现状，不写交付详录

本目录各档**只写当前实现状态**（已交付能力总表、代码落点、机制现状）；产品交付详录在需求档迭代表与 20 号验证记录。产品行为、能力或决策变化时同步对应现状档，模块导读与子模块表按归属选择；纯笔误、等价重构、测试或开发配置整理不触发全套回写。现行规则见 [AGENTS.md](../../AGENTS.md) 纪律 7/8。

**主要功能清单（2026-11-06 增设）**：各模块导读页（`00_` 档）维护一节「主要功能清单」——结构化树形（**功能域 → 功能项**两层，用户视角一句话、不挂 REQ 号），是模块当前生效主要功能的横切面，回答「现在能做什么」。与「已交付能力总表」分工：总表答「何时由哪个 REQ 交付」（交付账本），清单不重复账本内容。**产品功能交付或变更后，同步更新对应模块树的条目（增删改/归并）**；模块功能域结构变化（新增域/域归并）同轮调整树形。

## frontmatter 约定

每档必带四字段：`module`（所属模块中文名）/ `topic`（主题一句话）/ `desc`（一句话现状摘要）/ `synced`（最后同步日期）；模块导读页另带 `role: home` 与 `req`/`docs`/`decisions` 源指针（沿现状导读页惯例）。**本 README 豁免 frontmatter。**
