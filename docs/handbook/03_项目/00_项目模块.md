# 项目（Project）

## 产品定位

项目 = **一组成员智能体 + 协作方式 + 项目级约束 + 本地文件空间**的组合工作空间。项目下挂多个对话，每个对话由成员团队协作处理；绑定本地目录后，项目同时成为"对话产物落地 + 现有代码/文档被 Agent 读写"的双向工作区。

> **Q-24 实体反转注（2026-10-31，REQ-548~551 全数交付）**：工作区自本批起是**项目之上的独立领域容器实体**（非项目的显示层别名）——工作区管「场景与上下文」（默认库/方案/智能体+直挂对话+笔记本+记忆），项目保留执行容器全部现状（目录/Git/文件/团队）。产品入口=项目模块内容区顶部「项目｜工作区」双页签；实现状态详档=[01_工作区](01_工作区.md)，方案档=[106 号](docs/research/02_智能体/106_工作区领域层可行方案_20261031.md)。导航项改名仍挂 Q-23 衍生①。

> **参赛专项注（2026-10-24，两件均已交付）**：**REQ-417 协作研发场景模板与种子 ✅ M213**——DevTeamTemplate 挂项目页空态：规划者/编码者/审查者三角色 agent_as_tool 模板一键创建（同名 -2 后缀）+种子会话真实落库+两种子任务简报复制+演示动线五步（详 01 §3.10/02 §12 M213）；**REQ-416③ 外部 A2A 成员进协作面 ✅ M212**——连接器 kind=a2a 注册的外部智能体可作为成员被委派（见下表与智能体模块档）。

## 设计原理

- **三种协作模式**：
  - `agent_as_tool`（推荐）：主 Agent 把成员 Agent 当工具调用（ADK AgentTool）——上下文隔离、可并行、事件清晰；
  - `transfer`：主 Agent 转移控制权给成员（ADK SetSubAgents）——对照学习两种编排语义；
  - `single`：仅一个成员时退化为单 Agent。
- **事件时间线**：成员 Agent 的内部事件（工具调用/再委派）会透传到对话时间线并标注来源 Agent，协作过程完全可见。
- **本地目录即授权范围**：项目绑定本地目录后，模型获得该目录内的读写能力——`list_files` 列目录、`read_file` 读文本（≤1MB）、`save_file` 写产物（同名加时间戳不覆盖）；路径经安全拼接强制限制在目录内（拒绝绝对路径/`..`/符号链接逃逸），文件操作全部出现在过程时间线可审计。
- **产物闭环**：save_file 写盘成功 → 产物元数据入库 → 文件侧边栏可见可下载 → Git 视图能看到变更（分支/提交历史/diff）。
- **项目级约束**：一段追加给全部成员的统一指令（如"始终中文、先结论后依据"）。
- **工作流编排（REQ-33/205 ✅ M40，2026-10-23）**：`workflow_mode` 三模式（sequential/parallel/loop）以 ADK 工作流原语兑现——成员即节点（协调者首个+名序；loop 上限 3），`free` 保持模型自主编排。
