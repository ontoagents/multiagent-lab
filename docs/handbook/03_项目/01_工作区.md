## 定位与分层

```
工作区 Workspace（领域容器：管"场景与上下文"）
 ├─ 默认知识库 / 默认本体方案（只列 running）/ 默认智能体（三可空默认）
 ├─ 直挂对话（scope='agent' + workspace_id）
 ├─ 笔记本（REQ-495，一对多宿主）
 ├─ 记忆（REQ-551：跨会话个人记忆作用域，可审计口径）
 └─ 项目 × N（REQ-550：可选归属）
      项目 Project（执行容器：目录绑定/Git/文件三件套/团队——现状零变化）
```

分工：**工作区回答「这类工作用什么知识、什么方案、什么助手」，项目回答「产物写到哪、Git 怎么管」**。对话归属互斥（project_id XOR workspace_id，应用层校验；schema 级 scope CHECK 不动——SQLite 无法 ALTER，scope 表运行形态、workspace_id 表领域归属正交）。

## 实现要点（详设=106 号，此处只留骨架）

- **创建时继承（写时复制）**：工作区默认值只在 CreateConversation store 层默认值填充段一次写入会话行（`ResolveConvDefaults` 单点，优先级=请求显式参数 > 项目转发 > 工作区默认 > 零值）——运行期装配链/recallKB 单库门禁/retrieval 事件契约**零改动**；显式关 chip 不被复活；改默认不影响已建会话（批量刷新走「应用到现有会话」幂等动作，只覆写仍处继承值的行）。
- **外键两类策略**：config 引用列（default_kb_id/default_profile_id/default_agent_id）裸 TEXT 无 FK——失效=求值时校验存在性静默回落零值；归属列（conversation/project.workspace_id→workspace）REFERENCES ON DELETE SET NULL（删工作区对话回落智能体页，消息资产保留；memory 表 CASCADE——记忆无回落宿主，REQ-551 实施修订注已回修 106 号）。
- **失效降级**：默认库被删静默回落（chip 态可见，不扩响应契约）；默认方案失效走既有 ontology.unavailable 降级。
- **文件能力边界**：工作区直挂对话天然有 REQ-336 智能体文件四原语（resolveWorkRoot 回落 agent.work_dir），没有的只是项目三件套（save_file/list_files/项目根 read_file）与 Git 五端点——分层边界自洽，无需补面也无需裁剪。
