## 产品定位

> **平台定位（2026-10-24 Q-21）**：平台主定位变更为**工程化产品**（优先级裁判=工程化成熟度——可靠性/安全/可运维/性能；学习价值保留为产品能力，01 §8 Q-21）。
> **定位注更新（2026-10-28 Q-23）**：平台定位论述更新为**面向专业个人的工作学习助手——以本体为知识底座：知识不是一堆文档，而是可查询、可审计、可出题的结构化资产（单机自部署）**——Q-21「工程化产品」降为工程化成熟度裁判保留，「迷你版 Coze」对标论述放弃；用户画像=知识密集型专业个人（01 §8 Q-23/17 号 v0.72）。

## 设计原理

- **ReAct 循环**：每个 Agent 运行时装配为 Eino ADK 的 ChatModelAgent——模型思考 → 调用工具 → 观察结果 → 再思考，直到给出答案或到达最大迭代次数（防死循环）。
- **描述即路由语义**：多 Agent 协作时，子 Agent 的 description 是主 Agent 判断"何时委派给谁"的关键依据；成员能力画像（ExternalMemberProfile，REQ-429）进一步注入协调者描述强化该语义。
- **工具合并管线**（装配期按序合并、先到先得）：①勾选的内置工具 → ②技能携带的工具白名单 → ③Agent 级 MCP server 工具（`{server}__{tool}` 前缀防撞）→ ④本体挂载 onto_* 工具（6 个；REQ-215 起指引只注入紧凑口径，概念发现由 `list_concepts` 运行时按需拉取）→ ⑤项目会话文件工具；MCP 清单装配带指纹缓存（REQ-356，TTL 60s）。
- **连接器统一外部能力**（REQ-214）：ssh/k8s/外部 MCP/A2A/CLI/stdio 六类连接器为统一产品概念——凭据服务端加密（AES-256-GCM）不进 LLM 上下文；装配期改名与审批/审计自动覆盖；k8s/ssh 由平台托管 Go MCP 插件承载（进程内嵌 loopback :8093）。
- **推理后端可插拔**：默认 `eino-adk`（进程内完整能力）；外部 CLI 后端（Claude Code/OpenCode/Aider/dsh）按 PATH 探测协议桥接，技能/MCP 降级为提示词注入，harness/context 配置随之旁路（53/54 号诚实边界）。
- **调用轨迹与过程呈现**：run_event 派生的轨迹面板（14 类行+四/五泳道时序条）与执行树为过程可观测单面（REQ-217/284/311/317/322/323 逐件演进，详能力总表）；对话流详略分档/元信息条见 REQ-477/478 行。
- **演进定位校准（Q-22）**：自研 runtime 退守「协调者+轻执行者」、重执行外接主流智能体（57 号在案）；平台差异化=协议枢纽（MCP/A2A 双向）+统一治理+资产供给+跨协议过程可视化——外部成员通道与 A2A 深化批已全量交付，详能力总表。
- **五层域事实源**：Harness/Context/Loop/Graph 各一档（[53](53_Harness_设计实现与演进.md)/[54](54_Context_设计实现与演进.md)/[55](55_Loop_设计实现与演进.md)/[56](56_Graph_设计实现与演进.md)）——层职责/代码地图/域内能力表/开放问题，各域新增演进默认落对应档；侧板五层页签=REQ-218/219 交付（详能力总表）。
- **架构坐标系**：运行时可拆十层（传输/装配/循环/状态/上下文/工具/能力 seam/多智能体/交互/可观测），本平台强在装配与事件流、弱在上下文工程与能力替换——详见 [36 号十层对照](docs/research/02_智能体/36_智能体开发架构深度对比_本地实现与DeepSeekHarness.md)。
