服务间为 **loopback 信任模型（零服务间鉴权）**——部署网络边界见《[16_部署与运行](../platform-knowledge/01_整体设计/16_部署与运行.md) §3.0 警告》（REQ-236⑦）；平台边缘准入 REQ-209 accessAuth 仅管 backend /api/*。

### 1.2 核心数据流

1. **构建流**：六路径任一入口 → spec_json 草稿 → `Spec.Validate` 结构校验 + qualitygate 门禁（LLM 路径错误回喂修复 ≤3 轮；merge 路径走导入审查）→ 用户确认入库（保存即版本快照）。
2. **分发流**：方案 Start → runtime-manager 从 :8091 拉取各本体 TTL（original 直回/spec 经 sidecar 导出）→ 引擎装载（bulk load）→ 健康检查 → running + 异步质量快评（REQ-234①）。
3. **消费流**：对话挂载 running 方案（`runtime_profile_id`）→ backend 装配期经 `ONTOLOGY_MCP_URL` 拉 facade 6 工具（source=ontology:facade）→ 模型调用 onto_* → facade 按 ontology_id 路由（RunningByOntology 最早创建确定序，REQ-236②）→ 翻译 SPARQL 引擎执行。
4. **生效语义**：仓库保存新版本后方案**显式重载**生效（REQ-87 刻意保留的教学点）；drift 由 loaded_versions 快照+lifecycle plan 工具检测（REQ-155）。
5. **引用可见**：本体被方案挂载/KB 词表（kg_ontology_id）/agent 伴生绑定三处消费，聚合视图 GET /{id}/references + 详情「被引用」页签（REQ-233）。

### 1.3 与知识库/智能体的交集契约

- **运行期单向 本体→KB**（I3 裁定）：KB 抽取配置挂 `kg_ontology_id` → backend `FetchSpecVocab` 拉 spec 只读投影概念/关系词表（label 优先名兜底）→ KB 侧 120/60 截断注入抽取 prompt（KB-6③）。
- **对话侧**：挂载/取消/guide 紧凑口径归 01 侧 REQ-215（本体侧只保证 guide 端点与 6 工具契约）。
- **伴生本体**（01 侧 REQ-170/194/211/216/227~230 域）：伴生子图 `ont-{id}` 存于宿主方案引擎（运行平面），本体资产详情「伴生候选」页签为跨 agent 管理面；本体删除伴生拦截 409。边界 D-O19：伴生不入第五栏 KG 检索区。

## 2. 构建平面（ontology-service :8091，约 7.5k 行 57 端点）

### 2.1 数据模型：spec_json 多形态资产与版本

- **存储**：SQLite（modernc.org 纯 Go 驱动零 CGO）；迁移 001~005（repo/version/ontochat/pipeline/quality_strict）+ 039（REQ-207 候选版本表，🚧 并行开发中）。
- **spec_json 三要素 + 数据属性声明层**（`pkg/ontology/spec`）：concepts（name/label/definition/parents 多继承）/ relations（from/to 域值域）/ **data_properties（REQ-268/M77：name/label/definition/domain/range——类型挂载口径=声明层挂类型，实例 attributes 键与声明同名关联、值保持原形态零破坏；range 短名 string/number/integer/boolean/date，未知保留 IRI）**/ instances（attributes map + relations）。**模型边界（诚实声明，随 D-O22 批次推进扩容）**：~~无数据属性~~（M77 已落）/ 无公理/复杂约束——公理承载=REQ-269（触发驱动）；重语义资产过渡期仍建议 oo 轨（§2.4 两轨分工随批次复审）。
- **多形态资产**：`ontology_artifact`（ontology_id, format）——original（turtle/owl_rdfxml/csv/graphml，导入原样存档不可变）/ spec_json（归一化工作形态）/ quality-report（质量报告 artifact，可摘除）/ ingest_mapping_json 等。
- **版本**：保存即 bump+全量快照（`ontology_version` UNIQUE(ontology_id,version)）；版本 diff（三集合 added/removed/changed+引用影响统计）；fork（forked_from 溯源）。**版本语义现状=线性快照堆**（无草稿-发布态/命名版本/分支——命名版本随 REQ-207 候选状态机设计，52 号 A-2）。

### 2.3 校验与质量管线

- **结构校验只有一条**：`Spec.Validate`（引用完整性/命名唯一，不短路、结构化错误回喂）——表单/画布/LLM 草稿/导入全部收敛到同一段。
- **质量门禁** `internal/qualitygate`（REQ-171）：15 检查项数据驱动（11 基础〔孤立概念/缺失定义标签/命名风格/悬空端点/层级循环/实例类型缺失/重复命名等〕+REQ-255 reasoning_owlrl 推理档+REQ-268 数据属性两件：dangling_dataprop_domain〔error〕/undeclared_attribute_key〔info，仅本体声明过数据属性才检查——存量自由属性资产零扰动〕），三维评分 扣分制 error-10/warning-3/info-1，综合=完备.35+一致.45+可维护.20；`POST /api/ontology/quality/check` 双模式（ontology_id 落 artifact 可摘除 / spec 内联不落库）+ **save=false 纯快评**（消费面：runtime-manager 装载快照 REQ-234① + backend ontobuild 生成草稿统一快评 REQ-267/M76）；strict 开关（ontology 级）默认宽松。
- **LLM 生成修复环**：结构 Validate+质量门禁双校验源→错误级回喂 ≤3 轮→未过转人工（铁律：LLM 生成必过门禁）。

### 2.4 导入导出与转换

- **导入**：spec 无损 / CSV 实例灌装（preview→apply+映射配置 artifact）/ GraphML / OWL RDF-XML 与 Turtle 与 **JSON-LD**（经 `tools/rdf-sidecar/sidecar.py`，`SIDECAR_SCRIPT`+`SIDECAR_PYTHON` env；零 venv D-O15）。导入即保留原始形态（硬要求）+有损导入报告。
- **导入映射细则（REQ-69 定稿，REQ-235/M62 交付兑现）**：①类→concept：`owl:Class|rdfs:Class|skos:Concept`（系统命名空间跳过）；②名称→label 优先序 `skos:prefLabel > skos:altLabel > rdfs:label > IRI local`；③定义→`rdfs:comment|skos:definition`；④层次→`rdfs:subClassOf | skos:broader | skos:narrower（反向）`统一第二轮补（父须已注册，外部引用 warning 丢弃防悬空）；⑤对象属性 `owl:ObjectProperty`（domain/range 须注册概念，缺失 warning+from/to 置空）→relation 与实例关系；⑥**数据属性声明捕获**（REQ-235② 固定策略一档 **已升档，REQ-268/M77**）：`owl:DatatypeProperty` 声明→`data_properties`（label_or_local 命名+独立 label/definition；domain 未注册为概念留空不悬空；range xsd→短名、未知保留 IRI）；实例 datatype 断言→attributes 且**谓词命中声明 URI 时键归一为声明名**（label「副本数」≠URI local「replicas」场景）；域约束与属性公理丢弃 warning 明示、纯声明导入不计 lossy；⑦实例 `owl:NamedIndividual`：类型未注册为概念→**丢弃+warning**（置空保留会产生过不了结构校验的悬空实例，卡死合并应用）；⑧其余公理/限制/推理语义丢弃计 lossy warning。真实验收集：52 号分析期外部语料（HOCC 等），机制回归以单测 fixture（SKOS 词表/JSON-LD/datatype 三形态）+真机 API 全链承载。
- **导出**：spec→Turtle（sidecar，rdflib 回读校验）/ spec→VOWL JSON（平台原生 `importer/vowljson.go`，WebVOWL 对照视图供数）/ 原文形态直出。
- **合并**：merge/preview→apply 三策略（replace/merge-overwrite/merge 重命名并入+引用改写）——oo 回流与 OntoExtend 草稿共用该审查底座（REQ-157）；**导入报告内嵌 preview.import_report**（REQ-235/H5：lossy 清单+warnings 随审查/应用结果透出，前端「有损导入清单→前往图形编辑补录→重跑对账」动线；此前 wrapper 形态与前端消费错位一并归一）。
- **两轨分工（REQ-235⑤；D-O22 批次推进中复审）**：spec_json 表达力已扩容（M77 数据属性声明层落地）；公理/等价类/推理需求仍建议 Open Ontologies（oo）轨承载（REQ-269 落地后复审）——导入向导固定指引文案。

### 2.5 LLM 辅助创建

模型能力归主平台（「模型能力归主平台，校验归构建平面」）：`POST {PLATFORM_URL}/api/ontology-llm/generate`（backend `chat.GenerateStructured`，默认 chat 连接或 conn_id 指定）→ llmcreate 生成-校验修复环；OntoChat 多轮 CQ 引导复用同通道。生成链路 **ai-draft 已异步化**（POST ai-draft-async 202 立返 job_id+轮询，REQ-207/M43/E5；**前端异步接线随 REQ-267/M76**；OntoChat turn 仍同步）；LLM 输出契约含可选 `data_properties` 段（REQ-268/M77，llmcreate JSON Schema 与 ontobuild 提取提示词均已扩，模型输出的声明自此透传入草稿不再被静默丢弃）；LLM 域 eval 基准 ontoeval 已随 M43 交付（种子 5+真实 3 双信号）——52 号 A-6 两项均落治理。

## 3. 运行平面（runtime-manager :8090，约 3.5k 行）

### 3.1 方案模型与生命周期

- **Profile**：id/name/engine（oxigraph|fuseki）/ontology_ids/config JSON（reasoning 开关等）/port/status（created→starting→running⇄stopped，任意态可进 error）/pid/last_error/loaded_versions（REQ-155 drift 快照）/**loaded_quality（REQ-234① 装载质量快照）**。迁移 001~007（004 历史缺号无害）。
- **Start**：拉 TTL（FetchTTL）→ 端口分配（**bind 探测**：127.0.0.1 逐候选试探占用跳过，REQ-236③）→ startEngine（执行方式分发）→ 健康检查 ≤20×500ms → running + 异步质量快评写 loaded_quality（REQ-234①，失败静默）。
- **Stop/Reload**：Reload=Stop+Start（REQ-87 显式重载）。
- **启动对账 Reconcile**（REQ-236①，main 路由装配前调用）：DB running 态逐一探测——docker 容器 `DockerRunning` 领养（Stop=`DockerStop` rm -f）→ native 引擎 HealthCheck 领养（重建 procs 句柄，Stop=kill DB pid）→ 皆不可达收敛 stopped（对账语义 last_error 非 error）。治重启后「僵尸 running/孤儿引擎」双向漂移（伴生 EnsureHostPlan 先例反哺）。

### 3.2 引擎与执行方式

- **执行方式三态（系统级 runtime_config 单行表）**：**默认 docker**（D-O20 v0.73 变更，2026-10-01 开发者拍板）——迁移 006 翻转存量 k8s 默认行；**配置 docker 但探测不可用 → 启动期降级进程内 native**（配置值不写回；`GET /api/runtime-config` 增 `effective_method` 透出实际生效值）；k8s 接口预留（显式配置必报错）。用户显式配置优先。
- **oxigraph**：native 子进程（候选序 OXIGRAPH_BIN→PATH→data/bin→tools/bin，REQ-146 一键安装 pin v0.5.11）/ docker 官方镜像（容器名 rt-{profileID}，**端口映射绑 127.0.0.1** REQ-236⑤，数据目录挂载）。**fuseki**：native+推理开关（config.reasoning，OWL_FB 规则推理）；docker 化未做。引擎执行与 Agent 沙箱（REQ-122 族）是两套独立机制。
- **安全边界**：facade 与工作台双只读白名单（§3.3/§3.4）；native 引擎绑 127.0.0.1；docker 映射绑回环；服务间零鉴权（部署边界归 16 号 §3.0）。

### 3.3 facade 契约（Q-14，4→5→6 工具）

`/mcp` Streamable HTTP，tools/list 固定 6 个只读工具：get_concept / get_instance / list_instances / neighbors / **list_concepts**（REQ-215 概念发现按需拉取，guide 不再枚举全量）/ **sparql_query**（REQ-151 SELECT-only 词法白名单+10s 超时+limit 50/200 诚实截断+graph=companion 伴生分支）。路由 RunningByOntology（REQ-236② 确定性）→ ProcEndpoint。**翻译透视**（REQ-94）：每次工具执行的 SPARQL/耗时/结果数落 trace_log（开关默认开），方案详情「翻译透视」页签可查。guide 紧凑口径（REQ-215）：本体身份+规模统计+工具用法，不枚举概念清单。

### 3.4 SPARQL 工作台与只读边界

`GET|POST /api/runtime-profiles/{id}/sparql`（标准 SPARQL protocol，JSON/Turtle 按 Accept）：**服务端只读 SELECT 白名单兜底**（REQ-236⑥——`facade.ValidateReadonlySelect` 导出面与 facade tools/call 同一权威口径；此前仅前端拦截）。前端 SparqlWorkbench（CM6+AntD 自组装：模板/CSV 导出/⌘⏎/localStorage 持久化，REQ-92 v2）。

### 3.5 观测面

方案日志（`logs/{id}.log` tail 200，NFR-O-5）/ 翻译透视（§3.3）/ loaded_versions drift（lifecycle plan 工具，构建平面 §2.2 toolchain）/ **loaded_quality**（方案卡低分橙标 overall<80 或 error>0，Tooltip 指路质量卡，REQ-234①）。
