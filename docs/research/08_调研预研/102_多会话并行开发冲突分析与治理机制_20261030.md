# 多会话并行开发冲突分析与治理机制（102 号）

## 二、根因分析

### RC1 活文档的 read-modify-write 无原子性（根本根因）

18/02/19/01/20 五档是「读全文→改内存→写全文」的编辑模式。两个会话交错执行时，后写者基于旧快照，先写者的增量静默蒸发。git 只在**提交时**发现冲突（push 被 reject），但双方都**本地 commit 成功后才 push**——本地 commit 的 doccheck 校验的是本地（可能已过时）状态，冲突被发现时已是多轮之后。

### RC2 每件交付的共享文档回写面过大（放大器）

单件交付的「七档回写」惯例（01/02/03|11/18/18A/19/20/AGENTS）使冲突面=全部活文档。件越重（如本批 P1 件均触碰 7+ 文档），与并行会话的文档交集越大。

### RC3 位号分配无原子机制

迁移号=「看目录里最大号+1」，REQ 迭代版本号=「读头部版本+1」——两者都是 check-then-act 竞态。当日并行节奏（每 30~60 分钟一个提交）使窗口必然被踩。

### RC4 编译/测试以目录为单元，半成品无隔离

Go 包=目录编译单元，并行会话写一半的文件即阻塞整包编译。无 build tag、无 _wip 隔离区、无分支隔离。

### RC5 会话间无协调协议

两会话各自守护 AGENTS.md 纪律（都不 `git add .`、都跑 doccheck），但**互相不知道对方的存在与在途面**。并行会话甚至发展出了「挂账-销账」自发协议（KB 批提交注挂账 02/19 未同步，等我方批收口后 bca2b0e 代补）——说明协作意愿存在，缺的是机制载体。

## 三、治理机制建议（三层，按落地成本排序）

### M1 约定层（零工具，AGENTS.md 增补即生效）

1. **位号原子占位**：迁移号/REQ 版本号分配改为「**先建空文件即占号**」——`touch migrations/NNN_xxx.sql && git add && git commit -m "占号"`（或最低成本：`ls migrations/ | tail -1` 后**立即**创建，缩窗口到秒级）。REQ 迭代版本号同口径。
2. **提交窗口最小化**：共享文档（18/02/19/01）修改→add→commit 一气呵成（本会话后期已实践），禁止「改完所有文档再统一提交」。
3. **push 前 rebase 强制**：`git pull --rebase` 冲突即知（push 被拒时也强制 rebase——本地 commit 的 doccheck 结论作废，需重跑）。可落 pre-push 钩子。
4. **半成品隔离**：写到一半的 Go 文件移入 `_wip/` 目录或加 `//go:build wip` tag——不阻塞他人编译。
5. **领取声明**：从 19 号领取需求时在行尾追加 `〔🚧 领取于 <会话标识> <时间>〕`，完成后改 ✅——把「批不同靠巧合」升级为「行级声明」。

### M2 机制层（小工具，当日可实现）

1. **共享文档 append-only 化**：
   - 18A 归档册已证明追加模式免疫——将 18 号迭代表、19 号删除动作改为 **append-only 日志段**（文件尾追加「本轮删了哪行」的日志行，实际行删除由日志重放器或下轮批量执行）；
   - 或最低成本：19 号「删行」改为「改 ✅ 留行」+统计行由 doccheck 从表格实时计算（删单点计数）。
2. **doccheck 增「丢失检测」**：提交时对 01/02/18/19 记录新增行的 hash 指纹，下轮发现「上轮新增行消失」即报警（检测 lost update——当前 doccheck 只查头部一致性，查不出行丢失）。
3. **迁移号分配器**：`tools/next-migration.sh`——原子创建下一个迁移文件（ls→sort→+1→touch→git add 一气呵成），并行会话共用。
4. **pre-push 钩子**：push 前自动 `git fetch && git diff HEAD origin/main --quiet || (echo "远端有新提交，先 rebase 重跑 doccheck" && exit 1)`。

### M3 结构层（长期演进）

1. **需求登记结构化**：19 号机读单点已是方向（REQ-499），进一步将「状态/领取人/时间戳」落 SQLite 或 JSON 文件（原子写），markdown 表格变为生成物——双领、统计冲突、行丢失三类问题一并消除。
2. **会话任务分发器**：批次领取走脚本原子化（`tools/claim-req.sh REQ-XXX`——文件锁+写入领取记录），多会话从「各自看表猜」变「API 领取」。
3. **分支化并行**：重批次会话在独立分支开发，收口时 rebase——冲突在 git 层显式暴露而非静默丢失。成本=合并负担后移，适合超大批次（如本批 25 件）。
