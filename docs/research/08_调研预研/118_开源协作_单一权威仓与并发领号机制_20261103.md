# 118_开源协作_单一权威仓与并发领号机制（REQ-605-06e2 / M413-06e2，2026-11-03）

> 状态：v1.0 ｜ 2026-11-03 ｜ 开发者拍板「接受建议，和领号机制合并开发」——拓扑翻转+领号后缀制同批交付
> 前置：102 号《多会话并行开发冲突分析与治理机制》（并行撞账治理先例）；PR #4 整合轮事故（2026-11-03，58a01b6e）

## §0 结论（开发者已拍板采纳）

**双改合一**：①`ontoagents/multiagent-lab`（public）升级为**唯一权威仓**，所有人（维护者/协作 Agent/外部贡献者）同一流程；②REQ/M 领号改**后缀制**（`REQ-<seq>-<rand4>`），并发领取免协调、免重编。存量 REQ-1~604 纯序号保持原样，双格式永久并存。本批即实施轮。

## §1 背景与问题

### 1.1 PR #4 事故复盘（直接触发）

外部贡献者 stacklace 基于滞后公共镜像（基线 71f5b223，落后权威线 35 commit）自主领号 REQ-571~574/M379，与权威线已交付同号全撞；整合轮（58a01b6e）重编四件为 REQ-601~604/M412，连带 03 迭代表版本号/20 冒烟行号/02 里程碑号三流重复号压缩归并。

### 1.2 双仓拓扑的三类结构性成本（根因）

1. **镜像滞后**：外部贡献者只能看见 public，权威线在个人仓——撞号不是违规，是结构必然；
2. **流程分叉**：「免领号+维护者代管」制造内外两套流程，与「欢迎外部贡献」定位矛盾（开发者 2026-11-03 明确否定此设计）；
3. **同步税**：每次交付手动 push 两处，靠人记忆，忘推即滞后。

### 1.3 个人仓无隐私收益的实证

xiaoyao/multiagent-lab 本身为**公开 fork**（0 star/0 issue）——双仓模型成立的唯一前提（需要隐藏/过滤某些内容：私有历史/密钥/只发布稳定版）不成立。交付 commit 全量细节公开，无中间态需要藏。

## §2 目标与非目标

**目标**：①单一事实源，消灭镜像类与流程分叉类撞号；②并发领号机械安全（多人多设备+外部贡献者同规则，免协调免重编）；③内外流程零差别。

**非目标**：①不迁移存量 604 号（历史引用数千处，成本>>收益）；②不给迭代表版本号/冒烟行号加后缀（单一仓下 push 串行化，git 层冲突检测自然拦）；③不做号段预分配（需要中心协调，与并发免协调目标矛盾）。

## §3 方案

### 3.1 拓扑翻转

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 唯一权威 | xiaoyao（个人 fork） | **public（ontoagents）main** |
| origin remote | xiaoyao | public + dual-push（xiaoyao 第二 pushurl，每次 push 自动双写备份） |
| 个人开发空间 | 第二权威仓 | 同仓 feature 分支 / draft PR（大批走分支+PR 自合，吃 CI 门禁） |
| 同步机制 | 手动两推 | 无（镜像不存在，同步税归零） |
| xiaoyao 仓去向 | 权威线 | 备份副本（dual-push 自动维护），不删不归档 |

### 3.2 领号后缀制

**格式**：`REQ-<seq>-<rand4>`，seq=三位序号段（当前最大+1），rand4=4 位小写字母数字随机（本机生成，如 `openssl rand -hex 2`）；完整串即唯一键。里程碑同批同后缀：`M<seq>-<rand4>`（随批主 REQ）。

**领取规则（人人相同，内外零差别）**：
1. `git fetch origin && git log origin/main -1` 核对最新 docs/18；
2. 序号段 = 当前最大 seq+1；后缀 = 本机随机生成（不查重、不派生自用户/机器名——公共账本不掺身份串，随机去重数学充分：36⁴≈168 万，同序号 5 并发碰撞 ~10⁻⁶）；
3. 并发撞序号段**无需顺延**（后缀保证唯一），当轮 push 时 git 层按行合并，账本按全串排序；
4. 完整串在正式账本行（18/18A/19/迭代表）强制全写；行文允许缩写为 `REQ-605`，检索面以全串为准（doccheck 存在性校验见 §3.3）。

**兼容口径**：存量 REQ-1~604 纯序号永久有效；完结 ID 永不复用；19 号/18A 排序改全串序（seq 主序+后缀次序）。

### 3.3 机检适配（doccheck）

`reqRefRe`/`registryRowRe`/`reqRowRe` 三正则升级双格式 `REQ-(\d{3})(?:-([a-z0-9]{4}))?`；在册集合分两级：全串集（后缀引用精确匹配）+序号集（裸序号引用/缩写按序号粒度宽松匹配——**存在性校验降级到序号粒度是已知宽松面，见 §5**）。⑥ 19 号校验天然兼容（前缀包含语义）。

### 3.4 流程文件适配

AGENTS 纪律 3（权威=public main+dual-push+后缀领号规则）；CONTRIBUTING（双通道退役→单流程，领号规则人人相同）；PR 模板（免领号句退役→领号指引）；onto-dev skill（领号节改写）。

## §4 备选对比

| 方案 | 并发安全 | 内外统一 | 成本 | 判定 |
| --- | --- | --- | --- | --- |
| 纯序号+protocol（现状） | 靠协调 | 差（曾双通道） | 顺延注+整合重编 | 事故率不可接受后淘汰 |
| 号段预分配 | 好 | 差（需中心协调） | 号段管理 | 否（与免协调矛盾） |
| 时间戳 ID | 好 | 好 | 串长、无序号时序提示 | 否 |
| **序号段+随机后缀（采纳）** | 好 | 好 | 双格式+缩写侵蚀风险 | ✅ |

## §5 诚实边界与风险

1. **缩写侵蚀**：行文缩写 `REQ-605` 丢后缀后，同序号段多件时引用有歧义——靠「正式账本行强制全串+doccheck 全串级校验」缓解，不能根除；
2. **存在性校验宽松面**：裸序号引用按序号粒度匹配——`REQ-605` 在仅存在 `REQ-605-aaaa` 时通过（序号级在册）；同序号段第二件不影响第一件校验；
3. **只覆盖两流**：REQ/M 两类 ID 后缀化；迭代表版本号/冒烟行号仍纯序号——依赖单一仓 push 串行化兜底，极端并行下仍可能同版本号撞行（git 文本冲突会拦，语义撞号走既有「撞号注」豁免）；
4. **双格式永久并存**：604 存量不迁移，新工具/新读者需理解两种形态。
