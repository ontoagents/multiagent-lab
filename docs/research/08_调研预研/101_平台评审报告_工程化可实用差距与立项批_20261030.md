## 2. 评审范围与方法

**维度**:六维(交互设计 / 界面设计 / 功能设计 / 智能体×本体×知识库集成 / 工程化与演进 / 架构设计)+ 两维盲区深查补查(并发与竞态正确性 / 性能与容量)。

**流程**(三轮证据链):

1. **第一轮六维评审**:只读——代码实读给 path:line;大档(docs/01/02/03/18/20 等)按纪律先读头部导读与版本号、grep 定位后按行号分段读,未通读;『缺功能』类结论均给出查过什么、确认没有的记录(如 P07 双轮宽关键词 grep、P24 `grep -rn "func Benchmark"` 三服务零命中、P05 server.go 全文 grep 'chunk' 零命中)。
2. **第一轮独立复核**:11 条高影响复核,全部 confirmed,覆盖 P01~P08(其中 P04/P06/P07 各获两个维度交叉复核)。复核修正 20+ 处行号偏差、定性收窄与影响面精确化——全部已回写进 §6 各条;复核唯一方向性发现是**原发现偏保守**(P02 改造面更广、P04 多漏一个伴生快照目录、P06 证实 SEMANTICA_WORKER_URL 是死配置)。
3. **第二轮深查**(并发/性能盲区补查):产出 P21~P28(多条带实跑记录);并把 P08(第一轮复核正文截断)/P09/P10 转正 verified。
4. **本报告**:汇总定稿。撰写轮未重复执行检查,仅抽查 5 处证据锚点核对行号,全部吻合。

**复核状态标记**:`verified`=经独立复核或深查实跑确认;`unconfirmed`=第一轮静态实读结论,未独立复核(共 10 条:P11~P20)。

**诚实边界**(详见 §11):只读未改码;深查环境无模型凭证,真机对话/委派链未冒烟;P23① 为代码推演未真机复现;-race 仅覆盖 backend/internal/chat 包;P06 的 compose config 未实跑(本机无 compose v2,基于文件静态判读+Compose profiles 语义)。
