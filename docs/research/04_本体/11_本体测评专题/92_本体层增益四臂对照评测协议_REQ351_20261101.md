# 本体层增益四臂对照评测协议（REQ-351 评估件）

> **定位**：评估件（零代码，沿 REQ-560 先例）——90 号引入点 #2 的协议设计落档。先验数字（+17.8pp/-15.0pp/Tool 57%）来自 EvoOntology 在 DDR-Bench 单基准六 backbone 的外推，**迁移本项目须小样本复验假设成立再扩全量**（03 §2.49 诚实边界②原句口径）。本档给出可执行的本地化协议；**活跑复验挂账**（销账触发见 §7）。

## 1. 待复验的先验假设（90 号 §五，EvoOntology × DDR-Bench 10-K）

| # | 假设 | 论文数字 | 本地化预测 |
| --- | --- | --- | --- |
| H1 | 自进化本体带来大幅任务增益 | 六 backbone 均值 **+17.8pp**（Traj-Wise） | 进化本体臂 > Baseline 臂，方向为正 |
| H2 | 静态语义层塞 prompt 有害或不稳定 | Claude-Sonnet-5 **-15.0pp**；六模型「不一致甚至有害」 | 静态注入臂 ≤ Baseline 臂或波动大 |
| H3 | 收益大头在 Tool 层（怎么用）而非知识层（补什么） | Tool-only 演化 +13.2 / 三级全开 +20.0；Tool 承重 **57%** | 消融轴（可选第二轮）：Tool 单开 > 知识单开 |
| H4 | 门控是自进化第一承重墙 | w/o Gate **-11.2pp** | 依赖 REQ-343 进化链的 gate 段（不单测，随 H1 联动核验） |

## 2. 四臂定义（本地化到平台消费链）

统一任务面：给定一组面向某业务本体的**问题-期望判定**条目（见 §3），被测链路=智能体对话（recallKB/KG 增强检索链 + onto facade 工具面），逐臂只改**本体供给方式**、其余全同（模型连接/top_k/提示词模板/工具集除臂差异外全冻结）。

| 臂 | 供给方式 | 本地承载 |
| --- | --- | --- |
| **A0 Baseline** | 无本体——纯 KB RAG 检索 | recallKB（enable_kb 会话，无 KG/本体注入） |
| **A1 +本体注入（静态 TBox）** | spec 概念/关系/数据属性清单全文注入 system prompt | 导出 spec_json 序列化文本（当前头版本） |
| **A2 +进化本体注入** | REQ-343 三段式（cq-rag 增量+演化）产物注入——注入「进化后」spec 快照 | cq-rag 链产物（evolution 包）+同 A1 注入法 |
| **A3 +静态语义层注入（负对照）** | 非结构化语义摘要注入（KB 文档摘要/领域说明文本，等 token 预算） | KB wiki summary 页（REQ-246）或材料摘要，截断至与 A1 等 token |

> **臂间公平性护栏**：A1/A2/A3 注入 token 预算对齐（±10%）；检索参数全臂同值； held-out 条目不进任何臂的本体构建/进化/选择（沿 90 号 reciprocal two-fold 洁癖，本地简化=半分折：条目集对半分，构建折只碰构建半区）。

## 3. 数据集与判定（复用既有评测基建，不新建引擎）

- **主数据集**：cqbench kind=case 案例级 gold（REQ-547/M354 已交付）——期望可答（⊇ 引用判定）/期望不可答（零引用判定）两维**确定性判定免判官**；复用 onto_core 数据集为起点，按被测本体域扩充至 §5 规模。
- **辅信号**：agenteval Judge 契约（backend/internal/agenteval/judge.go，REQ-223）——开放题 LLM 判官（ParseJudgeOutput 0~1 分），与确定性判定互补；判官连接与被测连接**同模型不同会话**（判官不与被测共享上下文）。
- **正交面不混入**：kb/evaldata 三臂（keyword/multihop/community）=检索策略对照轴；cqbench 第三信号（EvolutionPane with_benchmark）=质量门控轴——本协议只测**本体层价值轴**，三轴数据分账不合并。

## 4. 指标

1. **题级正确率**（臂内均值）：确定性条目=gold 判定 0/1；开放条目=Judge 分 ≥0.7 记 1。
2. **臂间差（pp）**：Δ(A2-A0)/Δ(A1-A0)/Δ(A3-A0) 及其按折配对差（同条目跨臂差分的均值——消条目难度方差）。
3. **方向核验清单**：H1=Δ(A2-A0)>0；H2=Δ(A3-A0)≤0 或跨折方差>Δ 均值（不稳定）；H3（可选第二轮）=Tool-only vs 全开消融。
4. **显著性下限**：N=40、配对二项近似——单臂正确率 95% CI 半宽 ≈ 15pp（粗判据：观测 |Δ|<10pp 时不下结论，只记「样本不足」）。

## 5. 小样本规模与成本

- **首轮（复验轮）**：N=40 条（可答/不可答≈3:1），4 臂×40=160 次被测运行+开放条目判官 ≈ 200~260 次 LLM 调用/折；两折 ≈ 400~520 次。
- **判定规则（先验假设成立性）**：
  - H1 方向为正且 Δ(A2-A0) ≥ +5pp → 「进化本体增益可迁移」**初步成立**→触发全量评估立项（N≥200+多模型）；
  - H1 方向为正但 <+5pp → 「弱正，样本不足」→扩样一次（N=80）再判；
  - H2 复现（静态注入不增益或有损）→ 90 号 E6 迁移注记转「本地复验一致」；
  - 任一方向反转 → **如实记录**并修 90 号 §五迁移预测（决策反转扫描纪律：grep EvoOntology/+17.8 全仓命中面逐处补指针）。

## 6. 执行清单（活跑时逐步照做）

1. 配置真实模型连接（判官+被测各一，或同连不同会话）；2. 选定被测本体（建议 onto_core 种子或业务 spec）+KB 语料；3. 生成/核对 cqbench case 数据集 N=40；4. 按 §2 四臂逐臂跑批（每臂独立会话集，记录 run 事件）；5. 汇总 §4 指标表；6. 按 §5 判定规则出结论；7. 结论回写本档 §7 结果槽+90 号 E6 行+03 §2.49 REQ-351 行注。
