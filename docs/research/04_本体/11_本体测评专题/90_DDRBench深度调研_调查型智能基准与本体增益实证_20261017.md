## 二、为什么是「本体的 DDR-Bench」：定位与关联

### 2.1 核心命题：调查型智能 vs 执行型智能

论文提出区分两种智能形态：

- **Executional intelligence（执行型）**：完成**已给定**任务的能力——现有绝大多数 agent 评测（text-to-SQL、TableQA、带问题的数据分析）都只测这一半；
- **Investigatory intelligence（调查型）**：**自主决定什么值得调查**的能力——人类分析师拿到数据时并没有预定义问题，而是先看数据找异常、形成假设、随新模式迭代修正。

DDR-Bench 把评测对象从「答对没有」换成「**在没有问题的长程探索里挖出了多少可验证的洞察**」。

### 2.2 与既有范式的差异

| 范式 | 给什么 | 评什么 | 缺陷 |
|---|---|---|---|
| TableQA / text-to-SQL | 预定义问题 | 答案正确性 | 只测执行型；问题本身泄露了该查什么 |
| LLM4DS 报告生成 | 详细指令（隐含多个研究目标） | 低层正确性检查+报告主观评分 | 破坏开放设定；规模小（<几十步交互） |
| Deep Research 基准 | 非结构化网页 | LLM-as-a-Judge / 忠实度 | 工具只有搜索；评测主观、不可复现 |
| **DDR-Bench** | **只有数据库+SQL/Python 工具，无问题** | **checklist recall 式逐项核验** | 见 §7 限制 |

### 2.3 与 EvoOntology 的关系（「本体」关联的核心）

EvoOntology（人大 ruc-datalab，arXiv 2609.15779，机制详见 40/43 号）选定 DDR-Bench 的 **10-K 场景**作为三个评测基准之一，把「无本体 Baseline / 静态语义层 / 自进化本体」三方放在**同一 ReAct 脚手架、同一 backbone、同一预算**下对照——得到业界第一组「**本体层对 data agent 的增益**」系统性实证：

- 自进化本体平均 **+17.8pp**（六 backbone Traj-Wise）；
- **静态语义层塞 prompt 反而有害**（Claude-Sonnet-5 -15.0pp）；
- 收益大头来自 Tool 层（57%）——「怎么让 agent 用本体」比「往本体里补知识」更值钱。

**为什么 DDR-Bench 能测出这个增益**：它的任务设计（无预定义问题、自主探索、无轮次上限）恰好放大了「重复探索」的成本——没有本体时 agent 每个实体都要从零盲探（找表、看字段、试 join）；本体把已验证的映射沉淀下来复用。若换成带预定义问题的 QA 型基准，本体省去探索环节的价值会被题目本身压缩掉。**这是一个方法论结论：要证明本体层价值，应选开放式探索任务，而非封闭 QA。**

## 三、基准设计

### 3.1 DDR 任务形式化

`I = DDR(LLM, D, T)`：给定数据库 D 与工具集 T（**仅 SQL + Python 两个工具，经 MCP 暴露**），LLM 以 ReAct 循环 `(r, t, o)` 迭代查询，**无预定义问题、无轮次上限**，仅收到极简起始提示（只含任务实体，如 "Start analysing the user with userid=2048"）与数据库基本元数据（表清单+简介）。模型**自主决定何时终止**，产出两类洞察：

- **Message-wise insight I_m**：每轮交互的增量解读（过程级）；
- **Trajectory-wise insight I_t**：终止时回看全轨迹的综合报告（结果级）。

洞察可视为「模型在数据库中重建的任务实体上下文」——如 EHR 场景下即患者的纵向就诊轨迹与健康状态。

### 3.2 Agent 设计三原则（最小脚手架）

1. **不给问题**：非输入-输出对结构，只有「数据库+prompt-checklist 实例」；
2. **框架最小化**：轻量 ReAct，**无工作流/记忆/规划模块**，只有 SQL+Python 两工具——刻意测**模型内在能力**而非外部脚手架（与 88 号 ontoeval「PR 重放」的思路同向：排除框架混淆因素）；
3. **探索不设限**：轮数无上限，终止由模型自定。

### 3.3 三库构成

| 数据库 | 领域 | 结构化部分 | 非结构化部分 | 实体数 | Checklist 项 |
|---|---|---|---|---:|---:|
| **MIMIC-IV** | 电子健康记录（Beth Israel 急诊/ICU） | Hosp+ICU 模块（29 表/318 字段） | 临床叙事 note 模块 | 100（按 note 数分层采样） | 774 |
| **GLOBEM** | 运动与心理健康（可穿戴传感器） | 蓝牙/步行/Wi-Fi/睡眠信号（6 表/222 字段） | 调查回答（干预前后心理社会福祉） | 91 | 435 |
| **10-K** | 美股公司年报（SEC EDGAR 官方 API） | XBRL 财务报表（5 表/5,832 字段） | Items 1/6/7A/8 等文本节 | 100（每家 >5,800 财务事实） | 849 |

三库合计 291 实体、2,058 checklist 项。三库 deliberately 异质：多表推理重构（MIMIC）、跨模态时序-心理关联（GLOBEM）、隐式财务建模（10-K）。

### 3.4 Checklist 构建（评测数据的产生方式 ★）

1. 用 **GPT-5-mini** 从各库**非结构化文本**提取可验证事实陈述，组织为 checklist；
2. **50+ 名领域专家人工筛选**，保证「数据域→事实域」的**满射映射**（surjective）——每个 checklist 项都确定可以从数据库的某个子集分析得出，不出现「数据里根本查不到」的鬼题；
3. 每项再经**人工验证 + LLM 检查**双重确认。

> **关键设计**：结构化数据供探索，非结构化文本供出题——两条信息通路同源但分离，评测事实客观存在于数据中，却不以问题形式出现。

### 3.5 评测协议

- **四种准确率口径**：{Sample-Averaged（按实体）, Item-Averaged（按 checklist 项）} × {Message-Wise, Trajectory-Wise}；
- **开放式 checklist**（MIMIC/10-K）：GPT-5-mini 判断模型洞察是否为每条事实提供了**足够上下文证据**，accuracy = 被支持项占比（**recall 式**：不求洞察覆盖全部清单，只数挖到了几条）；
- **封闭式 checklist**（GLOBEM）：GPT-5-mini 以洞察为上下文回答 checklist 问题，与 ground truth 对比；
- **Novelty 分析**：未被任何 checklist 项覆盖的洞察作为「新颖洞察」，GPT-5-mini 两两配对比较（匿名+换序）+ **Bradley-Terry 模型**聚合全局排名——结果与 checklist 准确率排名高度一致，证明 checklist 不系统性低估清单外的探索（评测覆盖面效度验证）。

## 四、关键结果与发现

### 4.1 SOTA（Overall Avg = 四口径平均，v2 数据）

| 模型 | MIMIC (Msg) | GLOBEM (Msg) | 10-K (Msg) | **Overall Avg** |
|---|---:|---:|---:|---:|
| **Claude 4.5 Sonnet** | 36.07 | 40.13 | 77.61 | **47.73** |
| DeepSeek-V3.2 | 28.98 | 38.46 | 60.08 | 38.80 |
| GPT-5.2 | 28.85 | 38.81 | 44.89 | 37.09 |
| GLM-4.6 | 25.03 | 41.56 | 60.31 | 37.52 |
| Kimi K2 | 33.61 | 37.14 | 51.06 | 36.42 |
| Gemini 2.5 Pro | 21.51 | 33.77 | 24.48 | 25.00 |
| Qwen2.5-7B | 12.81 | 27.20 | 10.52 | 14.81 |

- **仅 Claude 4.5 Sonnet 均值 >40%**——任务远未饱和；
- 10-K 是三库中明显最「可做」的场景（头部模型 60~77），GLOBEM 各模型普遍 38~41（算法生成型任务、字段全覆盖，区分度弱），MIMIC 最难且区分度最大；
- 开源头部（DeepSeek/GLM/Kimi）已逼近闭源二线；小模型全线崩塌（探索本身就是长程能力）。

### 4.2 四个行为学发现（对设计 agent/本体有直接含义）

1. **隐式规划**：高天花板模型（Claude/GLM/DeepSeek）在进入快速提升期前会延迟「抢夺易得信息」——无规划 prompt 却表现出 plan-then-act 的交互序列；强模型能在缺值/工具失败等意外下仍维持整体探索轨迹一致。
2. **末段 token 价值极高**：token 缩放曲线呈「先平后陡、无饱和」——广度查询只能拿到易得洞察，增益集中在末段少数几次高价值深度查询（复杂参数+二值反馈）；**性能来自深而准的定向查询，不是穷举**。
3. **平衡探索区**：以「字段覆盖率×归一化探索熵」作图，**足够覆盖+聚焦访问**的平衡区实例显著更高准确率（全模型一致）；弱模型要么探得太窄（Qwen/Gemini）要么注意力弥散（高熵）。
4. **自终止置信**：终止 token 概率随轮次的演化可区分模型代际——Qwen3 系列置信度平稳增长，Qwen2.5 系列剧烈波动（不知何时该停）。

### 4.3 抗污染设计

- **执行与评测分离**：探索阶段模型接触不到任何评测问题；评测在轨迹生成后用 checklist 事后核验；
- 列名/元数据匿名化重写（不改变含义）；
- 数据库中**无 QA 格式数据**——天然抗训练泄漏；
- 幻觉率实测极低，且与准确率**无统计相关**（从记忆里直接背出洞察的情形罕见）。

## 五、EvoOntology × DDR-Bench：本体层增益实证口径

> 机制细节见 40/43 号，本节只汇总**在 DDR-Bench 上的实证数字与口径**（本档核心价值之一：把这些数字的实验条件钉清楚，供引用时不失真）。

### 5.1 实验协议

- **场景**：DDR-Bench 10-K（三库中最可量化者）；指标 Traj-Wise / Msg-Wise accuracy（即原论文协议）；
- **Backbone**：6 个——GPT-5.5、GPT-5.6-sol、Claude-Sonnet-5、Claude-Opus-4.8、DeepSeek-V4-Flash、Qwen3.5-Flash；
- **Reciprocal two-fold**：每基准分 A/B 两折，A→B 用 70% A 做本体构建+演化+30% A 做配对验证，冻结后测 B；再 B→A 反向，报均值——**held-out 折的答案与评测反馈绝不参与本体构建/演化/选 candidate**（评测洁癖与 DDR-Bench 抗污染设计同构）。

### 5.2 主结果（DDR-Bench 10-K，Traj-Wise）

| Backbone | Baseline | Baseline+SL（静态层） | **EvoOntology** | 增益 |
|---|---:|---:|---:|---:|
| GPT-5.5 | 64.2 | 63.9 (-0.3) | **90.9** | **+26.7** |
| GPT-5.6-sol | 68.5 | 65.5 (-3.0) | **93.5** | +25.0 |
| Claude-Opus-4.8 | 73.0 | 71.4 (-1.6) | **92.3** | +19.3 |
| Claude-Sonnet-5 | 72.5 | **57.5 (-15.0)** | **81.3** | +8.8 |
| DeepSeek-V4-Flash | 30.3 | 31.7 (+1.4) | **52.3** | +22.0 |
| Qwen3.5-Flash | 14.3 | 13.3 (-1.0) | **19.1** | +4.8 |
| **六模型均值** | — | 不一致甚至有害 | — | **+17.8** |

四模型细化口径：Baseline→**Initial**（builder 初始本体）+12.3pp，Initial→**Evolved**（自进化后）再 +7.7pp——builder 给了强起点，**自进化循环兑现全部增益**。对照 ReAct+Memory：75.8 vs 89.5——记忆只重放「做过什么」，本体是**可组合的 typed 结构**。

### 5.3 承重结论（消融，四 backbone 均值）

| 消融 | Traj-Wise | Δ | 结论 |
|---|---:|---:|---|
| w/o **Gate**（candidate 全收） | 78.3 | **-11.2** | 配对评估门控是第一承重墙；无门自进化=随机游走 |
| w/o Attribution | 83.2 | -6.3 | 不归因就修错层（manifest 出问题却去改节点） |
| w/o Diagnose | 84.7 | -4.8 | 随机抽样轨迹提不出有效假设 |
| w/o Mappings | 76.1 | **-13.4** | 本体结构侧：概念→字段/join 的映射是命脉 |
| w/o Evidence | 80.8 | -8.7 | 探针证据是验证候选 SQL 的根据 |
| Tool-only 演化 | 82.7 | +13.2 | 三级单开 Tool 最大，但三级全开 +20.0——**互补不可替代** |

跨 backbone：进化后本体两两 Jaccard ≤0.62；跨模型迁移至少 **-6.6pp**（平均至 -10.9）——**本体是模型特异的**，不能一套通吃（40 号 §5.4 已详）。

### 5.4 成本

无本体 52.6K token/任务 → 初始 50.4K → 进化后 **42.0K（-20%）**，轮均轮数 14.6→8.4——**涨分与降本同时发生**：本体省掉的是重复探索，不是理解深度。

## 六、对本项目的映射与借鉴分级

### 6.1 方法论同构：REQ-343 的姊妹证明

REQ-343 要证明「RAG 层对 agent 的增益」，DDR-Bench × EvoOntology 证明了「本体层对 data agent 的增益」——**同一实验方法论**：同一脚手架/同预算下 {Baseline, +中间层} 配对对照 + held-out 纪律。若未来产品线出现「探索式数据分析/消费侧 agent 查数」场景，**本体层增益证明协议可直接照搬**（REQ-347 触发驱动的外部基准引入即此场景的落地形式）。

### 6.2 借鉴点（K 系列续编，接 88 号 K1~K6）

| 编号 | 借鉴点 | 挂靠 | 说明 |
|---|---|---|---|
| **K7** | **Checklist recall 式评测**：开放式产出（报告/本体）不做点数打分，改为「逐项核验是否被支持」，accuracy=支持项占比；配 novelty 配对比较验证覆盖面效度 | REQ-346（CQ 基准集 v2+） | 当前 ontoeval 包以 PR 重放+gold 对齐（precision 视角）为主；recall 视角可测「开放式本体/报告产出覆盖了多少已知事实」，补统计强度的另一条腿 |
| **K8** | **构建/评测分离抗污染**：出题（checklist 提取）与答题（agent 探索）严格分离，题面不以问题形式进入被评系统上下文 | REQ-346 数据构建流程 | 我们用 LLM 生成 CQ/基准集时的同款纪律：生成期不得接触被评 agent 的评测面 |
| **K9** | **本体层增益对照协议**：{无本体 Baseline, +本体} × 同脚手架/同 backbone/同预算 + reciprocal two-fold held-out 纪律 | REQ-347（触发驱动） | 触发条件见 6.4；与 REQ-343 RAG 增益证明共用实验骨架 |
| **K10** | **满射映射专家筛选**：checklist 每项都经人工确认「可从数据得出」 | REQ-346 | LLM 出题必配「可解性」人工/半自动抽检，防鬼题（与 85 号 N1 体检「统计强度不足」的修复方向一致） |

### 6.3 借鉴分级

| 级 | 内容 | 动作 |
|---|---|---|
| **A（方法论立即吸收）** | K7/K8/K10 评测方法论三件套 | 并入 REQ-346 v2 设计约束，不引运行时 |
| **B（触发驱动）** | K9 增益对照协议；10-K 场景复刻（SEC API 公开可取数，是三库中唯一无医疗/隐私门槛的） | REQ-347 触发条件增加一条：「探索式数据分析场景立项时」 |
| **C（参考不引入）** | 交互/ token / cost 三维 scaling 分析、探索熵可视化、自终止概率分析、novelty Bradley-Terry 全套 | 研究向重基建，工程当前无消费场景 |

### 6.4 引入触发条件（对应 85 号 P3「触发驱动」）

1. 产品出现**探索式数据分析**消费场景（本体系统能省去 agent 重复探索）→ 启用 K9 做本体层增益证明；
2. REQ-346 CQ 基准集 v2 规划时 → 吸收 K7/K8/K10 方法论；
3. 需要自建 mini-DDR 类基准时 → **从 10-K 起步**（SEC EDGAR 公开 API、XBRL 结构化+文本节，无 PHI/隐私合规负担）。

**实现落点盘点**（项目评测基础设施现状 vs DDR-Bench 范式）：

## 七、可用性与限制

| 项 | 说明 |
|---|---|
| **开源可用性 ⚠️** | 官方仅 HF Space（thinkwee/DDR_Bench，论文脚注；页面 JS 渲染，内容抓取为空，可访问性待人工浏览器验证）；**未检索到官方 GitHub 代码仓库**——复刻需按论文 §2/附录 H prompts 自建，或关注 Space 后续放码 |
| 数据门槛 | MIMIC-IV 需 PhysioNet 认证（PHI 合规）；GLOBEM 学术申请；**10-K 经 SEC EDGAR 公开 API 可自取** |
| 评测成本 | 每实体长程探索（数十至上百轮）+ GPT-5-mini 逐项核验——全量 291 实体跑一轮成本高，自建时建议子采样 |
| 判官依赖 | checklist 核验依赖 GPT-5-mini 作为 judge——判官偏差存在，但论文 §8 专门做了 LLM-as-a-Checker 可信度分析 |
| 场景局限 | 三库都是「单实体上下文重建」型任务（一个病人/一个用户/一家公司）；多实体跨库关联、本体工程学常见的 schema 级任务不覆盖 |
| 时效 | v2 2026-05-15（ICML 2026 定稿）；SOTA 数字随模型迭代会过期，引用时注明版本 |
