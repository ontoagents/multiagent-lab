## 1. 需求拆解：四项能力两项已有，真正的缺口是「权威源查询与获取」

| 开发者设想 | 主线现状 | 判定 |
| --- | --- | --- |
| **查询**业界权威已有本体 | 无（oo 双轨的目录查询随退役摘除；oo 目录=open-ontologies.io 服务端） | **缺口①** |
| **导出**（获取本体到本地） | 任意 TTL/OWL 导入管线在位（importer 嗅探五格式+审查报告+REQ-305 防线），但**没有权威源的检索与一键获取入口** | **缺口②** |
| **本地运行** | 运行方案挂载即运行——**TTL 形态本体可直接挂载**（runtime-manager FetchTTL：original turtle 直接回原文，无需转换） | ✅ 已有 |
| **基于拓展** | Fork 全形态复制（REQ-83）+导入合并 merge 审查（REQ-157，含概念重命名映射）+Spec/图形编辑 | ✅ 已有 |

**结论**：运行与拓展是主线强项（运维闭环完整），缺口只在「**权威本体从哪来**」——需要的是一个**权威本体的目录与获取入口**，而非新的运行/编辑能力。

## 2. 与 oo 双轨退役（REQ-100 ⛔）的边界：轻量自研回归，不复活双轨

oo 双轨退役（66 号，2026-10-08 开发者拍板方案 B）退役的是「**独立 Rust 服务 + MCP 工具双轨 + 数据目录**」这一形态（事实休眠零使用+休眠维护债）；**不是**否定「引入外部权威本体」的价值——66 号方案 A-1 有意保留了「**任意 TTL 来源的导入审查底座**」（ImportMergeWizard/importer，明确「面向任意 TTL 来源继续有效」），且 §2 九能力面对照留作「触发驱动重评底稿」——本需求正是那次预留的「触发」。

**新方案与 oo 的三点不同**：①无独立服务/进程/端口（纯 backend 只读代理+内置目录数据）；②无 MCP 工具与双轨对照（单向引入，不做回流）；③不绑 open-ontologies.io 单一上游（多源目录，离线可用兜底）。因此**不构成 REQ-100 反转**，是新能力（编号自 316 起经 18 号注册表分配）。

## 3. 权威源盘点与推荐形态

**方案（推荐）：内置精选目录为主 + LOV 在线检索为增强**——新页面「权威本体库」（本体模块构建栏新路径卡或资产栏页签，IA 落点拍板时定）：

- **P1 内置精选目录**（seeds 数据文件，离线可用）：收录 15~25 个业界权威本体的元数据（名称/领域/官方首页/规范文档 URL/TTL 下载 URL/许可/概念规模估计），建议首批覆盖 W3C 与标准组织系：
  PROV-O（溯源）/ DCAT（数据集）/ FOAF（人物社交）/ SKOS（词表）/ schema.org（通用电商搜索）/ SSN-SOSA（传感物联网）/ 时间本体 TIME / ORG（组织）/ DBpedia ontology（通用知识）/ SAREF（智能家居能源，ETSI）/ FIBO 领域样例（金融）/ FIBO/ SOSA/ CyclAlt——具体清单拍板时按教学与实用价值圈定；每条标注**许可与来源**（多为 W3C/CC-BY/ASF 开源许可，诚实呈现）。
- **P2 LOV 在线检索增强**（Linked Open Vocabularies，lov.linkeddata.es 有公开检索 API）：关键词搜业界词表/本体→元数据+来源 URL；不可达优雅降级（内置目录不受影响）。
- **获取与入库**：「导入到本地」→ backend 只读代理下载（复用 REQ-307 的 downloadTo 多源+大小上限经验；Content-Type 校验 .ttl/.owl/.rdf/.rdfx）→ **走既有 importer 嗅探管线**（格式识别+有损报告 REQ-235 口径+REQ-305 规模防线自动生效）→ 入库双形态（original+归一化 spec_json）→ 入库即获得全部既有能力：运行方案挂载（TTL 直挂）、Fork 拓展、merge 合并、图形编辑。
- **运行与拓展零新增**：页面详情卡直接给「运行」（跳运行栏新建方案预选该本体）与「Fork 拓展」「导入合并到既有本体」三个既有动线的入口链接——不造新轮。

## 4. 风险与诚实边界

- **网络可达性**：本机外网慢（REQ-307 实测官方源 12KB/s 级）——官方 W3C 站点一般可达；下载走代理+可配超时+失败诚实报错；内置目录的**元数据离线可用**（只有取包需要网络），目录页不因外网不可达而白屏。
- **有损转换**：OWL/RDFS→spec_json 是有损投影（REQ-235 口径：数据属性降级 attributes 一档等）——导入报告如实列 lossy 项；original 形态保真存档，**运行可挂 original TTL**（无损运行、有损结构化编辑的组合诚实呈现）。
- **规模防线**：schema.org 级大本体（数千类）在 REQ-305 防线内（5 万对象上限）可入；详情页大文本渲染 REQ-304 摘要卡兜底。
- **许可合规**：目录逐条带 license 字段；平台不再分发本体内容本身（按 URL 由使用方获取），许可关系保持「使用方↔源头」。
- **与 74 号/REQ-313（Snowflake 借鉴）的关系**：那是「运行/使用侧」的方案调研（P2 待拍板），与本「构建来源侧」正交，不冲突。
