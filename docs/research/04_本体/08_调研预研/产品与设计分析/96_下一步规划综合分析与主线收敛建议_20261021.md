## 0. 一句话结论

> **瓶颈的本质不是方向缺失，而是「主线收敛不清 + 质量门禁深度不足」——外部动态显示平台两条主线（MCP 协议层+Oxigraph 引擎层）选型正确，但评测与工具化深度滞后于学界；下一步应围绕「本体操作 MCP 工具化 + CQ 基准扩至 50+ 条 + 伴生图时序化」三条可验证的深度主线收敛，一次只吃一条，其余 REQ 显式归档/延迟。**

## 2. 外部动态关键信号（与内部现状的对齐）

> 详见 [业界与高校科研动态调研报告](../综述与赛道/98_业界与高校科研动态_下一步规划外部输入_20261021.md)

**四个已对齐**（我们的选型被业界验证为正确）：

| 外部信号 | 平台对应 | 状态 |
|---|---|---|
| MCP 月下载 5 亿、成为工具层事实标准（2025-12 入 Linux Foundation，2026-07-28 规范修订） | 平台 MCP 工具生态 | ✅ 已对齐 |
| Oxigraph 被 Open Ontologies 选用（同引擎） | D-O5 唯一引擎决策 | ✅ 前瞻性验证 |
| A2A v1.0 稳定（Go SDK 可用，150+ 组织支持） | Go+Eino ADK 选型 | ✅ 协议层不被边缘化 |

**四个差距**（深度不足的具体位置）：

| 差距 | 学界/业界标准 | 平台现状 | 来源 |
|---|---|---|---|
| **MCP 工具化** | Open Ontologies 21 个 MCP 工具，F1=0.717（vs LLM 直读 OWL F1=0.323） | facade 6 工具（对比 Graphiti 15） | O-1 |
| **CQ 基准深度** | CQ4OE 118 CQ + 两级评测；TRACE-KG 三指标 | 15 条 CQ 单基准集 | O-2 + N2 |
| **时序知识图** | Graphiti 双时间模型 + SodaMem 时序语义记忆 | 静态三元组，REQ-280 未启动 | O-3 |
| **Agent 互操作** | MCP+A2A 双栈成为生产默认 | 仅 MCP | O-4 |

**两个重要观察**：

1. **Go 在框架层劣势、协议层等价**：Agent 框架主战场 Python，但 MCP/A2A Go SDK 已可用（A2A v1.0 含 Go）；Google ADK 原生支持 Go。结论：聚焦协议层对齐，不追框架层。
2. **评测基准信任危机**：Berkeley RDI 发现所有主要 Agent 评测基准可被利用 → 自建基准+第三方交叉验证。

## 3. 主线收敛建议

基于内部现状与外部信号，建议以**两条主线+一条清理+一个交汇探索**组织下一步工作：

### 主线 A：本体纵深（质量门禁+工具化）—— 解决 R1 生产资格线

> **核心命题**：从"功能齐全的本体平台"→"可被验证的生产级本体平台"

**短期（1~2 个月）—— O-1 MCP 工具化本体操作**：
- 将 Oxigraph CRUD/SPARQL/SHACL 验证/OWL 推理/CQ 评测封装为标准 MCP 工具集
- facade 从 6 工具扩展到 15+ 工具（对齐 Graphiti 规模）
- 直接收益：① 外部 Agent 可标准化操作本体 ② 内部 LLM 本体构建质量提升（F1 0.323 → 0.717）③ 为 O-5 多 Agent 协作奠基
- REQ 映射：REQ-239 版本纪律+REQ-280 伴生图扩展+facade 工具扩展
- 学习价值：MCP 协议深度实践 + OWL 推理工程化

**中期（2~4 个月）—— O-2 + O-3 CQ 基准扩充+时序 KG**：
- 参考 CQ4OE 118 CQ 方法论，将基准集扩至 50+ 条，显式覆盖属性/层级/公理三弱项
- 引入 TRACE-KG RWA/EGU/SCI 结构质量指标作 CQ 评测补充
- Oxigraph 伴生图引入 valid_time + system_time 双时间戳，支持边失效/取代语义
- REQ 映射：REQ-346（评估）+ REQ-280（伴生图时序）+ REQ-331（质量档案）
- 学习价值：质量评估方法论 + 时序 KG 工程

### 主线 B：Agent 平台（协议升级）—— 保持与行业标准同步

**长期（4~6 个月）—— O-4 A2A 端点暴露**：
- 将本平台智能体构建为 A2A 服务端点，支持 Agent Card 发布
- 优先在本体查询、CQ 评测等场景展示跨 Agent 协作
- 技术路径：Go A2A SDK（Google ADK 原生支持）
- REQ 映射：新占号立项
- 学习价值：A2A 协议实践 + Agent 互操作
- **诚实边界**：A2A 实际采用与宣传存在差距（Credal 2026-03 分析），对单组织场景非刚需；学习项目定位下投入回报需评估

### 清理动作：68 个待领取 REQ 显式处置

**动作**：
1. 按主线归属过滤：主线 A/B 直接相关的 REQ → 进入主线路线图
2. 长期不领取的 REQ → 归档或标记为「长期池，不进入主线视野」
3. 触发驱动类 REQ → 显式触发条件（已有部分，需补齐）
4. 产出：更新 02 里程碑表，让主线清晰可见

**预期效果**：主线 REQ 从 ~70 降到 ~20，主线聚焦，认知负荷显著下降。

### 交汇探索：O-5 多 Agent 协作本体工程

**定位**：主线 A+B 的交汇点，作为深度探索课题（非主线承诺）

- 设计「领域专家 Agent + 本体工程师 Agent + 质量评审 Agent」协作工作流
- 结合 RAG + 图接地技术（参考 LLM4ACOE 方法论）
- 触发条件：主线 A 的 MCP 工具化完成 + 主线 B 的 A2A 暴露完成
- 学习价值：两线能力的综合展示，高创新性

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| **个人+AI 协作的认知负荷**：一次只选一条主线 | 按路线图严格串行，主线 A 未完成不启动主线 B |
| **Go 在 Agent 框架层劣势** | 聚焦协议层（MCP/A2A），不追框架层对齐 |
| **LLM 本体生成质量瓶颈**（学界共识） | 质量门禁聚焦属性/层级/公理三弱项；门禁深度随 CQ 集扩充 |
| **评测基准信任危机** | 自建基准 + 第三方交叉验证（参考 Berkeley RDI 建议） |
| **Oxigraph 性能上限** | 当前规模无需担忧；超规模时评估 Neo4j/FalkorDB |
| **LLM 能力快速变化**（如 GPT-5 在本体生成突破） | 质量门禁设计保持可调整，不绑死特定 LLM |
