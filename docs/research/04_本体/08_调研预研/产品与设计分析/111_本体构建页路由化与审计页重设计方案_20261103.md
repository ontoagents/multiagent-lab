## 2. 设计目标

1. **构建栏**：Hub+独占路径页——路径选择、路径宿主、跨栏跳板三种角色分离；每条构建路径独占一页、充分空间、互不陈列；跨路径交接从「localStorage 魔法键暗号」升级为「URL 路由参数一次性语义 + 记忆键分治」。
2. **审计栏**：从「三页签堆叠+静默失败」重排为「两页签自上而下的审计时刻动线」——五类审计时刻（T1 改完回看/T2 装载检查/T3 消费复盘/T4 查询排查/T5 合规导出）各有落点；数据面接线三档分级（直接接/需小改动/明确不做），不画饼、不渲染假数据。
3. **不改的**：五栏 IA（D-O11）、校验管线单条（C2）、审计栏消费侧定位（D-O19）、REQ-595 已交付 datasource 链路的 REST/键/状态机（仅外壳重排）。

## 3. 构建页路由化方案

### 3.1 信息架构：Hub + 独占路径页

```
本体模块（五栏不变）
└─ 构建栏
   ├─ 构建入口 Hub（#/onto/build）        ← 轻量：起点导航 + 进行中概览 + 动线条
   └─ 路径页 × N（#/onto/build/{path}）   ← 每条路径独占一页，充分空间，互不陈列
        ontochat / custom / kb / structured / datasource / parking / ontoextend / catalog
        （kg 退役为重定向，不再是路径——见 §3.3-⑧）
```

- **Hub 只做三件事**：按「手里有什么」选起点、看进行中任务、看生产动线引导。不再是路径宿主。
- **路径页只做一件事**：承载单条路径的完整流程，纵向充分展开；页内不再出现其他路径的入口（命令面板 Mod+K 保留为全局路径切换辅助——现状唯一全局枚举面，保留）。
- 构建栏顶部**不再有 8 页签切换行**（现 `BuildLayout.tsx:28-56` 的页签行随本方案退役）；模块五栏页签（OntologyModule 层）不动（C1）。

### 3.2 路由结构（hash 契约增量演进，C9）

现有 `parseOntoHash/ontoHash`（ontoRoute.ts:28-65）基础上做四点扩展，全部向后兼容：

1. **Hub 路由 = `#/onto/build`（无 path 段）**。现解析器对无第二段已返回 `{col:'build'}` 无 path——hub 路由零语法新增，但接线须两处补：①useState 初始化器「无 path→渲染 Hub」；②**popstate/hashchange 处理器补无 path 分支**——现处理器仅认 `r?.col==='build' && r.path`（BuildPage.tsx:48-62），浏览器后退回 `#/onto/build` 会被静默忽略而停留原路径页，须改为无 path 时也 setState 落 Hub。`#/onto/build/home` 保留为 hub 别名（进页 replace 成无 path 形态，旧深链不断）。
2. **路径页路由 = `#/onto/build/{path}`**，沿用现八值中的七值；`#/onto/build/kg` 保留解析但渲染为**重定向**（等效现 KgGuidePage 行为：写 `eino.onto.sidebar='audit'`+事件+hash 跳消费与审计栏）——旧深链/书签不断链。
3. **新增 hash 内 query 参数**：`#/onto/build/{path}?k=v&...`。`OntoRoute` 增可选 `params` 字段，解析器在路径段后捕获 querystring（仅 build 栏启用；assets/runtime/learn 语法不动）。用途=**跨路径交接走 URL**（§3.4），替代魔法键的交接职责。
4. **`deepLinkOnto` 同轮配套修改**（ontoRoute.ts:76-90）：现对 build+path 组合无条件写 `eino.onto.buildPath`+`homeMigrated` 两键（:82-85）——修改为：path 缺省或 `'home'`（hub 形态）**不写** buildPath 记忆键；`homeMigrated` 置位随一次性迁移逻辑退役而移除。已知调用方适配盘点（F12）：AgentSidePanel.tsx:883（path:'ontochat'——路径页深链，写键语义正确不动）、ToolPhase.tsx:104（path 变量透传——须覆盖 path 缺省情形）、CommandPalette.tsx:30（c-build 现传 `path:'home'`——改传 hub 形态无 path）与 :40（路径组条目 p.key——不动）。实施时仍须全仓 grep `deepLinkOnto` 复核无新增调用方。

`eino.onto.buildPath` 记忆键语义微调：由「最后选中路径」改为「最后访问的路径页」（hub 不写此键——含 deepLinkOnto 的 hub 形态，见第 4 点），刷新/重进构建栏时恢复到最后访问的路径页；无记录落 Hub。一次性迁移逻辑（paths.tsx:40-44 MIGRATED_KEY）退役——hub 成为缺省，存量路径值首读直接按 §3.5 落对应页。

### 3.3 Hub 页区块与八条路径页要点

**Hub 页区块**（三层节奏：页头→分区→条目，视觉静音 C7）：

| 区块 | 内容 | 形态 |
|---|---|---|
| 页头 | 标题「构建本体」+一句话定位（如「从你手里的材料出发，殊途同归收敛到同一套校验与资产」） | work-head 标准结构（pages.css:17-21），右端无主操作钮 |
| A · 进行中（有内容才显示） | 活跃异步任务+未完成草稿的续接入口（数据源见 §3.4-③ job 注册表） | 行式条目：路径图标+名称+一句话阶段+「继续」钮（深链路径页）；空态=整个区块不渲染（非空壳） |
| B · 按手里有什么选起点 | hub 一级组织=构建路径分类学本身（handbook 17 §2.2 来源×形态正交分类的落地），四组：①有一段描述→OntoChat 访谈；②有学习材料→概念停车场；③有结构化数据→SQLite 数据源／CSV·JSON 表格映射；④有现成语料或标准→知识库构建／权威本体库；⑤已有本体要改→演化；从零手动起步→自定义（空白起步唯一入口在此，消解同屏两处） | 分组标题灰字+条目行（图标+名称+一句话+诚实状态徽标+去）；每组 1~3 行；新手最常见「一段描述」置顶 |
| C · 生产动线（默认折叠） | 现 ProductionGuide 五钮跨栏引导条原样迁入，默认折叠 | 折叠条灰字（REQ-484 双模式叙事保留） |
| D · KG 消费注记 | 一行灰字：「要看 KG 图谱抽取与消费→前往消费与审计栏」链接 | 替代整张 kg 卡/页签 |

Hub 同屏点击目标：分组条目 8 + 动线展开 5 ≈ 13，且语义单一（全部=进某条路径或某栏）；对比现状 19 个且语义混杂。诚实状态徽标沿用 STATE_TAG 语义但**修正文案体系**：`可用 / 部分可用（注明前置条件）/ 一期范围（如「仅 SQLite」）`——「演化路径」（类别混入状态）退役，演化属性放进一句话描述（paths.tsx:26 文案问题）。

**路径页通用骨架**（三个共享壳组件，复用平台布局语言不引入新范式）：

1. **PathShell**（替代 BuildLayout 页签行职责）：顶条=「← 构建入口」（返回 hub，不丢进行中态——job 与草稿均在持久层，见 §3.4）+ 路径名 + 诚实状态徽标 + 右端该路径主操作。路径页正文 `.work-main` 标准结构。
2. **FlowSteps**：向导型路径共用步骤条（视觉对齐现 custom 的 Steps 语言），统一「步数可以有差异、语言必须一致」。各路径步数不变（不做假统一）。
3. **ConvergeCard**（收敛卡统一件）：生成型路径完成时刻统一三选——①进入编辑校验（深链 custom S2）②前往资产详情（资产栏深链）③再建一个（重置本路径）。落地 17 号 §2.3「差异只在生成段、收敛在资产段」的交互面统一；现 DoneCTA 及 datasource 成功卡三选、catalog onCreated 跳转等各自变体逐步归拢（DoneCTA 是否保留为内部件=实现细节，实施可裁）。
