## 3. 结论

1. **处置路径①（JDK 降级）未解除缺陷**：JDK 21.0.12 下实例级推断 5/5 恒缺——不仅未恢复，且从 JDK 25 时代登记的「时有时无（非确定性）」变为本轮观测「恒缺」。判定：**缺陷与 JDK 版本非单因素相关**（或 JDK 影响形态与登记假设相反）；REQ-513 缺陷维持、伤害面维持（推理对照 UI 推理侧+消费面 type 绑定查询在推理形态下结果不可信）。
2. **生产对账不受影响的口径复核维持**：词表闭包恒物化（下限闸 5/5 PASS）——推理形态计数对账（REQ-329）继续可信。
3. **处置路径②（Jena 升级）当前不可执行**：镜像目录核实 6.2.0=当前 latest（TUNA/阿里 binaries 目录现存即 6.2.0；上游无 6.3+ 发行）——无含修复的新版可升级。解除条件改写为「**上游 Jena 发布修复版并按本报告 §1 环境复测通过**」。
4. **登记假设修正（E6 注记）**：03 REQ-513 行「实例分类推断多次启动间时有时无」在本轮 JDK21×5 样本内为「恒缺」——非确定性形态以跨轮大样本为准，本轮小样本不足以推翻「时有无」登记，但足以否证「JDK21 恢复正常」的降级预期。
