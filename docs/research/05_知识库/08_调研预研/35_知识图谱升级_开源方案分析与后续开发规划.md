## 一、现状诊断：六个环节与「教学口径」的差距

REQ-127~130 已把功能面铺齐（浏览/多跳/治理/社区四件套），但每个环节都停在**最小可演示**档位。代码级差距如下：

| 环节 | 现状实现（代码证据） | 工业 GraphRAG/LightRAG 对照 | 实际影响 |
| --- | --- | --- | --- |
| **① 抽取** | 单 prompt 全语料一次抽取，预算硬编码 60 chunks / 24,000 字符（`backend/internal/kg/kg.go:22-25`），超限静默截断；无并发；无实体/关系类型约束 | 逐 chunk 抽取 + 并发流水线（LightRAG）；schema/本体白名单约束（GraphRAG 配置、LangChain LLMGraphTransformer、Graph Maker） | **大库覆盖不全**（第 61 个 chunk 起直接丢）；实体/关系类型漂移、粒度不稳定 |
| **② 归一化** | 仅人工合并 + 系统建议用 O(n²) 名称互相包含规则（`backend/internal/store/kg.go:750-775`，上限 20 条）；无别名表 | iText2KG 实体名+标签双嵌入余弦匹配；KGGen 两步抽取+迭代聚类 | 实体碎片化——同一实体的多种写法各自成点，度数/社区/检索全被稀释 |
| **③ 存储** | SQLite 三表，关系端点是**实体名字符串引用非外键**（`migrations/010_kg_audit.sql`），无向量列、无图引擎 | 属性图引擎或 RDF 库；实体带 embedding | 图遍历全靠 SQL IN 或全图载入内存 BFS（注释自认前提「实体 ≤ 数百」） |
| **④ 检索** | 三步管线（chunk 向量→chunk 提及实体→前沿扩展），**跳数硬限 2**（`kb/graphrag.go:110-113`，非 2 一律钳为 1——12 v0.9 设计的「递归 CTE 多跳」未兑现）；实体无向量、不能被语义搜到 | 递归/变长路径多跳；实体向量召回；HippoRAG 式 PPR 单步多跳证据收集 | seed 只能来自 chunk 命中；跳数浅且打分粗糙（0.6/0.8 硬编码） |
| **⑤ 全局问答** | label propagation（自研，上限 12 社区 + `__tail__` 长尾）+ 骨架摘要；检索用中文 2-gram 包含计数**零 embedding**（`kg/community.go:187-207`）；**摘要只回显不进 LLM 上下文，且与对话主链路不通**（`chat/runner.go` recallKB 只走三步管线） | GraphRAG global search：社区摘要 map-reduce 进上下文生成全局回答；层次社区（Leiden） | SC-K4「这个库整体在讲什么」只有页面级演示价值——**回答不是 LLM 基于社区摘要生成的** |
| **⑥ 更新** | doc 级全量替换（`ReplaceKGForDoc` 事务内删重插）；社区/摘要手动全量重建 | LightRAG 增量合并 + 选择性删除；Graphiti 边失效双时间线 | 库一大重建成本线性膨胀，摘要缓存全失效 |

**诊断结论**：最痛的两处是 **①抽取覆盖（大库截断+无约束）** 与 **⑤全局问答断链（有摘要无问答）**；④检索浅是第二梯队。这四个环节恰好都是「算法与管线」问题而非「存储引擎」问题——这直接决定了 §3 的选型方向。

## 二、开源方案全景（2026-09-29 实时核实）

### 2.1 图算法（Go 侧）

| 算法 | Go 生态现状 | 结论 |
| --- | --- | --- |
| Louvain 社区检测 | **gonum `graph/community.Modularize`** 现成（返回 `ReducedGraph` 层次结构，可逐层展开社区树）；v0.17.0（2026-01）已含 | ✅ 可直接用 |
| Leiden 社区检测 | gonum **2026-04 合入 master**（`community.Leiden`），**尚未进正式 release**（v0.17.0 无此文件） | ⏳ 等 v0.18，先用 Louvain |
| Personalized PageRank | **gonum 无任何 PageRank**（全网流传的 `graph/topology.PersonalizedPageRank` 是幻觉，路径 404）；第三方库均停更（alixaxel/pagerank 87★ 2021 停） | ✍️ 自写（稀疏图迭代 ~数十行，HippoRAG 语义） |
| label propagation | gonum 无；Go 生态无有星标实现 | 现有自研保留作对照即可 |

> Go 图算法面结论：**gonum 是唯一可信选择**（BSD-3，go get 原生零 CGO）；独立 Go 图算法库全是玩具级。其余通用图库（dominikbraun/graph 2227★）无社区检测。

## 四、后续开发规划（KB-4~9 草案）

> 排序原则：先检索侧（现有图数据直接受益、用户可感知、不动抽取管线）→ 再抽取侧（质量根因、成本较高）→ 后工程化。每项独立可交付、独立可回滚，沿「任务边界即提交」纪律。

### 阶段一：检索与全局问答闭环（P1，建议先行）

**KB-4 检索管线升级**（对应差距 ③④）
- ①**递归 CTE 多跳兑现**：跳数 1~3 可配（12 v0.9 原设计落地），替换「非 2 钳 1」的前沿 IN 近似；邻域浏览 API 同步放开；
- ②**实体向量召回**：实体「名称+描述」embedding（复用 kb embedder；向量存 SQLite BLOB 余弦——沿用 vector.go 现成模式，实体数百~千级够用），graphrag-search 扩为「chunk 向量 + 实体向量」双入口融合打分；
- ③**PPR 多跳证据收集**（HippoRAG 思路）：自写 Personalized PageRank（gonum 图结构上迭代），以向量命中实体为种子跑 PPR 取 topN 证据节点——把「逐跳扩展」升级为「全局证据分布」；与 ①② 并存可 A/B 对照（教学价值点）。
- 契约兼容：`graphrag-search` 入参/出参只增不改；retrieval SSE 事件结构不变。

**KB-5 全局问答闭环**（对应差距 ⑤，对齐 SC-K4）
- ①**社区检测升级**：label propagation → **gonum Louvain**（`community.Modularize` 层次社区），解除 12 上限（长尾合并改层次聚合）；label propagation 保留为可选对照；
- ②**摘要 map-reduce 真闭环**：global-search 由「2-gram 匹配回显 hits」改为「TopN 相关社区摘要拼入 LLM 上下文生成全局回答」（GraphRAG global search 语义）；摘要匹配可升级 embedding 相似度（可选）；
- ③**接入对话主链路**：chat recallKB 对 graphrag 库增加全局问答分支（问题意图判断或显式参数），SSE `retrieval` 事件带 `source=community` 标注（与 M16 graphrag detail 字段风格对齐，前端复用现有渲染）；
- ⚠️ 决策点：11 v1.0 已定「摘要手动重建全量生成」，12 v0.9 原设计是「按需生成+缓存」——KB-5 做大库时建议回到按需缓存口径，**立项时请开发者拍板**（KB-O4 结论部分反转）。

### 阶段二：抽取质量与治理自动化（P1~P2）

**KB-6 抽取管线升级**（对应差距 ①，质量根因）
- ①**逐 chunk 并发抽取**：分 chunk 调 LLM（worker pool，并发度/模型连接可配），解除 60 chunks/24k 字符硬截断（改库级可配预算 + 成本预估提示——KB-O4 口径）；
- ②**两步抽取**（KGGen 方法论）：先抽实体清单、再基于实体清单抽关系——保证指代一致；
- ③**本体约束模式（差异化能力，建议作本阶段亮点）**：graphrag 库可选挂载平台本体（资产或 running 方案），抽取 prompt 注入该本体的概念/关系词表作白名单约束（对齐 33 号「本体约束型」路线与 REQ-129① 库级提示词覆写底座）——**这是通用 GraphRAG 框架没有的**：平台同时拥有本体工程平面与 KG，D-O14（KB→本体）之外补上「本体→KB 抽取约束」的反向联动。

**KB-7 实体消歧自动化**（对应差距 ②）
- ①**embedding 合并建议**：实体名+描述向量化，topK 相似候选 + 阈值，替代 O(n²) 名称包含规则；沿用「**仅建议、人工确认**」边界（REQ-129 原则不破）；
- ②**别名表**：`kg_entity` 补 `alias` 列（12 v0.9 已设计未落地），检索与搜索命中别名；
- ③合并建议加入「双嵌入防误并」提示（名称+类型分权重，iText2KG 语义：`Python:语言` ≠ `Python:蛇`）。

### 阶段三：工程化与远期（P2~P3）

**KB-8 增量更新与重建工程化**（对应差距 ⑥）
- 文档删除/重索引时受影响实体/关系清理与社区**受影响子图增量重算**（LightRAG 语义）；KG 重建异步化 + 进度可见（对齐 REQ-55 索引状态语义）。

**KB-9 KGStore 可插拔抽象 + Oxigraph RDF backend PoC**（P3，触发式）
