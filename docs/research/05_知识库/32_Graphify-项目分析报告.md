# Graphify 项目分析报告

> 信息来源：微信公众号「AI开源无界」文章（2026-09-22）+ GitHub 实时数据（2026-09-23 查询）
> 开源地址：https://github.com/Graphify-Labs/graphify ｜ 官网：https://www.graphify.com

---

## 一、项目是什么

**Graphify** 是一个给 AI 编程助手（Claude Code、Cursor、Codex、Gemini CLI 等）安装的"技能"：在助手里敲一条 `/graphify .` 命令，它就把整个代码库（连同文档、SQL 表结构、配置、PDF）扫描成一张**可查询的知识图谱**。之后 AI 回答问题先查图，不用挨个读文件。

**解决的痛点**：AI 助手面对大项目时只能靠 grep 关键词匹配，token 消耗大、文件间调用关系经常漏。图谱给的上下文是"顺着真实代码关系查出的路径"，而向量检索返回的只是"长得像"的内容。

## 三、核心机制拆解

### 1. 一条命令建图，产出三个文件
敲 `/graphify .` 后项目里多出 `graphify-out` 目录。跑 FastAPI 代码库的示例中，每个节点是一个概念，同色节点属于同一子系统（自动聚类）。

### 2. 代码解析全本地，零 API 费用（最核心卖点）
- 代码文件走 **tree-sitter 语法树解析**，支持 **40+ 种语言**
- 全程不碰大模型，代码不出本机 → 建代码图谱**一分钱不花**
- 只有文档、PDF、图片、音视频等非代码内容才走模型（用助手会话模型或自配 API key）

### 3. 每条边都标了来源（可信度分级）
| 标签 | 含义 |
|---|---|
| EXTRACTED | 源码里直接写明的关系，实打实存在 |
| INFERRED | 工具自己推断的，需人工核实 |
| AMBIGUOUS | 工具自己都拿不准，单独标出 |

### 4. 三条查询命令（真在图上遍历）
- `query`：大白话提问，返回相关子图
- `path`：看两个东西之间怎么连起来的
- `explain`：解释一个概念及其周围关系

官方示例：拿 FastAPI 的图问 APIRouter，能看到它出自 `routing.py` 第 2210 行、连着 47 个节点、每条边带来源标签。

### 5. 基准测试数据（官方口径）
LOCOMO 数据集上 recall@10 = **0.497**（mem0 仅 0.048，supermemory 0.149）；QA 准确率 45.3%，低于 supermemory 的 49.7%。即：**检索召回大幅领先，但问答准确率与竞品各有胜负**，宣传时要注意辨别。

### 6. 自动分析项目结构
- **god nodes**：连接数最多的核心概念，新人看一眼就知道项目重点
- **Leiden 算法**聚类子系统并自动命名，`graph.html` 里按子系统浏览

### 7. 注释与决策进图（细节亮点）
`NOTE:`、`WHY:` 开头的注释和架构决策记录（ADR）被抽成独立节点，挂在所解释的代码上——"当时为什么这么写"和代码本身在同一张图里，可一起查到。

### 8. 持续更新与团队协作
- 改过的文件**增量更新**，不用全量重跑
- 装 git hook 后 commit/切分支自动重建图
- 图文件可提交进仓库，团队 clone 即用
- 可做成 **MCP 服务**或 HTTP 服务全团队共用
- **PR 看板**：看每个 PR 动了图中哪些区域、哪些 PR 撞在同一个子系统上（合并顺序预警）

## 四、技术架构分析

| 层面 | 选型 | 评价 |
|---|---|---|
| 解析 | tree-sitter AST | 确定性解析，快、免费、离线 |
| 聚类 | Leiden 算法 | 社区发现的学术标准做法 |
| 集成 | Claude Code / Cursor / Codex / Gemini CLI 技能 + MCP + HTTP | 覆盖主流 AI 编程工具 |
| 安装 | uv tool install（PyPI） | 现代化 Python 工具链 |

架构上它是**"确定性 AST + 概率性 LLM"的混合管线**：代码关系用确定性的语法树解析（可信、免费），非代码语义用 LLM 抽取（有成本、有噪声），再用来源标签区分两者可信度——这个设计思路比纯 GraphRAG 方案更工程化。

## 五、快速上手与避坑

```bash
uv tool install graphifyy   # 注意：PyPI 包名两个 y
graphify install            # 注册到你的 AI 助手
# 然后在助手里敲 /graphify .
```

**文章提到的坑**：
1. PyPI 上叫 `graphify` 什么的包都与官方无关，官方包是 **`graphifyy`**（装完命令仍叫 `graphify`）
2. Windows PowerShell 下敲 `graphify .` 不能带斜杠（`/` 会被当路径）
3. 提示 command not found → 跑 `uv tool update-shell` 后开新终端
4. 中文提问多的用户加装 `graphifyy[chinese]`（带 jieba 分词）

## 六、定位与局限

**值得装的场景**：
- 项目 500–5000 个文件（社区评测的最优区间）
- 新人入职快速摸清架构
- 团队共享项目结构知识
- AI 辅助重构/审查大型遗留代码

**不建议的场景**：
- 几十个文件的小项目——直接让 AI 读文件更快，别折腾
- PDF/文档堆山的项目——非代码内容走模型，建图会烧 API 额度

**风险点**：
- 项目太年轻（4 月发布、已到 v8），API 和图谱格式可能变动
- 1436 个 open issues，遇到坑可能要自己绕
- "知识图谱"类工具宣传水分普遍偏高，官方 benchmark 建议只做参考、自测为准

## 七、总结

Graphify 是今年 AI 编程工具赛道里**少数把知识图谱真正塞进日常开发流程**的产品：本地零成本建图、边级来源标注、增量更新、MCP/PR 看板这些设计都切中真实工作流。12 万 star 证明需求真实存在——AI 助手的上下文获取方式正在从"grep + 拼文件"向"查图"演进。

但也要理性：项目极年轻、迭代快、issue 积压多，benchmark 数据是官方口径。**建议动作**：先在 1000+ 文件的非核心仓库试装一次，对比你的 AI 助手在"查图 vs 直接读文件"两种模式下的回答质量，再决定是否引入团队流程。
