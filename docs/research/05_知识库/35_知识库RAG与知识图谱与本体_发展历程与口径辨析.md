# 智能体语境下的知识层：RAG、知识图谱、本体——发展历程与口径辨析

> **本文回答两个问题**：这三个词**各自到底指什么**（不同场景下含义不同，混用是大量无效争论的根源），以及它们**各自怎么走到今天**（三条独立起源、近年开始交汇的技术线）。

## 1. 口径辨析：一个词，四种说法

三个词都经历了「学术原义 → 工程口语 → 泛称」的稀释过程。方案会上出现"要不要上知识图谱"这类争论时，往往是各方说的根本不是同一件事。

### 1.1 RAG：机制，不是组件

| 口径层              | 含义                                                                                                          | 典型表述                                                                                                              |
| ---------------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **学术原义**（2020）   | 参数记忆（模型权重）与非参数记忆（可微分检索索引）的耦合；用**边际似然**联合优化检索与生成。`RAG-Sequence`（整段输出用同一批文档）与 `RAG-Token`（每个 token 可不同文档）两种形式 | Lewis et al., *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*, NeurIPS 2020；检索器 DPR + 生成器 BART |
| **工程口语**（2023 起） | 切 chunk → 向量化 → TopK → 塞进提示词。后被追称为 **Naive RAG**                                                            | "我们上了 RAG"                                                                                                        |
| **广义**（2024 起）   | 任何"把外部知识送进上下文"的手段：长上下文直塞、工具调用、数据库查询、MCP 取数                                                                  | "RAG 现在就是上下文工程的一部分"                                                                                               |
| **误用**           | 把"接了向量库"等同于"有了 RAG 系统"；把"提示词里塞了文档"等同于"做了检索优化"                                                               | —                                                                                                                 |

**关键区分**：RAG 描述的是**检索与生成的耦合机制**，向量库只是它的一个零件。判断一个系统"有没有 RAG"，要看检索是否受生成目标约束、是否有相关性判定与证据回注，而不是看有没有向量库。

### 1.2 知识图谱：有无本体，是两个物种

| 口径层                    | 含义                                                        | 判据                    |
| ---------------------- | --------------------------------------------------------- | --------------------- |
| **语义网原义**              | RDF 三元组 + **本体**（TBox）+ 描述逻辑推理 + **开放世界假设** + IRI 标识与链接数据 | 能否做逻辑蕴含、能否跨源对齐        |
| **工业属性图**              | 标签属性图（节点/边带属性），图数据库存储，图算法（最短路径、社区发现、PPR），通常**封闭世界**       | 能否高效跑图算法              |
| **GraphRAG 义**（2024 起） | 用 LLM 从文本抽取的实体—关系图，作为**检索索引**使用。常常**没有本体、不做逻辑推理**         | 是否有 schema 约束抽取、是否有公理 |
| **营销泛称**               | "知识图谱" = 任何结构化知识、甚至任何图谱可视化                                | —                     |

**最容易踩的坑**：把 LLM 抽取出的三元组叫做"知识图谱"，然后期待它具备语义网意义上的推理与一致性校验能力。实际上：

- **有本体的图**：类/属性/公理定义了"什么关系允许存在、什么必然成立"，可做蕴含推理与约束校验，能回答"这个断言是否违反模型"。
- **无本体的抽取图**：本质是**另一种索引**——它索引的是"实体间的共现与邻接"，而非"事实的语义"。它的价值是**多跳遍历与全局结构**，不是推理。它同样有效，但能力边界完全不同。

一个快速判别问句：**"这张图里，缺失一条边意味着'假'还是'未知'？**" 答"未知"的是开放世界图（语义网口径），答"假"的是封闭世界图（属性图口径）。这个答案决定了你的系统能不能在未命中时安全降级。

### 1.3 本体：契约，不是字典

| 口径层                 | 含义                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------- |
| **哲学义**             | 存在论——"存在什么"。亚里士多德的十范畴；`ontology` 一词造于 17 世纪初（Lorhard 1606 等），长期属形而上学                     |
| **信息科学义**（1990s 定型） | Gruber 1993：**共享概念化的明确形式化规范**；Borst 1997 补"共享概念模型的形式化规范说明"。四要素 = **概念化 / 明确 / 形式化 / 共享** |
| **标准义**             | RDFS + OWL（类、属性、domain/range、基数约束、公理），描述逻辑底座（OWL DL 大致对应 `SHOIN(D)`），配 SHACL 做图结构校验      |
| **LLM 时代泛称**        | schema、类型定义、JSON Schema、工具参数模式、"数据契约"                                                    |

**关键区分**——四个常被混为一谈的东西：

| 概念                  | 回答的问题                            | 例子                |
| ------------------- | -------------------------------- | ----------------- |
| **本体**              | 这个领域里**有什么种类的东西、它们能怎么关联、什么必然成立** | "项目"依赖"组件"；依赖是传递的 |
| **词表 / 受控词汇**（SKOS） | 用什么**词**指称它们                     | 同义词、上下位词表         |
| **分类法**             | 怎么**归类**（通常是树）                   | 文档分类目录            |
| **数据 schema**       | 一条**记录长什么样**                     | 表结构、JSON 字段类型     |

本体不等于"更详细的 schema"。schema 约束**语法**（字段类型、必填），本体约束**语义与公理**（关系的值域、传递性、不相交性、存在性）。一个只有字段定义的 JSON Schema 不是本体；一个带公理、能做蕴含的 OWL 模型才是。

### 1.4 坐标图：三者不在同一层

```
                    ┌──────────────────────────────────────────┐
   机制层           │  RAG / 上下文工程                          │
   (怎么送进去)      │  检索 · 压缩 · 记忆 · 工具结果 · 结构化注入   │
                    └──────────────────────────────────────────┘
                    ┌──────────────┬──────────────┬─────────────┐
   表示/结构层       │  向量索引     │  图索引       │  结构化源     │
   (以什么形态存)    │  语义相似     │  实体—关系    │  表 / 指标    │
                    └──────────────┴──────────────┴─────────────┘
                    ┌──────────────────────────────────────────┐
   语义层           │  本体（TBox）：类 / 属性 / 公理 / 约束        │
   (什么算合法)      │   ↓ 约束抽取与校验                          │
                    └──────────────────────────────────────────┘
                    ┌──────────────────────────────────────────┐
   实例层           │  知识图谱（ABox）：谁与谁有什么关系            │
   (事实)           └──────────────────────────────────────────┘
```

**一句话关系**：**本体定义什么是合法的说法，知识图谱存放具体的说法，RAG 决定哪些说法被送进模型。**

由此产生四类典型错配（实践中最高频）：

| 错配        | 表现                  | 后果           |
| --------- | ------------------- | ------------ |
| 用向量索引干图的活 | 多跳关系问题靠相似度硬搜        | 超过三四个实体后链路断掉 |
| 用图干向量的活   | 用图遍历回答模糊语义问题        | 召回僵硬、覆盖率低    |
| 用图干本体的活   | 期待抽取图能推理/校验一致性      | 图里没有公理，无从推起  |
| 用本体干图的活   | 把实例塞进本体、或期待本体回答事实问题 | 层级错乱，规模一上来就崩 |

## 2. 发展历程：三条独立起源的线

三条线起源不同、驱动力量不同，直到 2023~2024 年才真正交汇。分开看各自的脉络，才能理解它们今天的形态从何而来。

### 2.1 RAG 线：从"外接记忆"到"上下文工程"

| 时间         | 里程碑                                                    | 解决的问题 / 意义                                                                            |
| ---------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| 2017       | Transformer                                            | 注意力机制给出上下文表示的基础                                                                       |
| 2019       | ORQA、REALM                                             | 检索增强**预训练**：把检索器训进语言模型目标（REALM 在掩码预测上奖励检索器）                                           |
| 2020.05    | **RAG 论文**（Lewis et al., NeurIPS 2020）                 | 正式命名；DPR 稠密检索 + BART/T5 生成；边际似然联合优化；确立"双编码器检索器 + 生成器"模板                               |
| 2020       | DPR（Karpukhin et al.）                                  | 双编码器 + 对比学习，显著超过 BM25，成为稠密检索基线                                                        |
| 2021       | FiD（Izacard & Grave）                                   | 多段落独立编码、解码器晚期融合，可同时推理上百段落                                                             |
| 2020–2022  | ColBERT / ColBERTv2                                    | 后期交互（token 级 MaxSim），精度与速度的折中；残差压缩降存储 6~10 倍                                          |
| 2021–2022  | RETRO                                                  | 每层插入块级交叉注意力，万亿 token 索引；小模型逼近大模型的困惑度                                                  |
| 2021–2023  | WebGPT、Toolformer                                      | **检索变工具**：模型学会"何时调用外部能力"                                                              |
| 2022       | Rethinking with Retrieval（He et al.）                   | 证明即便强 LLM 也因检索而更忠实；RAG 从"QA 技术"重新定位为"生成模型的通用接地机制"                                     |
| 2023.03    | LangChain / LlamaIndex 商品化                             | 编排库把检索栈变成积木；行业焦点从"要不要用"转向"怎么做得准、便宜、可观测"                                               |
| 2023.10    | Self-RAG、HyDE、Query2Doc、IRCoT、RAGAS                    | **自适应检索**：反射 token 决定何时检索、段落是否支持结论；思维链与检索交错推进多跳；检索质量首次有系统评估                           |
| 2024.04    | **GraphRAG**（Edge et al.）                              | 针对向量检索答不了"语料整体在讲什么"的全局问题：LLM 抽实体关系建图 → Leiden 社区检测 → 分层社区摘要 → 全局/局部双检索                |
| 2024.09    | 长上下文冲击                                                 | Gemini 1.5 / Claude 达百万级 token，"RAG 是否还有必要"成为年度争论；结论是**互补而非替代**（成本、新鲜度、归因）            |
| 2024.09    | Anthropic Contextual Retrieval                         | 在切块时补上下文再嵌入，显著降低检索失败率                                                                 |
| 2024.10    | LightRAG（Guo et al.）                                   | 双层检索 + 增量更新，token 消耗约降一个数量级，不必改一文档重建全索引                                               |
| 2024       | HippoRAG（Gutiérrez et al.）                             | 受海马索引理论启发，LLM 抽三元组 + 个性化 PageRank 做图引导检索                                              |
| 2024       | RAPTOR、G-Retriever、KGP、DALK                            | 树状递归摘要 / Steiner 子树检索 / 多文档图导航 / 领域动态协同增强                                             |
| 2025.03    | Search-R1、R1-Searcher                                  | 用**可验证奖励的强化学习**教模型何时发起检索、如何组织证据（受推理模型浪潮带动）                                            |
| 2025.06    | Karpathy 提出 **context engineering**                    | "填充上下文窗口的精妙技艺与科学"，取代 prompt engineering 的说法                                           |
| 2025.08    | RAG 安全成为独立研究方向                                         | PoisonedRAG、ConfusedPilot 等证明少量恶意文档即可劫持输出；防御与鲁棒性基准加速                                  |
| 2025.09.29 | Anthropic《Effective context engineering for AI agents》 | 给出"注意力预算""上下文腐烂（context rot）""高信号 token"等工程词汇，把学科化推向主流                                |
| 2025.10    | Gartner 收录该术语                                          | 预测 2028 年出现在 80% 的 AI 工具中                                                             |
| 2026.03    | BalanceRAG                                             | 级联风险校准：先用 LLM-only 分支，自评不可靠时才升级到 RAG——**检索被当作需要路由的昂贵动作**                              |
| 2026.04    | ContextRAG                                             | 构建分层检索图但**去掉逐文档的 LLM 实体关系抽取**，砍掉随语料线性增长的 token 成本——GraphRAG 走向"轻抽取"的信号                |
| 2026.05    | 原作者口径变化                                                | RAG 原始论文共同作者 Douwe Kiela 公开表示 "RAG" 已被吸收进更宽的上位概念 **上下文工程**；同期行业媒体出现"上下文架构正在取代 RAG"的表述 |

**这条线的五代划分**（便于定位自己所处阶段）：

| 代           | 时间        | 核心命题                         |
| ----------- | --------- | ---------------------------- |
| Naive RAG   | 2020–2022 | 知识不在模型里 → 先搜后答               |
| Modular RAG | 2022–2023 | 管道太僵 → 检索/重排/生成可编排           |
| 反思 + 图      | 2023–2024 | 检索到垃圾也不知道 → 加质检员与结构          |
| 路由 + 成本     | 2024–2025 | 什么都走 RAG 太贵 → 简单直答、复杂才检索     |
| Agentic RAG | 2025–     | 固定流程不够 → 由模型自己决定查什么、查几轮、怎么合成 |

走向非常清晰：**从人设计管道，到模型自己决定怎么找信息。**

### 2.2 知识图谱线：两次浪潮，动机完全不同

**第一次浪潮（1960s–2012）：自上而下，本体优先**

| 时间        | 里程碑                                                               |
| --------- | ----------------------------------------------------------------- |
| 1960s 末   | 语义网络（Quillian 等）：节点表示概念、边表示联系——图状知识表示的雏形                          |
| 1974/1975 | 框架理论（Minsky）                                                      |
| 1984      | Cyc（Lenat）：试图手工编码人类常识，至今仍是最大的人工构建知识体系之一                           |
| 1985      | WordNet（Miller）：词汇语义网络，后来成为 NLP 基础设施                              |
| 1985      | KL-ONE / 描述逻辑：为后来的 OWL 提供逻辑底座                                     |
| 1990s     | 本体工程成为独立议题（Gruber 1993 等，见 §2.3）                                  |
| 1999      | RDF 成为 W3C 推荐标准（RDF 1.1 于 2004/2014 定稿）                           |
| 2001.05   | Berners-Lee / Hendler / Lassila 在《Scientific American》提出**语义网**愿景 |
| 2004.02   | **OWL** 成为 W3C 推荐标准                                               |
| 2006      | Linked Data 原则（用 URI 连接分布式数据）                                     |
| 2007      | Freebase、DBpedia（从 Wikipedia infobox 抽取结构化数据）                     |
| 2008/2013 | SPARQL 1.0 / 1.1                                                  |

**第二次浪潮（2012 起）：工程驱动，规模优先**

| 时间        | 里程碑                                                                                |
| --------- | ---------------------------------------------------------------------------------- |
| 2012.05   | **Google Knowledge Graph** 发布，搜索结果直接呈现知识面板——"知识图谱"一词由此进入大众视野并固化下来                  |
| 2012      | Wikidata 成立（协作式开放知识库）                                                              |
| 2013      | **TransE**（Bordes et al.）：把实体与关系嵌入向量空间，知识图谱首次能与神经网络协同计算；其后 RotatE、ComplEx 等跟进      |
| 2017–2020 | 图神经网络（GCN / GAT / R-GCN）用于链接预测与图谱补全                                                |
| 2019–2021 | KEPLER、ERNIE、KG-BERT：把 KG 注入预训练，尝试让参数记忆携带结构知识                                      |
| 2023–2024 | **LLM × KG** 爆发：GraphRAG、StructGPT、Think-on-Graph；KG 同时扮演三个角色——**检索索引、事实校验器、抽取产物** |
| 2024–2026 | 成本理性回归：LightRAG、HippoRAG、ArchRAG、Youtu-GraphRAG 等改进建图与检索；出现"去 LLM 抽取"的降本路线         |

**两波浪潮的根本差异**（理解今天乱象的钥匙）：

| 维度 | 第一波（语义网）                 | 第二波（LLM 时代）             |
| -- | ------------------------ | ----------------------- |
| 目标 | 给整个 Web 加机器可理解的语义        | 给 LLM 补上关系结构与全局视野       |
| 路径 | 自上而下：先建本体，再挂实例           | 自下而上：先抽实例，本体常常缺席        |
| 逻辑 | 描述逻辑蕴含、开放世界              | 图遍历、概率排序、常按封闭世界直觉使用     |
| 规模 | 追求跨源互联（Linked Open Data） | 通常单语料封闭（private corpus） |
| 落地 | 未大规模兑现（成本、性能、缺杀手级应用）     | 已商品化，但收益需实测             |

**语义网为什么没落地**（诚实复盘，不是为了否定它）：标注与建模成本高、推理性能跟不上规模、缺少杀手级应用、企业缺乏跨源数据治理的动力。但它沉淀下来的东西**至今仍在被使用**：RDF/OWL/SPARQL/SHACL 标准族、Wikidata 与 DBpedia 这类公共知识库、schema.org 这类轻量词汇表——**理想未兑现，资产留下来了**。

### 2.3 本体线：从哲学到"让智能体不跑偏"

| 阶段          | 时间             | 关键事件                                                                                                                                                                                                                                                           |
| ----------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **哲学期**     | 公元前 4 世纪—1950s | 亚里士多德《范畴篇》十范畴；本体论是形而上学的分支，与计算机无关。`ontology` 一词 17 世纪初出现                                                                                                                                                                                                        |
| **知识工程期**   | 1980s–1990s    | Cyc（1984）尝试编码常识；Neches et al.（1991）给出信息科学中的早期定义；**Gruber（1993）** 给出被最广泛引用的定义；Guarino & Giaretta（1995）做术语澄清；Borst（1997）补"共享"；**Guarino（1998）** 提出形式本体，强调本体依赖概念化而非词汇                                                                                             |
| **标准化期**    | 1999–2012      | DAML+OIL → **OWL（2004）**；方法论成熟：METHONTOLOGY（1997）、On-To-Knowledge、OntoClean（2002）、NeOn（2006–2010）；大型领域本体出现：Gene Ontology（1998）、FMA、SNOMED CT；SKOS（2009）为词表提供轻量出口；schema.org（2011）成为工业界愿意接受的极小共识                                                                |
| **沉淀与反思期**  | 2010s          | 本体工程被视作"重资产"；自动**本体学习**（ontology learning）长期未达预期；工业界大量转向轻量 schema 与属性图；本体在主流 AI 话语中边缘化                                                                                                                                                                         |
| **LLM 期**   | 2023–          | LLM 辅助本体工程全面铺开：术语抽取、候选类与关系建议、定义撰写、能力问题（competency questions）生成、本体匹配（Agent-OM 等）。代表工作：LLMs4OL、OntoGPT、Text2KGBench。本体工程师角色从"手工建模者"变为"语义工作流的编排者"                                                                                                                 |
| **Agent 期** | 2025–          | **智能体成为本体的主要消费者**（此前是数据库、搜索引擎、符号推理器）。两个可见变化：①本体从"只给机器推理的形式件"变成"智能体检索、校验、记忆、规划、行动时依赖的运行时结构"；②本体从 **logic-first** 转向 **agent-digestible**——`rdfs:comment`、`skos:definition`、`skos:scopeNote`、`skos:example` 这类自然语言字段不再是给人看的注释，而是**语义可供性**：它们直接影响检索、抽取、消歧、工具选择与生成 |

**这条线最值得记住的一句观察**：本体的价值主张正在迁移——从「**让机器能推理**」迁移到「**让智能体不跑偏**」。前者的市场从未真正兑现，后者的需求正在变得刚性：当智能体要长时间自主运行、要调用工具、要写入记忆时，缺少一个可被校验的语义契约，系统就无法判断"这一步是否越界"。

### 2.4 三条线的交汇点

| 时间        | RAG 线              | KG 线               | 本体线                    | 交汇信号                       |
| --------- | ------------------ | ------------------ | ---------------------- | -------------------------- |
| 2020 前    | 检索增强预训练            | 语义网沉淀期             | 本体工程重资产化               | 基本独立                       |
| 2020–2022 | RAG 命名、稠密检索成熟      | KG 嵌入与 GNN         | 本体边缘化                  | 偶有交叉（KEPLER/ERNIE）         |
| 2023      | 自适应检索、评估体系         | KG 用于幻觉缓解          | LLM 辅助本体工程萌芽           | **LLM 成为共同催化剂**            |
| 2024      | GraphRAG           | GraphRAG 让 KG 重新热门 | —                      | **KG 被重新定位为"检索结构"**        |
| 2025      | Agentic RAG、RL 教检索 | 成本理性回归             | 本体面向 agent 重写          | **三者都进入"外部状态"话题**          |
| 2026      | 被上下文工程吸收           | 轻抽取、去 LLM 化        | schema 约束抽取（用本体限定抽取目标） | **schema 回归**：无约束抽取的噪声不可治理 |

**三个收敛点**：

1. **外部结构化状态成为共识**：知识图谱、本体、记忆层，本质上都是"放在模型外面的、可被检索与校验的东西"。
2. **上下文工程成为总纲**：检索、压缩、记忆、工具结果、结构化注入，都被统一到"决定模型每一步看到什么"这一件事之下。
3. **schema 回归**：2024 年的无约束 LLM 抽取在 2025–2026 年暴露出噪声不可治理的问题；用本体/schema 限定抽取目标（限定实体类型、关系类型、属性类型）成为新范式的共同选择——这恰是本体线在沉寂十余年后重新被需要的理由。

## 3. 关系模型与组合方式

### 3.1 分层职责

| 层   | 组件              | 职责                    | 失效表现              |
| --- | --------------- | --------------------- | ----------------- |
| 机制层 | RAG / 上下文工程     | 决定何时检索、检索什么、如何组装、何时压缩 | 上下文膨胀、context rot |
| 表示层 | 向量索引            | 语义相似召回                | 模糊语义尚可，多跳链路断      |
| 结构层 | 图索引             | 实体关系遍历、社区结构           | 覆盖率低（依赖抽取质量）      |
| 语义层 | 本体（TBox）        | 定义合法的类型、关系与公理；约束抽取与校验 | 无本体则噪声不可治理        |
| 实例层 | 知识图谱（ABox）      | 存放具体事实，支持溯源           | 不完备（开放世界下缺失≠否定）   |
| 治理层 | 溯源、审核队列、冲突消解、权限 | 保证"送进上下文的东西可信"        | 错误答案带正确引用，最难发现    |


### 3.2 四种典型组合与代价

| 组合 | 擅长 | 不擅长 | 主要代价 |
| --- | --- | --- | --- |
| **① 纯向量 RAG** | 语义相似片段、开放域问答 | 多跳关系、全局主题 | 最便宜；但复杂问题上会"自信地错" |
| **② 向量 + 无本体抽取图** | 多跳遍历、全局社区摘要 | 一致性校验、逻辑蕴含 | 建图 token 成本随语料线性增长；抽取噪声 |
| **③ 向量 + 本体约束的图** | 领域固定时的可控抽取与校验 | 跨域泛化、冷启动 | 本体建模成本高（前期重资产） |
| **④ 结构化源 / 语义层直连** | 指标、维度、KPI 类问题 | 非结构化文本 | 需要语义层建模；向量检索在这类问题上得分接近零 |

**核心工程建议：路由，而不是统一。** 用一种检索策略对付所有问题，是产生"自信地错误"的最短路径。按问题类型分流——

- **查事实（lookup）** → 混合检索（稠密 + BM25）+ 重排
- **查关系（relationship）** → 图遍历
- **查指标（metric）** → 语义层 / 结构化查询
- **查全局（global）** → 社区摘要或分层摘要
- **高价值多跳** → 智能体式检索（规划、检索、评分、改写、再检索）

### 3.3 2026 年的基线形态

综合当前行业实践，一个"够用"的知识层大致是：

> 混合检索 + 重排作为默认底座（纯向量检索已退化为 fallback）；**检索作为智能体可调用的工具**，而非焊在提示词前面的固定步骤；按问题类型路由到图 / 语义层 / 记忆；对窗口做显式的工程管理（按需加载、填满时压缩、激进丢弃）。

## 4. 工程边界与常见误用（诚实清单）

**关于 RAG**

- 检索质量无法用生成质量掩盖。如果语料本身矛盾、过期、权限错误，RAG 只会更快更自信地给出错误答案，并且**带着看起来正确的引用**。
- 检索必须能被打分。无法度量检索质量，就无法改进它——这是区分演示系统与生产系统的分水岭。

**关于长上下文**

- 长上下文**不替代**检索，四个理由同时成立：成本（注意力平方级；有厂商估算全量调用可比按需检索贵约三个数量级）、规模（真实语料远大于任何窗口）、延迟（长上下文调用数十秒级，在每任务多次检索的智能体循环中不可接受）、以及 **context rot**（即使装得下，填满后质量下降）。
- 但缓存经济学改变了压缩的账：主流服务商的 prompt 缓存让重发前缀便宜约 90%（DeepSeek 缓存价约为原价 1/50）。**一旦改写历史（摘要/压缩），前缀失效、全价重算** —— 在这种定价下，摘要要缩小 50 倍以上才回本。因此成熟的 harness 都在**少压缩、结构化压缩、缓存友好地压缩**（先裁工具输出、系统提示与技能常驻不参与重置），而不是持续压缩。有从业者把 KV-cache 命中率称为生产级智能体最重要的单一指标（**未定论，但方向被多方印证**）。

**关于知识图谱**

- 图**不自动带来推理**。没有本体的抽取图只能遍历，不能蕴含。
- 抽取质量是天花板。历史上的自动化系统都出现过概念漂移（NELL 需周期性重训清理）；DBpedia、Wikidata 存在已知错误与破坏性编辑；公共知识图谱也曾向海量用户传播过错误事实（错误标注的死亡信息、错误的身份合并）。
- 不完备性 + 开放世界假设：缺失一条边**不等于**该事实为假。逻辑上保守，工程上别扭——系统必须在未命中时明确降级，而不是静默当作"不存在"。

**关于 GraphRAG 的收益**（最需要实测的一项）

一个公开工程复述给出的对照（41 个真实案例，课程与文档类语料）：

| 指标 | GraphRAG | 混合检索 |
| --- | --- | --- |
| 引用正确率 | 100% | 100% |
| 课程回忆率 | 76% | 76% |
| MRR | 0.65 | **0.70** |
| 输入 token | +61% | 基线 |
| 每轮成本 | +44% | 基线 |
| 建索引成本 | 90 篇约 $45；全语料估算接近 $2000 | — |

结论：**如果你的数据不是一张高度互联的实体网，先测再上**。这类实测并不否定 GraphRAG，而是把"要不要上图"从信仰问题变成可度量问题。

**关于本体**

- 本体是重资产，冷启动慢。收益出现在**领域固定、需要校验与治理、需要长期演进**的场景；一次性问答任务通常不值得。
- 本体的失败模式不是"建不出来"，而是"建完没人用"——建模与消费脱节是历史上一再出现的教训。

**关于记忆层（新增风险面）**

- 可写的长期记忆是**新的攻击面**：能写入长期记忆的对手可以影响该系统此后触及的每一个用户；反向则是跨会话上下文泄漏。
- 多智能体下会出现"上下文一致性"问题：两个智能体检索到不同切片，对同一对象给出矛盾答案，且无人仲裁。**未定论**，但已被视为将要被命名的能力项。

## 5. 面向智能体平台的取舍建议

> 本节面向"以智能体为核心的系统"给出通用取舍，不涉及任何具体产品。

1. **先分清"知识给谁用"。** 给**模型**用的（进上下文，追求高信号密度）、给**人**用的（浏览与溯源，追求可解释链路）、给**系统**用的（校验与路由，追求可判定）——这三者的最优形态不同，混在一起做必然三边妥协。
2. **检索是工具，不是流程前缀。** 由智能体决定何时检索、检索几轮、是否需要改写查询，而不是在提示词前面焊死一次 TopK。这条是 Naive RAG 与 Agentic RAG 的分界。
3. **结构化注入要按形态分流。** 片段（向量）解决"像不像"，关系（图）解决"连不连"，本体（schema）解决"合不合法"。三者回答的问题不同，不能互相替代。
4. **质量与治理优先于算法。** 溯源到原文、审核队列、冲突消解、权限边界——这些决定了系统能否被信任，而算法只决定上限。错误答案配正确引用是最难发现的失败模式。
5. **评估先行。** 至少能回答：这次检索召回了什么、哪些真的被模型用上了、为什么这条被提升。只统计"检索了什么"而不知道"用了什么"，记忆系统就永远停留在只写一次的日志。
6. **本体按需上，且要有消费方。** 在"领域固定 + 需要校验 + 长期演进"三条件同时成立时才值得投入；投入前先确定谁消费它（抽取约束？校验？工具选择？记忆结构？），否则会重演"建完没人用"。
7. **成本意识前置。** 建图与重排的 token 成本随语料线性增长；缓存让历史改写变得昂贵。这两条共同决定了"压缩策略"与"建图范围"必须先算账再设计。

## 6. 前沿争议（未定论，引用时请标明）

| 争议 | 一方 | 另一方 | 现状 |
| --- | --- | --- | --- |
| RAG 是否"已死" | 长上下文 + 智能体检索让它退居组件 | 检索在成本/新鲜度/归因上不可替代 | **话语层面被吸收，组件层面永存**——连原始论文作者都认同"RAG 已被并入上下文工程" |
| GraphRAG 收益是否值回成本 | 多跳与全局问题显著改善 | 实测中 MRR 反而更低、成本高 44%~ | 取决于语料是否为高度互联的实体网；**必须自测** |
| 本体是否必要 | 重资产、历史上多次失败 | agent 时代成为刚需契约 | 折中路线正在成形：轻量 schema 约束抽取，而非完整形式本体 |
| 记忆层是否会成为新基础设施层 | 推理成本每 18 个月降一个数量级，而存储/检索/重排成本随用户与会话深度增长 | 模型层会持续吞噬外部记忆 | 主流判断偏向"会"：云账单主线将从 GPU token 转向检索与记忆基础设施（**未定论**） |
