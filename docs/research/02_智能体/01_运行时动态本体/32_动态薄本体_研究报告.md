# 智能体运行过程中构建动态本体：可行性与方案研究报告

> 研究主题：以 MLSys 2026 论文《Ontology-Guided Long-Term Agent Memory for Conversational RAG》（Hill Research，Shuang Cao & Rui Li）为起点，结合 30+ 篇相关文献，系统论证"在智能体运行过程中构建动态本体"的可行性，并给出可落地的参考方案。
>
> 研究日期：2026 年 9 月 25 日
>
> 配套文档：《动态本体 × 智能体记忆：研究资料合集》（同目录 `动态薄本体_资料合集.md`）

---

## 摘要

智能体在长期多会话运行中面临一个已被反复证实的结构性缺陷：当用户的当前提问与早期陈述之间**没有词汇重叠**时，稠密检索与长上下文方案都会漏掉本应召回的记忆——dense-only 检索的 Recall@10 随对话从 20 轮延长到 60 轮以上，从 0.61 跌至 0.28。MLSys 2026 的本体引导记忆论文给出了一条解题路径：在运行过程中从对话数据里**自动学习一张轻量本体图**，把语句级证据提升为带溯源的类型化概念关系，使检索在"概念层面"而非"token 层面"运作，将 Recall@10 提升至 0.70、成本较长上下文降低 81%。

本报告的核心结论是：**在智能体运行过程中构建动态本体在技术上已经可行，且正在从研究议题转变为工程实践共识；但其可行是有条件的——必须以"保守提升门控 + 双时间线 + 验证闭环"三件套约束本体演化过程，否则 schema 漂移、三元组幻觉与冲突污染会把收益反转成风险。** 报告给出五项技术可行性证据链、一份工程成本账本、六大风险对策，以及一套四层六模块的参考架构和轻量/标准/重型三档实施路线。

## 1. 问题界定与研究背景

### 1.1 源起：一篇 MLSys 2026 论文揭示的"隐式召回失败"

微信文章拆解的 MLSys 2026 论文《Ontology-Guided Long-Term Agent Memory for Conversational RAG》定义了一个此前未被充分度量的失效模式——**隐式召回失败（implicit recall failure）**：

> 用户在会话 1 第 3 轮说"我超爱《泰坦尼克号》"；此后两周对话横跨 87 个回合；到会话 3 第 91 轮，用户问"这周末我该看什么？"——提问中不含任何与《泰坦尼克号》重叠的词汇，但用户期待系统给出个性化的爱情片推荐。

该论文的关键量化发现：

| 指标 | Dense-only | 长上下文（128K） | 本体引导系统 |
|---|---|---|---|
| Recall@10（隐式查询） | 0.580 | 0.601 | **0.706** |
| nDCG@10 | 0.410 | — | **0.514** |
| 相对成本 | 1.0× | ~5.6× | **1.31×** |
| P95 延迟 | — | 310ms（越界） | **~185ms** |
| 引用忠实度 | 0.86 | — | **0.93** |

一个决定性细节：**把完整历史塞进 128K 上下文，Recall@10 仅比 dense-only 高 0.02，成本高一个数量级**。这说明"扩窗口"无法替代"结构化理解"——问题不在记忆存不存得下，而在检索时能不能**跨越概念鸿沟**找到它。

### 1.2 什么是"运行时动态本体"

本报告讨论的**动态本体（dynamic ontology）**，指智能体在运行过程中（at runtime）针对自身的记忆与知识流，**自动归纳、持续演化、自我维护的概念层 schema**，包含三个构成要素：

1. **类型系统**：实体类型、关系类型、事件类型的概念词表（如 `User → PREFERS_GENRE → Genre`）；
2. **实例图**：按该 schema 组织的符号化记忆图谱（节点/边/属性/时间戳/权重）；
3. **演化机制**：能随新证据**新增类型、合并别名、废弃过时关系、提升/降级概念层级**，且全程可追溯、可回滚。

与传统本体工程的区别在于知识生产主体的倒置：传统流程是"专家先定义 schema，系统再填充实例"；动态本体则是"**数据先产生实例，schema 从实例中归纳涌现**"（data-to-schema），并且这个归纳发生在系统服务运行期间，而非离线一次性工程。

### 1.3 为什么智能体需要动态本体：静态方案的四点结构性缺陷

1. **词汇鸿沟**：稠密检索靠表面语义相似度，跨会话的隐式引用（别名、省略、概念联想）是其失效区。LoCoMo 基准（ACL 2024）证明长上下文 LLM 与普通 RAG 在跨数十会话的时间与因果推理上显著落后于人类。
2. **固定 schema 覆盖不了开放世界**：AutoSchemaKG（arXiv:2505.23628）指出经典 KG 构建的悖论——**依赖专家预定义 schema，从根本上限制了可扩展性与领域覆盖**。对话场景的实体/关系类型几乎无法枚举（"用户讨厌香菜"算 preference 还是 fact？）。
3. **事实随时间失效**：静态图谱无法回答"现在还成立吗"。Zep/Graphiti 的 bi-temporal 模型证明，记忆系统必须区分"事实何时发生"与"何时被记录"，并在矛盾出现时**失效化（invalidate）而非删除**旧边。
4. **记忆与本体彼此绑定演化**：运行时研究的一个重要共识是——**解决智能体的记忆管理问题与解决本体的动态演进问题本质上是同源的**。系统必须具备类型发现、异常检测、实体消歧合并与修剪能力，否则"智能体无法学习它无法命名的东西"。

## 2. 文献全景与技术演进脉络

### 2.1 一条主线：从静态知识工程到运行时本体自组织

梳理 2023–2026 年文献，可以看到清晰的四阶段演进：

```
静态知识工程            容量型记忆              结构增强检索            运行时动态本体
(专家schema+抽取)  →   (OS式分层缓存)     →   (图+向量混合)      →   (schema归纳+自演化)
2023前                  2023 MemGPT            2024 GraphRAG/HippoRAG   2025-2026
                                              2024-25 LightRAG/MemoRAG  AutoSchemaKG/Zep/Tag2Graph
```

LLM 知识图谱构建综述（arXiv:2510.20345）将这一转变概括为范式倒置：研究焦点从 **"LLMs for Ontology Engineering"（LLM 辅助专家建本体）转向 "Ontologies and KGs for LLMs"（本体和 KG 服务于 LLM 的记忆与推理）**——图谱不再是给人看的静态知识库，而是 LLM 的"外部知识记忆"（external knowledge memory），优先考量事实覆盖率、可扩展性与可维护性，而非语义完备性。

### 2.2 四条技术路线对比

**路线 A：容量型记忆（解决"存不下"，不解决"找不准"）**

| 系统 | 核心机制 | 局限 |
|---|---|---|
| MemGPT (2023, → Letta) | OS 式分层：主上下文/外部上下文，LLM 自主 page in/out | 只管存取调度，无概念结构；召回仍依赖相似度 |
| Mem0 (arXiv:2504.19413) | write-manage-read 循环：抽取事实→增删改决策→读取接地 | 记忆单元彼此独立，缺乏类型化关联，隐式召回弱 |
| A-MEM (arXiv:2502.12110) | Zettelkasten 卡片盒式动态组织笔记网络 | 链接为涌现式无类型关联，schema 意识弱 |

**路线 B：结构增强检索（引入图，但 schema 固定或无 schema）**

| 系统 | 核心机制 | 与动态本体的关系 |
|---|---|---|
| GraphRAG (arXiv:2404.16130) | LLM 抽取实体图 + Leiden 社区检测 + 分层摘要，map-reduce 回答全局问题 | 需**预定义实体类型**；社区摘要会随后续文档变更过时，需重建 |
| HippoRAG (NeurIPS 2024) | 海马体索引理论：LLM 当"海马体"建 KG 索引，Personalized PageRank 单步多跳 | 单步检索比迭代检索便宜 10-20×、快 6-13×；schema 固定 |
| LightRAG (arXiv:2410.05779) | 双层检索（低层实体/高层主题）+ **增量更新算法**（新文档并入图，免全量重建） | **增量更新机制可直接移植**到动态本体；但 schema 仍是抽取时隐式产生 |
| MemoRAG (theWebConf 2025) | 轻量 LLM 建全局记忆 → 生成草稿线索 → 引导检索 → 强 LLM 生成 | 全局记忆压缩形态，无类型化本体 |

**路线 C：动态 schema 归纳（动态本体的直接文献基础）**

| 系统 | 核心机制 | 关键证据 |
|---|---|---|
| **AutoSchemaKG** (arXiv:2505.23628) | LLM 同时抽三元组+归纳 schema；实体+事件双建模范化（conceptualization）；零预定义 schema | 处理 5000 万文档构建 ATLAS（9 亿节点/59 亿边）；**schema 归纳与人工 schema 语义对齐达 92–95%**；多跳 QA 超 SOTA 12–18% |
| EDC (Zhang & Soh 2024) | Extract–Define–Canonicalize 三段式：开放抽取→语义定义→schema 规范化 | 可对齐已有本体，也可在无预定义结构时新建 |
| AdaKGC (2023) | 动态 schema 演化：纳入新关系/新实体类型**无需重训** | 证明 schema 扩展不必绑定模型训练 |
| Agentic-KGR (arXiv:2510.09156) | 多智能体 RL 协同演化：动态 schema 扩展 + **staged relation promotion（分阶段关系提升）** + 置信衰减 | 实体去重准确率 98.5%；事务批量写入提速 30% |
| Buehler (MIT, J. Mater. Res. 2025) | 推理型 LLM + 持续更新图谱的反馈循环，迭代自组织 | 数百轮迭代后图谱呈**无标度网络**：hub 形成、模块稳定、不饱和——从复杂网络视角证明自组织图谱的数学稳定性 |

**路线 D：时序记忆图谱（对话场景的动态本体落地）**

| 系统 | 核心机制 | 关键证据 |
|---|---|---|
| **Zep / Graphiti** (arXiv:2501.13956) | 三层子图（episode→语义实体→社区）+ **bi-temporal 双时间线** + 矛盾边失效化 + **self-building ontology** | LongMemEval 上较全上下文准确率 +18.5%、延迟降 90%；单会话偏好类问题 20.0%→56.7% |
| **Tag2Graph-Learner**（MLSys 2026 原论文） | 标注器+分类器走热路径、LLM 只做验证器；反复一致共现的证据经门控**提升为类型化概念边**；反馈驱动权重更新 | Recall@10 0.58→0.70；跨模态分歧 −47%；冷启动（≤10 轮）0.613，成熟画像 0.718 |

### 2.3 评测基准图谱：隐式召回已被系统化度量

| 基准 | 规模 | 考察能力 | 对动态本体的意义 |
|---|---|---|---|
| LoCoMo (ACL 2024) | 50 段对话，~300 轮/9K tokens，最多 35 会话 | 单跳/多跳/时序/开放域 QA | 证明长程时序因果推理是 LLM 系统的普遍短板 |
| LongMemEval (ICLR 2025) | 500 题，平均 115K tokens | 信息抽取、跨会话推理、时序、知识更新、拒答 | 商业助手平均掉 30 分；偏好与时序类是重灾区 |
| BEAM (2025) | 对话最长达 10M tokens | 含矛盾消解、事件排序等 10 项能力 | 1M 窗口模型也搞不定——"堆窗口"路线的终结证据 |
| MemoryAgentBench (2025) | — | 含冲突消解/选择性遗忘 | 补充记忆Agent能力面 |
| Implicit Preference Recall（原论文自建） | 500 段多会话，均值 73 轮，三领域 | 无关键词查询的早期偏好召回 | **直接以"隐式召回"为评测对象**，标注应召回的历史证据 |

> 注意基准生态的已知问题：LoCoMo 存在 vendor 子集差异（完整版 50 段/7512 题 vs 广泛引用的 10 段/1986 题子集），LLM-as-judge 选择可造成两位数波动，跨论文数字需谨慎对比。

### 2.4 交叉验证：多条独立证据链指向同一结论

值得强调的是，"运行时动态本体有效"并非单一论文的孤立结论，而是**至少四条独立研究线在 2025–2026 年交汇的共识**：

1. **学术系统线**（Tag2Graph、HippoRAG、AutoSchemaKG）：概念级结构对隐式/多跳检索的收益被反复量化；
2. **工业产品线**（Zep/Graphiti、Mem0、Letta）：451 Research 2026 年 4 月报告确认 Zep 已在生产系统中运行"self-building ontology"，检索路径 <200ms；
3. **复杂网络理论线**（Buehler 2025）：反馈驱动的图自组织产生数学上稳定的无标度结构，不发散、不饱和；
4. **机制可解释线**（arXiv:2605.03354 电路分析）：对 mem0/A-MEM 的跨模型电路追踪发现记忆路由计算在 0.6B 模型即存在，但内容接地要到 4B——提示动态本体系统中的"路由决策"与"内容抽取"应当用不同规模的模型分工。

## 3. 可行性分析

### 3.1 技术可行性：五项证据链

**证据 1：LLM 的 schema 归纳质量已越过可用阈值。**
AutoSchemaKG 在零人工干预下，自动归纳的 schema 与人类专家 schema 达到 92–95% 语义对齐；LLMs4OL、Ontogenia、CQbyCQ 等工作证实 LLM 可自主识别类、对象属性并生成逻辑公理，质量"与初级人类建模者相当"。这推翻了"本体必须专家手建"的前提——这是动态本体可行性的第一块基石。

**证据 2：增量图构建与实时更新技术已经成熟。**
Graphiti 的实时增量写入（bi-temporal 边失效、标签传播社区更新免全量重算）与 LightRAG 的增量更新算法（新文档按同一索引流程并入节点/边并集，免全量重建）解决了"运行时持续写入"的工程问题。Agentic-KGR 的事务批量 upsert 进一步把高吞吐更新开销降 30%。

**证据 3：隐式召回收益被多系统独立复现。**
- 原论文：Recall@10 +0.12（0.58→0.706），别名子集 0.49→0.66，时间间隔子集 0.52→0.67；
- Zep：LongMemEval 单会话偏好 20.0%→56.7%，时序推理 45.1%→62.4%；
- HippoRAG：多跳 QA 提升 20%，成本降 10-20×。
三个团队、三种实现，同一方向、同一量级的收益——复现性达标。

**证据 4：反馈闭环可以充当监督信号，且已被工程化。**
原论文的"被使用且正确/被遗漏但需要"双通道反馈，把检索结果直接回写记忆表示，**无需离线重训**即可持续个性化；路由诊断显示随本体变密，graph-first 选择比例从 41.2% 升至 71.3%、错误路由率从 14.2% 降至 6.8%——系统确实在"越用越准"。

**证据 5：延迟与成本可控制在生产护栏内。**
原论文全链路（抽取→提升→路由→检索）P95 约 185ms，历史扩 8× 延迟仅 176→189ms；存储线性增长（图 2.5→18.1MB/用户，FAISS 12.0→93.1MB/用户），呈"**存储线性、延迟有界**"的良性扩展特性。Zep 生产配置检索 <200ms。成本侧：原论文较长上下文降 81%，HippoRAG 较迭代检索便宜 10-20×。

### 3.2 工程可行性：一份成本账本

以原论文披露数据外推一个 10 万 DAU、人均日均 200 轮对话的生产系统：

| 项 | 估算 | 依据 |
|---|---|---|
| 每用户存储（图+向量） | 8× 历史时约 110MB | 原论文扩展曲线（2.5→18.1MB 图 + 12.0→93.1MB FAISS） |
| 热路径延迟 | <200ms P95 | BERT-base 标注器 + 2 层 MLP 打分/路由，LLM 仅离线/异步验证 |
| LLM 调用 | 不在服务热路径 | 蒸馏 MLP 上线，重学习全部离线；LLM 验证器微批异步 |
| 相对长上下文方案成本 | ~0.18–0.19× | 原论文 81% 成本削减 |

结论：**成本与延迟不构成可行性障碍**，反而是动态本体路线相对长上下文路线的核心优势。

### 3.3 六大风险与对策

| # | 风险 | 机理 | 对策（文献已验证） |
|---|---|---|---|
| R1 | **本体漂移/schema 碎片化** | 每次归纳都引入新类型，词表爆炸、同义类型并存 | 提升门控（promotion gate）：仅"跨会话复现 + 跨上下文一致 + 本体兼容"的证据可入 schema（原论文）；EDC 的规范化阶段统一归并；周期性社区检测收敛类型层级（GraphRAG/Graphiti） |
| R2 | **三元组幻觉污染图谱** | LLM 抽取错误一旦入图，会通过多跳遍历放大 | 职责分离：轻量模型走热路径、**LLM 只做 yes/no 验证器**；低置信度三元组只留向量存储不入图（原论文）；RAKG 式检索增强校验过滤幻觉 |
| R3 | **冷启动能力不足** | 验证证据需积累，10 轮对话时验证覆盖率仅 19% | 混合检索兜底（冷启动仍 0.613 > dense-only 0.557）；种子 schema 预热（领域模板 + Evontree 式少样本挖掘 LLM 内隐知识）；冷启动期提高 dense-first 路由先验 |
| R4 | **矛盾与时序不一致** | 用户偏好随时间改变，新旧边冲突 | bi-temporal 双时间线 + 矛盾边失效化而非删除（Graphiti）；所有提升带溯源支持审计回滚（原论文） |
| R5 | **隐私与治理** | 本体把分散对话聚合为高密度画像，聚合泄露风险上升 | 租户级增长配额、隐私敏感断言拒绝提升（原论文护栏）；ABAC 属性级访问控制（Zep 企业版）；提升需满足"证据多样性"门槛防单点推断 |
| R6 | **反馈稀疏导致停滞** | 用户不确认时闭环失去监督 | 事后反事实运行挖掘"被遗漏但需要"的修复性事实（原论文）；按关系设置学习率与限速防重学习风暴 |

### 3.4 可行性结论

**分级判定：**

| 场景特征 | 判定 | 依据 |
|---|---|---|
| 长期多会话个性化（助手/陪伴/客户运营） | ✅ **强可行**，收益/成本比最佳 | 隐式召回正是痛点核心，三线证据复现 |
| 企业知识型智能体（跨部门多源知识） | ✅ **可行**，需治理配套 | AutoSchemaKG 证明企业级规模可达；ABAC+溯源成熟 |
| 单轮 QA、短会话工具型 Agent | ⚠️ **不划算** | 提升机制需要跨会话复现信号，短会话喂不饱本体 |
| 开放域因果推理、超长程叙事一致性 | ⚠️ **部分可行** | 原论文自认评测覆盖有限，属开放问题 |
| 强合规域（医疗/金融） | ✅ 可行但需重治理 | Hill Research 本身即临床 AI 团队；审计回滚是刚需前提 |

## 4. 方案设计：运行时动态本体参考架构

### 4.1 总体架构：四层六模块

```
┌─────────────────────────────────────────────────────────────┐
│ L4 本体层（动态schema）  类型词表 | 概念层级 | 演化日志            │
│   ↑ 提升/归纳/合并/废弃                                       │
│ L3 符号记忆层            类型化概念图（带权重/时间戳/溯源）        │
│   ↑↑ 混合检索（图遍历⇄稠密⇄画像先验）+ 可学习路由                 │
│ L2 情景记忆层            向量存储（全部语句嵌入，含低置信度证据）   │
│   ↑ 摄取                                                      │
│ L1 事件层                原始对话/消息/工具轨迹（无损，带参考时间） │
└─────────────────────────────────────────────────────────────┘
        ↕ 反馈闭环：使用确认→边权重强化；反事实→补遗
```

设计原则（综合文献得出）：
- **双存储共生**：全部语句进向量存储（保召回广度），仅通过门控的证据入图（保概念精度）——低置信度信息"仍可检索，但不影响图"；
- **热路径无 LLM**：抽取、打分、路由全部用蒸馏小模型（<10ms 级），LLM 只做异步验证与离线归纳；
- **一切提升带溯源**：可追踪、可撤销是动态演化的安全前提。

### 4.2 六个核心模块

**M1 事件摄取层**
每条语句并行写入：① 图存储（候选三元组，待验证）；② 向量存储（嵌入+回合号+实体元数据）；③ 画像缓存（近期检索统计）。参考时间戳解析相对日期（Graphiti 做法）。

**M2 证据抽取与验证**
span 级 BIO 标注器识别实体/属性 + 轻量关系分类器连出候选三元组 → **受约束 LLM 只做 yes/no 验证 + 关系短语规范化到本体词表**。分工逻辑：热路径保持快速，验证器吸收开放文本多样性。

**M3 本体提升门控（系统的灵魂）**
断言→概念关系的提升条件（全部满足）：跨会话复现（带近因加权）× 跨上下文一致 × 本体兼容，由离线浅层分类器聚合成校准概率，超保守门限（论文验证 τ∈[0.60,0.80] 宽平台区）且证据足够多样才入边。同时处理别名消解：片名/昵称/多语言变体仅一致时合并。新增关系类型走同一门控——这就是"动态本体"的生长机制。

**M4 双时间线与冲突消解**
每条边携带 `valid_at / invalid_at / expired_at`；新事实与旧边矛盾时**失效化旧边而非删除**，保留可查询历史（"用户 2025 年喜欢什么？"）。社区层（标签传播）负责矛盾时的真值状态更新。

**M5 混合检索与可学习路由**
三视角打分：`s = 0.55·s_graph + 0.35·s_dense + 0.10·s_profile`（权重离线拟合，跨域稳定）。路由器只消费廉价信号（别名风险、时间距离、是否触达提升概念、近期策略成功率），按查询分派 graph-first/dense-first 与候选预算：个性化重→graph-first（论文实测 85%），事实型→dense-first（88%）；两视角尖锐分歧时花上限小预算额外扩展一跳，超延迟护栏则回退安全视角。一致性问题**只在被验证使用过的证据子集上对齐**两模态（分歧 −47%），避免全池对齐的代价。

**M6 反馈闭环与记忆维护**
- "被使用且正确"通道：引用被验证忠实 → 强化对应边权重；
- "被遗漏但需要"通道：事后反事实运行发现漏召回 → 补建修复性事实；
- 微批异步应用，按关系学习率 + 限速，重学习不阻塞请求路径。

### 4.3 三档实施路线

| 维度 | 轻量档 | 标准档（推荐） | 重型档 |
|---|---|---|---|
| 本体来源 | 固定种子 schema + 运行时仅实例填充（Zep 模式入门版） | 种子 schema + 运行时类型发现与提升（原论文 Tag2Graph 模式） | 全自动 schema 归纳 + 多智能体协同演化（AutoSchemaKG/Agentic-KGR 模式） |
| 检索 | 向量为主 + 简单图查询 | graph⇄dense 双路 + 规则路由 | + 可学习路由 + 一致性正则 + 反事实重放 |
| 时序 | 单时间戳 | bi-temporal + 边失效 | + 社区层真值更新 + 置信衰减 |
| 适用 | POC、<1 万用户 | 生产对话产品、企业助手 | 多租户平台、强合规域 |
| 团队门槛 | 1-2 人 / 4-6 周 | 4-6 人 / 3-4 月 | 研究型团队 / 6 月+ |

## 5. 实施路线图（四阶段）

**阶段 1（第 1–6 周）：地基。** 搭 L1/L2 双存储与评测 harness（LoCoMo/LongMemEval 私有化子集），dense-only 基线建档；固定种子 schema 上线实例填充（轻量档）。里程碑：基线 Recall@10 与成本数据入库。

**阶段 2（第 7–16 周）：长出图。** 上线 M2 抽取验证 + M3 提升门控（先只允许种子类型内的边提升）+ M4 双时间线。灰度 5% 流量，监控提升通过率、别名合并错误率、引用忠实度。里程碑：隐式查询切片 Recall@10 提升 ≥0.08（对齐论文幅度）。

**阶段 3（第 17–28 周）：让本体动起来。** 开放运行时类型发现（新关系类型经门控入词表）、EDC 式周期规范化合并同义类型、路由器上线（先规则后学习）。里程碑：类型词表收敛（增长率 <5%/月）、P95 <200ms、路由错误率 <10%。

**阶段 4（第 29 周起）：闭环自治。** 反馈双通道全量、反事实补遗、置信衰减与修剪、审计回滚演练。里程碑：跨模态分歧 <50%、人工评估（Fleiss' κ≥0.7）不低于基线。

## 6. 开放问题与未来方向

1. **冷启动理论**：验证覆盖率 10 轮仅 19%，"无反馈条件下的本体先验注入"（Evontree 式自蒸馏、领域元本体迁移）尚无成熟方案；
2. **反馈稀疏下的退化行为**：原论文自认未充分讨论；可能方向是从隐式信号（采纳/跳过/改写）中蒸馏监督；
3. **开放域因果推理**：当前本体以偏好/事实类关系为主，因果与时序叙事结构的关系类型设计仍是空白（LoCoMo 事件图可作起点）；
4. **潜在记忆与符号本体的融合**：MemGen/LatentGraphMem 的潜空间记忆与显式图各有所长（后者长上下文稳定性更好），混合架构是新兴方向；
5. **多智能体共享本体**：Agentic-KGR 的协同演化初步触及，团队级/组织级本体的并发演化协议（类似分布式 schema 迁移）无文献覆盖；
6. **机制层验证**：电路分析表明路由与接地是不同的模型能力，动态本体系统的模型规模分工（小模型路由+大模型接地）值得系统性研究。

## 7. 结论

1. **可行性判定：成立，且有时效性。** 五项证据链（schema 归纳质量、增量图技术、收益复现、反馈闭环、延迟成本）表明动态本体构建已越过从研究到工程的阈值。2026 年的产业信号（451 Research 覆盖 Zep、Mem0 融资 2500 万美元、Letta 平台化）说明这不再是实验室课题。但可行性是**条件性**的：门控、双时间线、验证闭环三件套缺一不可，绕过门控直接让 LLM 自由写图等于主动引入幻觉放大器。

2. **问题定位：动态本体是"隐式召回失败"的对症解，而非普适升级。** 它的价值集中在跨会话、无词汇锚点、需要个性化与时序推理的场景；单轮工具型 Agent 引入它是负收益。

3. **方案要点**：四层架构（事件→情景→符号→本体）+ 六模块（摄取/抽取验证/提升门控/时序冲突/混合路由/反馈闭环），标准档（种子 schema + 运行时类型发现）是多数团队的正确起点；轻量档（Graphiti 模式）可 6 周内出 POC。

4. **最大的未解风险不在技术而在治理**：本体把碎片对话聚合成高密度用户画像，聚合泄露、本体漂移的审计、错误提升的回滚，这些治理能力决定了系统能走多远。先建审计回滚，再放开自动演化——顺序不能反。
