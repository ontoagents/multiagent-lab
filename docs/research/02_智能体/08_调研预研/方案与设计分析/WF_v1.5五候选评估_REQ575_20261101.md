# WF v1.5 五候选评估轮（REQ-575/M389 评估件）

> **定位**：评估件（零代码，沿 REQ-560 先例）——113 号 §5.3 五候选「另行评估立项」的评估履行；判定基线=WF-①~⑧ 八件全数交付后的现状（REQ-562~569 ✅ M369~376+REQ-552 改道件 M377）。判定口径：go（领号排期）/条件 go（触发驱动 🔁）/no-go（关闭并留触发复活条件）/已覆盖（收口）。

## 1. 五候选逐项判定

### 候选① 失败送达+四字段完成卡 —— **条件 go（触发驱动 🔁）**

- 现状核验：REQ-563 Runner 失败策略=retry 1 次+skip_downstream 级联——**已完成节点的产出在 Trace/回放可见，但失败 run 无「成果送达」卡**；REQ-557 过程账本（usage_by_agent/tool 事件 agent 归因）已交付=本候选的衔接面就绪。
- 价值判断：真实——长 DAG 后段失败时前段已完成产出（可能高成本）散落 Trace 不成体系；「诚实边界」叙事的 WF 面载体。
- 判定：**触发驱动**。触发条件=开发者实际遭遇失败 run 后想捞取已完成产出的困扰出现（自用期 E1）。届时领号：失败 run 终态事件附 completed 节点产出清单（四字段卡：产出/verified/notCovered/下步建议）+对话流尾送达行。

### 候选② 节点级提问隔离与兜底 —— **no-go（留复活条件）**

- 现状核验：WF-③ RequireApproval 人审卡点=run 级挂起（approval_pending）；REQ-560 拍板已定「并行 HITL 串行呈现一期」——并行多 HITL 场景被串行呈现消解，节点级隔离的并发价值暂无承载面。
- 判定：**no-go**。复活条件=串行呈现在实际使用中造成可感知阻塞（一个待审节点冻结整图而其他分支本可推进）。届时重估范围=ask_human 粒度细化+pendingQuestions 查询+三次上限降级（113 号原案三件套）。

### 候选③ rerun 输入指纹近似缓存 —— **条件 go（触发驱动 🔁）**

- 现状核验：WF-④ 快照+rerun 语义已交付——**上游 completed 产出保留+failed 及下游重跑**；「completed 保留」已隐式覆盖「输入未变不必重算」的主场景（确定性节点产出不变）。指纹缓存的增量=输出非确定节点（LLM 节点）在输入未变时跳过重生成——价值真实但依赖「节点+输入指纹」哈希基建。
- 判定：**触发驱动**。触发条件=实际 rerun 中「LLM 节点输入未变却被重生成」的成本困扰被感知（长 run 大 token 节点）。届时领号：节点 id+规范化输入 hash 指纹表+「可调常量不进 prompt」「环境已写即失效」两纪律原样保留（113 号 §13）。

### 候选④ 门禁干跑预览 —— **no-go（留复活条件）**

- 现状核验：WF-③ 门禁断言（四类型 EvaluateGate）失败已有**回喂循环兜底**（≤GateMaxFeedback 2 轮重新生成）；REQ-558 产物预览（CSP sandbox）已交付确认卡侧预览面。干跑预览的增量=确认前预执行实测耗时——但门禁失败已有系统性兜底，预执行的副作用面（确定性节点无副作用假设需逐节点审计）成本先行。
- 判定：**no-go**。复活条件=「确认卡确认后门禁必败」的高频困扰出现（回喂 2 轮仍过不了的形态化案例积累）。

### 候选⑤ 阶段图回放条带 —— **已实质覆盖（收口，非独立件）**

- 消费面核对（本轮随办）：113 号原案「DAG 计划器产出阶段标记，确认卡与回放读同一份标记（单源不两画）」——现状=WF-⑥ workflow_mode=dag 接线（计划 JSON 单源）+WF-⑦ 计划确认卡（草稿源即计划 JSON）+WF-⑧ 重跑 UI/可视化（读同一 Runner 状态与一等节点事件 wf.node.*）；**PreviewOf 拓扑预览（parallel 标注）与 Runner 深度分层同口径**（workflow/preview.go 与 runner.go 同源 Kahn 分层）——「单源不两画」已由计划 JSON+一等节点事件两处单源实现。
- 判定：**已实质覆盖，独立件否决收口**。113 号 §5.3 该行标注收口指针。
