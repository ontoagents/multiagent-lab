# 22_多类型智能体支持方案研究（REQ-142）

> 状态：Draft v0.1（2026-09-24，REQ-142 研究交付）
> 作者：董奎 × 自动化执行者
> 需求锚点：01 v0.31 REQ-142（P4 发展方向待办）；结论供开发者评估是否另行立项，**不构成排期承诺**

## 1. 研究背景

当前平台智能体均为**对话型**（Eino ADK ChatModelAgent + ReAct 工具循环）。REQ-142 要求研究其他类型智能体的支持方案，作为发展方向。本章按「任务型 / 工作流编排型 / 自主规划型 / 多 Agent 协作形态」四类给出落点分析与引入路径。

## 2. 四类形态与 Eino/ADK 落点

| 类型 | 特征 | Eino/ADK 落点 | 与平台现状的距离 | 引入成本 |
| --- | --- | --- | --- | --- |
| **任务型**（一次任务，产出物交付） | 触发即跑、无对话轮次、产出文件/报告 | ADK Runner 一次性 Run（已有）；差异仅在**无对话 UI** + 产物归档 | 低——M11 产物管线已就绪 | 小：任务型 Agent 视图 + 触发器（手动/定时） |
| **工作流编排型**（确定性 DAG/顺序） | 固定步骤、分支/并行、少自主决策 | ADK Sequential/Parallel/Loop Agent（项目 workflow_mode 的 P1 兑现） | 中——REQ-33 workflow_mode 已预留（free 生效，其余告警降级） | 中：sequential/parallel 两模式落地 + 前端编排器 |
| **自主规划型**（Plan-and-Execute） | 先生成计划再逐步执行、可重规划 | ADK 无内置 Planner；可自研 PlannerAgent（计划→分派→复核循环）或接 bootstrap 思路 | 大——需要计划数据结构 + 计划/执行分离 + 重规划触发 | 大：建议作为独立里程碑（含计划可视化） |
| **多 Agent 协作形态** | 群聊/辩论/角色扮演等超出现有 agent_as_tool/transfer 的协作拓扑 | ADK 已支持 AgentAsTool/SetSubAgents/确定性转移；群聊需 GroupChatManager 类编排 | 中——M4 已有两种拓扑，缺群聊与共享记忆 | 中：新增 group 拓扑（共享事件时间线已有基础） |

## 3. 推荐引入路径（三步走）

1. **第一步（低悬果实）**：**任务型 Agent**——复用现有装配与产物管线，增加「任务运行」形态（无对话、跑完归档产物）；同时把项目 `workflow_mode` 的 `sequential` 落地（REQ-33 兑现，编排拓扑仅顺序）。
2. **第二步**：**工作流编排**——parallel + 前端步骤编排器；与 REQ-143/144（对话对比扩展）共享窗格/剖面机制。
3. **第三步**：**自主规划型**——Plan-and-Execute Agent（独立里程碑，含计划数据结构与可视化）；多 Agent 群聊拓扑视需求穿插。

## 4. 风险与边界

- **教学价值优先**：每种形态应带来可对照的学习点（任务型=产物管线、编排型=确定性 vs 自主、规划型=Plan/Execute 分离），不为堆形态而做。
- **后端可插拔约束**（§6.16.4）：外部 CLI 后端不支持多 Agent/工作流——新形态初期限 eino-adk 后端。
- **不做**：通用 Agent 市场、跨平台协议（A2A 等）——超出学习平台定位。
