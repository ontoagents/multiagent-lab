## 0. 结论先行——三问直答

**问 1：工作区和项目到底是平级还是包含？**

**包含（垂直分层），且是「可选归属」的部分包含，不是全量包含。** 正式口径（`docs/handbook/03_项目/01_工作区.md:19-28` 分层图）：工作区=领域容器（管「这类工作用什么知识、什么方案、什么助手」：默认库/方案/智能体 + 直挂对话 + 笔记本 + 记忆）；项目=执行容器（管「产物写到哪、Git 怎么管」：目录/Git/文件三件套/团队），经 `project.workspace_id` **可选**归属某个工作区（NULL=未归属合法，迁移 `081_project_workspace.sql:2-5`）；会话归属互斥 `project_id XOR workspace_id`（应用层校验，`backend/internal/store/conversations.go:126-128`）。真实的模型是「部分项目挂靠在部分工作区之下」，而非「所有项目都属于工作区」。

**问 2：分开的目的今天还成立吗？**

**成立，且已被三条业务链消费成事实，不可逆。** 直接目的（免每会话重选两个 chip 的摩擦，106 号 obj-3）、深层目的（场景默认值的语义归属）、Q-23 衍生② 跨会话记忆作用域，今天分别由 `inheritWorkspaceDefaults`（conversations.go:339-354）、`notebook.workspace_id`（080_note.sql）、memory 表 CASCADE（082_memory.sql:6-8）兑现。受损的只有两处**名义面**（默认智能体字段的后端消费缺口、「VS Code 绑定目录」隐喻失真）——那是能力补齐与命名说明问题，不构成「拆开」的证据。**双模块分立正是「界面层分成两个完整模块、机制层维持一体」——与问 2 的结论精确同构。**

**问 3：界面怎么改才能让人看出来？**

**E 路线（拍板）：双模块分立 + 互链表达。**「项目」恢复独立导航（完整项目体验：平铺树/模板入口/项目会话），「工作区」新增独立导航（完整工作区体验：工作区树/总览/直挂对话/名下项目卡）；包含关系不再依赖页签或单树结构，改由三件表达——①跨模块互链（项目行「⌂ 工作区《X》」chip 跳工作区模块、工作区总览名下项目卡跳项目模块）；②呈现对等（继承来源/记忆注入行两模块一致透出，C1/C5）；③正式关系句四点单源（§4.4）。原 D 路线（单树嵌套）作废，改判理由见 §3.2-D→E。

### 3.2 取舍理由

**B/C 不适配论证承 120 号原样**：B 逆着数据事实走（workspace_id 已是四表实列，退役=迁移+回退）且重走红队死路（obj-3 语义错位 + 记忆作用域连根拔）；C 砍继承链则原始摩擦回归、项目自建默认值面则重复建设——C 唯一的正确内核（「用户直觉上项目更像顶层」）恰是 E 要在界面上安置的，而不是顺着直觉重排数据模型。A 可用但会重蹈覆辙（页签并列的第一混淆信号仍在，十二件补丁已实证无效）。

**D→E 改判理由（本档新增）**：D 单树把「项目」完全折叠进工作区子树——项目从一级导航对象降为二级子对象，重度项目用户的浏览面（平铺全量树/协作模板入口/未归属项目一网打尽）在单树内只能拆解承载（120 号 §4.1.2 已暴露此缺口：跨工作区全量项目平铺视图「不设」，退 P2 观察）。开发者拍板原话「**恢复增加工作区前的项目**」直指这一点：项目执行容器需要**独立完整**的浏览与操作面，工作区视角（场景配置/直挂对话/名下项目总览）与项目视角（平铺树/模板/Git/文件）是两个完整的体验，不该互为宿主。E 让两容器各归其位——与 Q-24 批「双入口共存」拍板（智能体页保留）同向；「页签并列暗示平级」的旧风险在 E 下的对策不再是结构吞并，而是互链 chip + 呈现对等 + 关系句单源三件表达（C1~C5/§4.4）+ 各模块面包屑/空态/文案的分立语义。

**E 的代价与风险（如实标注）**：导航六项→七项；「双入口平级暗示」回潮风险=三件表达对冲；深链重排面（§5.2）；REQ-597 已交付口径反转（§5.3，01 §3.28 反转注）；前端呈现层为主+两件必选后端小件，零迁移。冒烟覆盖走 `docs/20` 工作区/项目节。

## ④ E 路线（双模块分立）的完整交互设计

### 4.0 设计原则（五条）

1. **双模块各司其职**：工作区模块=领域容器完整体验（场景配置/直挂对话/笔记本/记忆/名下项目总览）；项目模块=执行容器完整体验（平铺树/项目会话/文件 Git/协作模板）。
2. **包含关系靠表达不靠结构**：互链（chip/项目卡）+呈现对等（继承/记忆行）+关系句单源——「项目可归属工作区」在两模块都有可见出口。
3. **作用面=呈现面**：工作区对项目会话起作用的每个点（继承/记忆/笔记本）都有对应呈现；文案断言与真实写入一致（创建流归属不得谎报，B2）。
4. **归属可选如实**：未归属是合法态，显式呈现不强迫（未归属项目在项目模块平铺树原样，不设惩罚性分区）。
5. **机制零改动**：`workspace_id` 归属/默认值转发/记忆作用域/继承链照旧——分立只发生在导航与呈现层。

### 4.1 IA 结构（目标态）

**导航层：六模块 → 七模块。**「项目」恢复独立导航项（label=项目）+「工作区」新增独立导航项（key=workspaces）。REQ-597 的「导航恒落工作区」退役；GlobalNav label「工作区」回改「项目」并新增「工作区」项。

**项目模块（路由 `/projects` 原样）**：

- 模块体=**加工作区前的项目体验**（REQ-597 之前形态归位）：项目平铺树（Sidebar mode='project'）+项目会话（ChatWindow + ProjectSidePanel）+协作模板入口原位（「＋新建对话」Dropdown dev/hyb 与模板弹窗宿主留 ProjectsPage 原位——不迁移）；ProjectsBody 回模块主位。
- REQ-597 页签结构退役：module-tabs 区块与 ProjTab state 删除，WorkspacePage 不再寄居项目模块。
- 已归属项目行加「⌂ 工作区《X》」chip 互链（REQ-577 徽标资产沿用）——点击跳工作区模块并选中该工作区。
- 左栏标题恢复「项目」；空态恢复项目引导（步骤补「可归属工作区获得默认知识背景」提示句）。

**工作区模块（路由 `/workspaces` 新增，key=workspaces）**：

- 模块体=工作区专页（现 WorkspacePage 为主体演进）：**工作区树**（工作区→直挂对话；空壳节点=名称+计数徽标，chevron 诚实化）+**工作区总览**（头部配置 / 笔记本绑定 / 记忆 / **名下项目卡列**——项目卡点击跳项目模块打开该项目）。
- WorkspaceSidePanel 随迁（config/projects/记忆三视图原样）。
- 左栏标题「工作区」。
- 「未归属项目」不在工作区模块设分组——未归属项目的浏览宿主=项目模块平铺树；归属动作入口=项目侧板「默认值转发源」区（C3）。

**包含关系表达（三件）**：

| 方向 | 载体 | 动作 |
| --- | --- | --- |
| 项目 → 工作区 | 项目树行「⌂ 工作区《X》」chip + 项目侧板「默认值转发源」chip（C3） | 点击跳工作区模块选中该工作区（`eino.focus.workspace` 重排后深链） |
| 工作区 → 项目 | 总览「名下项目」卡列（C4） | 点击跳项目模块打开该项目 |
| 会话级 | 继承来源行对等（C1）+ 记忆注入行（C5）+ 智能体页归属 chip（C2） | chip 跳工作区模块 |

**两块侧板不合并**（承 120 号）：WorkspaceSidePanel 与 ProjectSidePanel 保持各自实体——领域容器与执行容器的配置面分开正是分层语义。

**面包屑各模块内独立**：项目模块「项目 › 项目 P1 › 会话名」；工作区模块「工作区 › 工作区 A › 直挂会话」。跨模块层级不出现在同一面包屑（分立语义）。
