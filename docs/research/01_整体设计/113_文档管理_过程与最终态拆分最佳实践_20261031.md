## 1. 背景与决策链

### 1.1 现状问题（v2.2 盘点证据沿用，计数 2026-11-01 本轮实跑复核）

platform-knowledge 实测 **190 档**（含本档；实跑 `find platform-knowledge -name "*.md" | wc -l` = 190）。结构性问题四条（本轮复核无变化）：

1. **过程档淹没人读面**：调研预研+方案评审类 110/189（58%），其中 `08_调研预研/` 路径下 88 档（实跑复核 = 88）；前 12 大档（531~1062 行）全部是调研/评审/方案档，而子模块实现状态档仅 37~110 行——体量与人读价值倒挂。
2. **同档混杂过程与最终态**：53 号 §二.5「体检结论归档」、90/110 号「现状架构+演进路线+评审过程同档」、子模块状态档内含迭代表/交付详录——读者需跳过大量历史节才能拿到现状。
3. **自家规范失守**：64 档文件名带日期后缀（实跑复核 = 64，含本档 `_20261031`）、21 档无 frontmatter、34/66 号同文双档、编号跨目录重号（31×7/34×5/90×3/91×2）裸「XX 号」引用不可定位。
4. **页面与检索同源绑定**：页面=构建期目录扫描全量内联（`KB_RAW` glob，3.7MB 进 bundle）、助手 RAG=全目录 walk（`SyncPlatformKB`）——「目录=页面树=检索面」三位一体，人读与机器检索无法分开治理。

### 1.2 决策链：三代方案演进

**第一代 v1.0「展示层过滤」（2026-10-31，已退役）**：`layer: final|process` frontmatter 标注 + 页面构建期按 layer 过滤 + doccheck/docsize 增项机检兜底。被开发者三条修正指令整体推翻——①不追求绝对一致、不需要可机检（轻量纪律而非重门禁）；②检索索引面应随最终态文档走；③物理隔离选工作量小的迁移方向。

**第二代 v2.2「二分法」（2026-10-31~11-01，两轮独立评审后定稿，被本轮取代）**：仓库根级新家 `handbook/` 承接 24 档最终态文档；过程档 166 档原地留守（pk 改过程档专区）；RAG walk 与页面 glob 双切新家；doc_read 白名单加 handbook/ 分支保留过程档读链；轻量同步立**新增纪律 11**；断链面全量实测（宽匹配 211 条、真断链 113 处、不断 94 处）。被取代原因见 §1.3 拍板——落点从「根级新家」收敛为「docs 之下」，learning 从「留守+第二 glob 保上页」升级为独立区并进 RAG，纪律从「新增条文」收敛为「改写既有条文」。

**第三代 v3.0「四区收敛」（本版，2026-11-01 拍板生效）**：docs/ 一根四区（§2），`platform-knowledge/` 目录退役归零。v1.0 的「拆分方向成立」判断贯穿三代不变；v2.2 的代码落点实证（file:line）、断链判链方法、批次验收框架全部沿用，仅路径按四区更新。

### 1.3 本轮开发者拍板（2026-11-01）与三轮独立评审必采项清单

三轮独立评审意见收敛后，开发者拍板必采项六条（原文口径）：

1. **B 收敛**：`docs/` 根级编号档＝需求与进度区，**原地不动**（其中 docs/04 将在批次 1.5 迁出）——三区不另立仓库根级目录，全部落 docs/ 之下。
2. **A 命名**：`docs/handbook/`＝现状手册区（platform-knowledge 的 24 档最终态文档迁入，子目录 01_整体设计~07_设置 同构）；`docs/research/`＝过程调研区（platform-knowledge 其余全部整体迁入，子目录结构原样，退出页面与向量检索；doc_read 精读白名单因 docs/ 前缀天然覆盖）；`docs/learning/`＝学习资产区（platform-knowledge/09_知识体系 整目录迁入，35 档）。
3. **learning 独立并进 RAG**：页面「学习资产」组 + 并入 RAG 检索面（v2.2 开放问题 6「09 是否保留向量检索命中」就此关闭为保留——双根 walk 语义比 v2.2 预估简单，因两根同属 docs/）。
4. **doccheck 结构项口径收窄**：不加内容一致性检查项（现状档与代码的语义一致性不可靠机判）；doccheck 维持既有结构断言（头部版本/迭代表一致性/19 号机读格式/AGENTS 窗口）不扩。
5. **pre-commit 非阻塞提示行**：hooks/pre-commit 加一条提示（提醒 handbook 现状档是否需同轮更新），**不阻断提交**——沿 docsize 不做硬门禁的防常红先例。
6. **同步纪律收敛进既有条文**：AGENTS 纪律 7 改写为知识同步（对象 docs/handbook 现状档，触发=语义级变更 ∪ 行为级代码改动，吸收原 AGENTS「模块生效功能总账补则」句）；纪律 8 增补「02 §12 里程碑行：批次/跨模块里程碑才立行，单件交付默认不立」（条文要点见 §4）。

另两条拍板口径贯穿全文：**24 档清单以本档 §5.1 为权威**；**「平台知识」保留为页面功能名**，用户可见串（RAG 库名、工具描述）去目录路径化、改写内容语义（§3.2/§3.5）。

### 1.4 业界对照（v2.2 结论沿用）

「当前态文档 vs 过程账本」分离是业界共识（ADR 记录为什么变、Arc42/C4 描述现在是什么样）——四区的 handbook（当前态）与 research+docs 迭代表（过程账本）分层同构；PEP/KEP/NEP 的「文档到位才允许终态」门禁先例**明确不采**（拍板=轻量纪律）；漂移解法取活档型（Google design docs 先例——持续更新、公开承认漂移、以纪律+拾补轮缓解）；Diátaxis 四分法=handbook 是 reference 象限（信息导向、镜像产品结构）、research 是 explanation（why），分开写分开放；RAG 优先吃 reference 沿 llms.txt「内容单源、双出口」取舍，learning 并入检索面是「教学资产也值得检索」的引申。
