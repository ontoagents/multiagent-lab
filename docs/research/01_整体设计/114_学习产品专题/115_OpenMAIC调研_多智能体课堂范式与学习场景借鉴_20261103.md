## 2. 产品设计精髓

- **IA 极简**：全产品 6 路由（首页=输入框+课程库/生成预览/课堂/Pro 工作台/兼容桥/内部 eval 页）；`ClassroomSurface` 唯一课堂实现，Pro 工作台第三栏放真课堂（variant="pane"）非预览非 iframe。
- **生成是服务端一等公民**：`POST /api/generation-runs` 服务端跑生成，关页面不中断；`/generation-preview` 只是 run 事件流的视图。
- **场景全景**：幻灯片（TTS 旁白+聚光灯/激光笔）/测验（实时判分）/HTML 互动模拟（沙箱 iframe，AI 经 `SET_WIDGET_STATE/HIGHLIGHT_ELEMENT/ANNOTATE_ELEMENT/REVEAL_ELEMENT` 四消息主动操作界面）/深度交互五形态（3D/仿真/游戏/思维导图/编程，同 Interactive 通道）/PBL v2/职教实操（实验性：**任务适配性前置判断——纯概念主题拒绝生成实操组件**，诚实边界写进官方文档「步骤状态不是平台持久化考核记录，也不是物理仿真」）。
- **课堂交互**（学习者可随时插话/被点名/讨论卡三种参与机制）：6 内置智能体（老师/助教/显眼包/好奇宝宝/笔记员/思考者，各带 persona/priority/音色）；cue_user 点名弹 2-4 个建议回复（≤60 字）；讨论卡倒计时自动跳过；圆桌=串行轮次制（所有发言经导演派发，天然不抢话）；白板 SVG 画布脚本绘图与 live 工具绘图共用动作原语。
- **自托管边界**：无云上独占功能，全部能力开源自托管可用；hosting.mdx 面向「为他人运营/嵌入产品」的宿主（owner 身份方法链/匿名工作认领/按席位计费扩展钩子）。

## 3. 实现原理精髓

### 3.1 双运行时架构（最关键架构事实）

| | 持久化 Agent Runtime（建课 agent，`lib/server/agent-runtime/`） | 课堂 Pi 导演编排（`lib/chat/pi/`） |
| --- | --- | --- |
| 状态归属 | **PostgreSQL 权威**（事件日志 seq 单调+转录 entry tree），客户端只是读者 | **服务端完全无状态**，历史/课程快照/白板账本全由客户端每请求上传 |
| 循环形态 | 标准 durable tool-call 循环 | 一次 HTTP 请求=一个完整导演循环 |
| 可靠性 | 租约/心跳（lease TTL 10s/heartbeat 2s）/接管 fencing/崩溃恢复（转录即检查点，恢复语义集中 `planResume()`：剥尾部不完整帧/ask_user 终态不自答/悬空 toolCall 补合成回执） | 无（失败即中断，重发即新一轮） |
| 事件流 | SSE `Last-Event-ID`+`after=seq` 重放+`caught_up` 帧+LISTEN/NOTIFY 唤醒+5s 兜底轮询（**有意的有损唤醒**，降延迟不保正确） | 不重连（失败标记 interrupted） |

### 3.2 生成管线=可断点续跑的分布式作业系统

`preparing→outlining→（确认栅栏 wait/countdown 2.5s/auto）→generating→completed` 状态机，PG 行存储+每步 checkpoint，崩溃后新 worker 从未完成步骤继续（`find(step => !completed.has(step.id))`）；三段重试（指数退避+jitter→路由级分类重试→fallback 模型换一轮）+每步 deadline（outline/scene 300s/actions 60s/TTS 30s）；**命令幂等 id 按意图派生**（`runId:confirm:revision`）防重复点击；场景并行生成有界并发（默认 4）。

### 3.3 导演循环（多智能体编排核心）

导演只有 4 个工具且全是**舞台指令**（不产内容）：`read_scene`（读场景证据，存请求级 Map 在下次 call_agent 时自动附加取一次即清空——「证据随委派带给子 agent」）/`call_agent`（派发言权，executionMode=sequential 串行）/`cue_user`（交还话筒）/`close_session`（收尾，前置条件=本回合已有可见发言）。子 agent 产内容且输出**内联动作**。防抢话三重保险：prompt 路由规则（老师先答/同角色不连排/学生不做第一个实质回答）+「已发言者及内容预览」注入+**长度硬帽**（老师≤70 字/学生≤40 字——「学生回答和老师一样长就是错的」）。

### 3.4 动作引擎与播放状态机

21 种动作动词（speech/spotlight/laser/12 种白板 wb_*/play_video/discussion/4 种 widget_*），在线流式与离线回放**共用同一个 ActionEngine**；`lib/choreography/timing.ts` 时间语义单一事实源（头注释：播放与视频导出必须共用同一组数字否则导出漂移）。播放=确定性脚本单调游标推进；live 即兴=脚本预埋的 discussion 钩子，cue_user/soft close 后游标恢复续播——**「脚本负责讲，导演负责答，靠游标保存/恢复缝合」**。

### 3.5 模型配置：slots/providers 能力树

slot=「产品里用到 AI 的一处地方」构成能力树（`llm→course.research/.outline/.agents/.content(.slide/.quiz/.interactive/.pbl)/.actions/classroom/agent`+平行的 tts/asr/image/video/webSearch/document 根），解析=从调用槽位逐级向上取第一个分配；`lock` 固定子树/`null` 截断/`fallback` 仅语言模型；配置非法**启动即拒**报精确字段路径。slot 划分判据一句话：「用户是否会为这个用途单独换模型」。

### 3.6 学习科学机制（自学视角最可用部分）

- **PBL proficiency 掌握度引擎**（`pbl/operations/kernel/proficiency.ts`，894 行纯函数，显式声明「不是 LLM prompt」）：score∈[-1,+1] EWMA(α=0.2)+tier 迟滞（进 advanced>0.50/离开<0.20）+重分层三重门（confidence≥0.4/动态信号≥3 条/冷却 5 回合）+静态信号加权×收缩因子（bio 正则/大纲难度梯度/测验正确率快照）+动态信号（每回合 error/struggle/concept_unlocked/提交分）；驱动 Instructor「披露阶梯」（beginner 默认给 how、1 次 real stuck 即放字面答案；advanced 默认只给 why）；**tier 不对学习者展示**（防标签效应）。
- **PBL v2 建模**：milestone→microtask 两级+scenario 角色扮演；四 agent 分工 Planner（单遍规划产完整 projectV2）/Instructor（教学回合+record_observation/adjust_difficulty 工具）/Simulator（角色扮演）/Evaluator（三模式流式：任务反馈/里程碑反思卡/终评 stars）；event-sourcing runtime；评估有证据门（milestone 收尾须 integrative reverse-question 整合性反向提问）。
- **ZPD skill 立场**：教学法 skill（拒绝量化「最近发展区分数」——「单次活动只能提供表现线索」）；支架分级表（未注意条件→方向性问题/步骤过多→步骤卡/缺知识→简短补教/受挫→缩小目标）。
- **quiz 机制**：确定性 id 会话+`:retry:N` 子会话 roll-over（防重复计数）；draft→submitted→reviewed 单调 CAS（防回写）；选择本地精确判分/主观 LLM 严格 JSON 判分；测验结果经 pre-play 快照反哺掌握度画像。

### 3.7 eval 体系（四种范式各有归宿）

语言推断=50 用例宽松 LLM-judge（temperature 0）全过门槛；PBL 规划=A/B 双变体+**17 条红线一票否决**（如「给开放型工作强造假交付物是最红的红线」「答案泄漏」）；白板几何=**纯确定性代码判定+故意故障注入**（注入坏 SVG path，模型必须读懂真实报错重试）；白板布局=VLM 五维量规。共性纪律：eval 必须显式 env 声明测什么模型、几何类能用代码绝不用 judge、报告含完整 prompt 与 tool trace。

### 3.8 Prompt 工程手法八条（最值得整包收编）

1. **最高频违规前置三次置顶**（Output Format 第一节+Important Reminders+user 消息结尾——「返回裸数组而非对象」是实测最高频违约）
2. **量化约束代替形容词**（文本高度查找表/宽度公式+「利用率≤75%」/字号层级表）
3. **Pre-Output Checklist P0/P1 分级**带 `[tag]`，踩坑经验直接写进 prompt 配 Wrong/Correct 对照
4. **正反例教学法**（泄题规则 4 组 ❌/✅ 字面对照）
5. **语言控制显式产物**（`languageDirective` 为大纲第一个输出键——流式头部 8KB 正则 O(1) 提取，配有序决策规则）
6. **JSON 容错而非强约束**（解析链：精确 parse→剥 `</think>`→markdown 块提取→括号配平→jsonrepair 库；下游代码兜底：未知 action 丢弃/选项归一化）
7. **TTS 可读性专用约束**（「从负π到正π」而非「负派」——语音+字幕双消费者）
8. **「prompt 永不承诺一张不会附上的图」**（vision 图片预算切片+15s 聚合预算+连续 3 次失败熔断，失败图片从 prompt 文本与附件同时剔除，降级纯文本而非失败）

## 4. 学习场景借鉴结论（开发者 2026-11-03 定位补充后的重估）

### 4.1 三方合成闭环

本项目学习场景（自学/深入研究，**无老师角色**）下，三份调研恰好各占一环：

```
外部材料（论文/教材/文档/音视频/主题）
   ↓ ① 学习过程【OpenMAIC 生成管线 × DeepTutor 交互组织（91 号）】
学习大纲 → 逐节精讲/互动演示 → 自测 → 追问探究 → 课题实践
   ↓ ② 沉淀【本项目独有——OpenMAIC「生成即消费」学完即散（其 RAG 仅内存词法索引）、
      DeepTutor 有知识中心但无本体结构（91 号 §3）】
笔记本(REQ-495) / 本体概念与关系(REQ-573 停车场) / KG / KB 索引
   ↓ ③ 消费【本项目独有】
RAG/GraphRAG 检索 · SparQL · 定向出题 · 掌握度子图 · 审计
   ↓ 回到 ①：薄弱概念定向出题 → 再学习（REQ-572 闭环）
```

借鉴策略：**拿 OpenMAIC 的学习过程引擎，接到本项目资产底座上**——老师讲课外壳全部弃掉，其内部学习科学机制与生成管线几乎原样可用。
