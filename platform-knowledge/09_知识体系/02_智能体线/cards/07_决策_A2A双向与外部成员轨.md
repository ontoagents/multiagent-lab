**背景**：多智能体生态的互操作需要开放协议。A2A（Agent-to-Agent）让平台智能体**被外部调用**（server 侧）与**调用外部智能体**（client 侧，外部成员入项目）成为同一件事的两面。

**server 侧定案**（REQ-442~444）：agent card 发现+message/send·stream+任务落库（tasks 状态机）+取消收口；平台特色是把**审批闸门**带进协议——外部调用触发审批时返回协议错误码并转 input-required 终态，恢复后继续（REQ-443 交互闭环）。错误响应脱敏（REQ-444），不泄内部实现。

**client 侧定案**（REQ-446/463）：外部 A2A 成员经 adk.Agent 适配桥进协作面，与 CLI 成员同口径（specs 单源防漂移）；AgentScope Python 包装器（39 号）用「跨语言回环单测」验证了**平台侧零代码主张**——外部任意语言的 agent 运行时只要包一层 A2A server 即插即用，平台不改一行。

**取舍与后果**：tasks 落库换取任务可审计可恢复（内存态单点是评审点名风险）；诚实边界=外部成员无审批面（其内部治理平台不可见）、上下文隔离（只传任务不传历史）。学习要点：双向协议的价值不在「能连通」，在把治理语义（审批/取消/挂起）翻译成协议原语。
