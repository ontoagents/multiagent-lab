# 本体构建 · 当前实现状态

> 本体模块五栏之一。**架构权威**：[04_本体_方案设计](../../docs/04_本体_方案设计.md) §2；实现视角：[90_本体_底层实现原理](90_本体_底层实现原理.md) §2/§3；调研资料见 [08_调研预研/](08_调研预研/)。

## 定位与能力现状

布局：左路径导航（状态徽标常显）+ 右工作区（REQ-183 两栏）。六路径殊途同归——草稿走统一校验循环，入库收敛到同一段资产能力。

| 路径 | 状态 | 实现要点 |
| --- | --- | --- |
| 1 自定义构建 | ✅ | 表单向导 S1~S4（五来源：导入/AI 创建/内置示例/空白/由知识库跳转）+ Spec 编辑（CodeMirror JSON）与图形编辑（React Flow 概念/实例双类节点）双形态，校验管线只有一条 |
| 2 OntoChat 流程 | ✅ | cq→domain→draft/refine→done 状态机；服务端 SQLite 持久化（重启会话还原+中断恢复标识）；**生成轮异步化（REQ-271/M80）**：202+job 轮询（job 同库 SQLite 持久化+悬挂自愈+同会话互斥+进度/取消/错误留痕+重试）+超时 300s 可配+「生成草稿」按钮化+few-shot 种子范例注入+提示词集中 prompts.go（GET /api/ontochat/prompts 只读透出+前端只读抽屉）；**CQ 抽取与净化（REQ-272/M81）**：抽取 CQ 按钮→异步 job→人工确认卡（勾选/编辑/删行/手动添加）→写入会话 CQs→生成草稿回写 spec.CQ（REQ-248 闭合） |
| 3 由知识库构建 | ✅ | 三策略（KB chunk→LLM / GraphRAG KG 直转 / 混合）+ CSV/JSON 结构化骨架（build-from-structured，列角色推断） |
| 4 Open Ontologies 回流 | ✅ | oo 导出 TTL → merge/preview 审查（有损导入报告）→ apply；双轨数据不互通（REQ-78 冻结） |
| 5 OntoExtend | ✅ | ODP 精选 12 模式内嵌 + LOV 词表（24h 缓存、不可达优雅降级）→ merge/apply |
| 6 ~~semantica~~ | ✕ | D-O15 退役（自研轻量等价） |

**导入**：spec 无损 / CSV 灌装（preview→apply+映射配置）/ GraphML / OWL RDF-XML 与 Turtle（python3+rdflib sidecar，`SIDECAR_SCRIPT` env）；导入即保留原始形态+有损报告。**边界**：SKOS/数据属性/JSON-LD 不识别（REQ-235 触发驱动）。

**校验与质量管线**：`Spec.Validate` 单一结构校验（全入口收敛）→ qualitygate 11 项三维评分（strict 默认宽松）→ LLM 生成双校验源修复环 ≤3 轮铁律。**进化闭环**（REQ-207/M43 ✅）：候选版本 vN-cK 状态机+配对门控（base vs patched 双信号，质量回退>5 或结构破坏不过）+采纳升正式版本永不覆盖+资产详情「进化」页签。

## 代码落点

- 前端：`BuildPage.tsx` + `OntoChatFlow` / `BuildFromKBFlow` / `OntoExtendFlow` / `ImportMergeWizard`
- 后端：`ontology-service/internal/{importer,merge,llmcreate,ontochat,ontoextend,vocabsearch,qualitygate}` + `backend/internal/ontobuild`；LLM 能力归主平台（`/api/ontology-llm/generate`，**ai-draft-async 202+job 轮询**已异步化）
- 评测基准：`internal/evaldata`（build tag eval：种子 5+真实 3，结构+qualitygate 双信号）
