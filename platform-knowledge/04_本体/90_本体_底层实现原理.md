# 本体底层实现原理（代码地图）

> **定位**：本体模块五栏界面（学习中心 / 构建 / 资产 / 运行 / 消费与审计）背后的实现视角汇总。设计口径与架构决策以 [docs/04_本体_方案设计.md](../../docs/04_本体_方案设计.md) 为权威事实源（v1.0 现状化）；模块导读页 [00_本体模块](../00_本体模块.md) 承载产品语义与教学价值；本文回答「这些能力在哪个服务、哪个包、用什么机制实现」。
> **三平面总览**：构建平面 `ontology-service`（:8091）管 spec 资产全生命周期；运行平面 `runtime-manager`（:8090）管引擎与运行方案；消费平面散布在主后端 `backend`（:8080）——KG、审计、伴生本体、对 Agent 的工具装配。前端 `web/src/pages/ontology/` 五栏一一对应。

反代注册单一入口：`backend/internal/api/server.go`（BuildProxy → :8091，RuntimeProxy → :8090，ooProxy → :8092）。两条**精确路由**压过反代前缀：`DELETE /api/ontologies/{id}`（删除守卫：伴生 409→running 方案 409→stopped 警示放行，REQ-233③）与 `GET /api/ontologies/{id}/references`（三源聚合）。**新增构建平面端点前缀必须同步注册反代**——OntoChat 404（REQ-103）与 PipelinePane 404（M-O17）两次回归同一根因。

## 1. 数据模型：spec_json 多形态资产（构建平面）

- **存储**：`ontology-service/internal/repo`——SQLite（modernc.org 纯 Go 驱动，零 CGO，D-O15 单机可部署）。迁移 001~005（repo/version/ontochat/pipeline/quality_strict）+ 039（REQ-207 候选版本表 evolution_candidate vN-cK 状态机，✅ M43）。
- **主形态 spec_json**：概念/关系/实例三要素 + **数据属性声明层 `data_properties`（REQ-268/M77，D-O22 实用化升级）**（`pkg/ontology/spec`），人类可读、可 diff、可校验、可画图。**模型边界**：~~无数据属性~~（M77 已落：DataProperty{name,label,definition,domain,range}，声明层挂类型、实例 attributes 键同名关联）/公理仍无——公理承载=REQ-269（触发驱动），重语义资产走 oo 轨（REQ-235⑤ 分工指引随 D-O22 批次推进复审）。
- **版本**：保存即新版本，历史快照可回取（`GET /{id}/versions/{v}/spec`）；diff 三集合统计+引用影响（REQ-95）；fork 溯源。版本语义=线性快照堆（命名版本随 REQ-207 候选状态机）。
- **产物（artifact）**：TTL 导出、质量报告 `quality-report`（可摘除）、LLM 草稿、ingest_mapping_json 等，零新表。
- **导入分层**（`internal/importer`）：spec 无损 / CSV 灌装 / GraphML / OWL-RDF-XML 与 Turtle 与 JSON-LD（sidecar 子进程）——「导入即保留原始形态」是硬要求；oo 双轨 TTL 回流走 merge/preview→apply 审查底座（REQ-157）。SKOS/JSON-LD/数据属性声明已识别（REQ-235/M62 + REQ-268/M77：owl:DatatypeProperty 声明捕获入 data_properties、实例断言谓词命中声明 URI 时键归一声明名；TTL 导出以 `<attr:名> owl:DatatypeProperty` 回写、attr: 命名空间与实例属性断言同 IRI）。**边界**：公理/限制/推理语义仍丢弃计 lossy（REQ-269 触发驱动）。
- **导出与转换**：spec→Turtle 经系统级 python3+rdflib sidecar（`SIDECAR_SCRIPT`/`SIDECAR_PYTHON` env，无 venv）；spec→VOWL JSON 平台原生导出（`importer/vowljson.go`，WebVOWL 对照供数）。

## 2. 校验与质量管线（构建平面）

- **结构校验只有一条**：`Spec.Validate`——表单、画布、LLM 草稿、导入全部收敛到同一段；图形编辑器数据经适配器转回 spec_json。
- **质量门禁**（`internal/qualitygate`，REQ-171）：15 检查项数据驱动（11 基础+REQ-255 reasoning_owlrl 推理档+REQ-268 dangling_dataprop_domain〔error〕/undeclared_attribute_key〔info，仅声明过数据属性才检查〕）+三维评分（完备 .35+一致 .45+可维护 .20，扣分制）；`POST /api/ontology/quality/check` 双模式（ontology_id 落 artifact / spec 内联不落库）+ **save=false 纯快评**；strict 开关默认宽松。**消费点五处**：保存/合并阻断（strict 开启时）、LLM 修复环（≤3 轮铁律）、**方案装载快评**（REQ-234①，runtime-manager FetchQuality 异步写 loaded_quality，低分警示不阻断）、资产质量卡页签、**backend ontobuild 生成草稿统一快评**（REQ-267/M76，QualitySnapshot inline+save=false 同一把尺）。
- **LLM 生成修复环**（`internal/llmcreate`）：模型能力归主平台（`/api/ontology-llm/generate` 代理；**ai-draft-async 202+job 轮询异步形态已交付** REQ-207/M43，前端接线 REQ-267/M76）→ 双校验源回喂 → 未过转人工。输出契约含可选 `data_properties` 段（REQ-268/M77，llmcreate JSON Schema 与 ontobuild 提取提示词均已扩）。本体域 eval 基准 `internal/evaldata`（build tag eval：种子 5+真实 3，结构断言+qualitygate 双信号）。

## 3. 六条构建路径的实现落点（构建平面）

| # | 路径 | 实现包/端点 | 状态 |
| --- | --- | --- | --- |
| 1 | 自定义构建 | 表单向导（S1~S4）+ Spec/图形双形态编辑 | ✅ 教学基准 |
| 2 | OntoChat | `internal/ontochat`——cq→domain→draft/refine→done，服务端 SQLite 持久化（重启会话还原）| ✅ |
| 3 | 由知识库构建 | KB 三策略 + `backend/internal/ontobuild`（CSV/JSON 结构化骨架）| ✅ |
| 4 | Open Ontologies 回流 | oo TTL → merge/preview 审查 → apply | ✅ |
| 5 | OntoExtend | ODP 12 模式内嵌 + LOV 词表（24h 缓存）→ merge/apply | ✅ |
| 6 | ~~semantica~~ | 已退役（D-O15），自研轻量等价实现 | ✕ |

所有路径殊途同归：草稿走统一校验循环，入库后收敛到同一段资产能力（校验→可视化→版本→运行→消费）。

## 4. 运行平面（runtime-manager :8090）

- **构建/运行解耦（D-O1）**：仓库是唯一事实源；方案是「部署视图」——保存新版本后**显式重载**生效（教学点）；drift 由 loaded_versions+lifecycle plan 检测（REQ-155）。
- **生命周期**：Start（拉 TTL→**端口 bind 探测** REQ-236③→执行方式分发→健康检查≤20×500ms→running+**异步质量快评** REQ-234①）/Stop/Reload。**启动对账 Reconcile**（REQ-236①，`internal/manager/reconcile.go`）：重启后 DB running 逐一探测——docker 容器领养（`DockerRunning` 接线+`DockerStop`）/native HealthCheck 领养（重建句柄，Stop=kill pid）/失活收敛 stopped——治僵尸 running 与孤儿引擎双向漂移。
- **执行方式（runtime_config 系统级）**：**默认 docker**（D-O20 v0.73；迁移 006 翻转存量 k8s 默认行），**未安装 docker 启动期降级进程内 native**（配置不写回；`GET /api/runtime-config` 增 effective_method）；k8s 接口预留。oxigraph：native（二进制候选序+一键安装 REQ-146 pin v0.5.11）/docker（容器 rt-{id}，**端口映射绑 127.0.0.1** REQ-236⑤）；fuseki：native+推理开关（docker 化未做）。与 Agent 沙箱（REQ-122 族）两套独立机制。
- **方案管理**（`internal/manager`）：CRUD/启停/健康探测/日志 tail 200/翻译透视 trace。迁移 001~007（004 历史缺号）。
- **只读边界双白名单**：facade `sparql_query` 词法校验 + **工作台代理端点服务端同口径兜底**（REQ-236⑥，`facade.ValidateReadonlySelect` 导出面）——绕过前端直打代理同样被拒。

## 5. 对 Agent 的契约：MCP facade 六工具（Q-14 / D-O17 / REQ-151 / REQ-215）

`runtime-manager/internal/facade`——tools/list 固定返回 6 个只读 `onto_*` 工具：`get_concept` / `get_instance` / `list_instances` / `neighbors` + `list_concepts`（REQ-215 概念发现按需拉取）+ `sparql_query`（受控开放查询面）。tools/call 按 ontology_id 路由（**RunningByOntology 最早创建确定序** REQ-236②）→ 翻译为 SPARQL 引擎执行——Agent 侧无感运行时差异。guide 紧凑口径（身份+规模+用法，不枚举概念清单）；「受控固定工具 vs 任意查询通道」的取舍本身是教学点。翻译透视：SPARQL/耗时/结果数落 trace_log（REQ-94，默认开）。

## 6. 消费与审计（主后端自研）

- **自研轻量 KG**（D-O15）：`backend/internal/store/kg.go` SQLite 三表（kg_entity/kg_relationship/kg_claim，claim 带 chunk_id 溯源）+ KB-6 两步抽取（本体约束词表 `kg_ontology_id`→FetchSpecVocab 只读投影，运行期单向本体→KB I3）+ 三步检索（向量→一跳→claims，空降级 degraded）。知识库侧 GraphRAG 共用。
- **审计**：onto_decision（KG 抽取留痕/实体消歧/手工补录三写入点）+ 溯源链 + PROV-O Turtle 导出（Go 原生模板）。本体资产治理四事件（subject_kind=ontology）为 REQ-224 载荷搭车件待轮。
- **观测台定位**（D-O19）：第五栏 KG 检索双源徽标（TTL/文本永不混排）；KG 图谱页签=KB 抽取 KG 只读观测，**本体 TTL 装载引擎后的运行态图谱在资产可视化→运行态实渲**（REQ-234②③ 指路闭环）；治理/重建入口收敛知识库侧（「展示位≠管理入口」）。
- **伴生本体**（01 侧域）：伴生子图 `ont-{id}` 存于**宿主方案引擎**（REQ-216 引擎归一，:9199 独立实例已退役）+ 快照回灌（方案重建无损）；本体删除伴生拦截 409；facade `sparql_query` graph=companion 分支。

## 8. 横切约束

1. **零 Python venv（D-O15）**：sidecar 走系统级 python3+rdflib（`SIDECAR_PYTHON` 可指路）；一切依赖纯 Go 或系统命令（docker/kubectl CLI 同口径）。
2. **单机可部署**：三服务 + SQLite + 内嵌/单二进制引擎，`run-dev.sh` 一条命令（注意：runtimed/ontologyd 以**仓库根为 cwd**、DB_PATH=data/*.db，从子目录启动会开错库）。
3. **诚实边界**：spec_json=轻量教学子集（重语义走 oo 轨）；KG 抽取/检索为教学口径轻量实现；升级路线=REQ-235（导入保真）/REQ-207（自进化）。
4. **低侵入三原则**（REQ-171 确立）：端点可独立调用、artifact 可摘除、strict 默认宽松——后续能力扩展沿用。
5. **服务间 loopback 信任模型**（零鉴权）：部署网络边界警告见 [16 号 §3.0](../01_整体设计/16_部署与运行.md)（REQ-236⑦）。
