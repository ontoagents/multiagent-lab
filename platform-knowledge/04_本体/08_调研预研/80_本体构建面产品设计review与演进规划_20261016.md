## 2. 生产场景 Review：构建面五大差距

对照「生产环境创建可用本体」，逐条对位主人关注点：

### G1 界面操作布局：六路径并列是「路径陈列馆」，不是生产动线

生产用户带着「我要构建/演化一个本体」的目标进入构建栏，面对的是六张并列路径卡+状态标签，需要自行判断选哪条、从哪断点续作。79 号 REQ-334（双模式叙事）已拍板但只解决模块级叙事层；**构建栏内部动线未动**——继续上次会话（OntoChat restored）、未完成的自定义构建、演化已有本体三类「进行中态」没有任何首屏聚合入口。此外 `BuildPage.tsx` 1,098 行单文件同时承载六路径调度 + custom 四步流程 + 上传/导入/质量报告，已到拆分阈值。

### G2 OntoChat：对话闭环已通，生产可用度差三点

1. **草稿→入库单轮确认**：draft 阶段一锤定音（确认入库 or 整体 refine），无概念/关系分组的增量确认粒度；REQ-312 的质量报告卡只到展示层。生产本体动辄百概念级，逐项过审是刚需。
2. **中断续作薄**：`restored` 仅 `{round, draft}` 布尔级恢复，会话上下文（story 访谈轮次、文件材料、已确认 CQ 簇）跨会话续作体验靠重建。
3. **文件材料与对话主线融合弱**：REQ-277 导入的材料在后续 domain 轮的引用/溯源展示未见专门设计（仅 PaperClipOutlined 附着）。

### G3 OntoExtend：后端链路齐、前端定位弃养，恰是生产最重的场景

企业 KG 运营中**已交付本体的增量演化**比新建更高频——这正是 OntoExtend 的领域。现状：evolution 候选五连端点已具备（propose/gate/accept/reject + candidates 列表）、merge 审查底座已具备（REQ-157）、但（a）无独立 REQ 跟踪（REQ-171 P2 载体下静置）；（b）入口卡停在「部分可用」；（c）与 AssetsPage 资产详情的「演化」动作无衔接——用户在资产页看到本体，想扩展时找不到通往 OntoExtend 的动线。D-O25 拍板伴生图并入统一检索面后，「演化信号→候选→审查→入库」的消费闭环缺了构建侧的接入口。

### G4 后端架构：rest.go 2,381 行单文件是继续加端点的宿主恶化源

构建平面仍在持续加端点（REQ-328 对账将新增对账组、REQ-333 NL2SPARQL 将新增查询组），全部挤入 `rest.go` 单文件的趋势若延续，M135/M133 落地时该文件将突破 3,000 行。业务包（qualitygate/importer/evolution/llmcreate）已分域，**REST 层未分层**；且三条 LLM 构建路径（ai-draft / ontoextend-draft / kb-extract）各自直调 LLM+qualitygate，无统一「来源→抽取→草稿→门禁→审查→入库」管线编排抽象——REQ-328 零丢失对账要求每段边界留痕，没有管线层则对账埋点要在三处重复实现。

### G5 生产资格线在构建面的余量（79 号 R1 承接部分外的缺口）

REQ-328（M130 待领取）覆盖「导入·运行·导出」三段对账，**构建中态不在其列**：OntoChat 会话轮次、未确认草稿、custom 流程的中间编辑态的零丢失保障无归属。REQ-331 质量档案挂资产级，构建时 qualitygate 15 检查项已在，但缺「生产就绪清单」（production readiness checklist）概念——发布动作与质量门禁、CQ 覆盖测试（REQ-274）之间无强制序。

## 3. 界面操作布局优化方案（U 系列）

### U1 构建栏信息架构重排：「目标驱动」替代「路径陈列」（P2，前端）

首屏改为三张目标卡：
- **新建本体**——展开后进入六路径选择（路径降级为选择项，成熟度标签转角标）；
- **继续上次**——聚合 OntoChat 活跃会话（restored 状态）+ custom 未完成流程 + 待确认草稿，一键回到断点；
- **演化已有**——从资产列表选本体 → 直达 OntoExtend / evolution 候选流（与 U3 联动）。

六路径 `PATHS` 数组与 `eino.onto.buildPath` 记忆机制保留，仅承载形态从首屏陈列改为二级选择。**不动五栏 IA**（与 REQ-334 拍板口径一致）。

### U2 OntoChat 阶段可视化 + 草稿增量确认（P2，前端+轻后端）

- 五阶段 `STAGE_TAG` 升级为常驻顶部 `Steps` 步骤条（custom 流程已用 antd Steps，交互语言统一）；
- draft 阶段改双栏：左侧质量报告卡（QualityReportCard 复用）+ 右侧 spec 差异预览（VersionDiff/SpecGraph 复用）；
- 入库前增量确认：概念/关系/数据属性分组勾选——直接复用本组件已有的 `cqDraft`/`clusterDraft` checkbox 勾选交互模式，无需新组件。

### U3 OntoExtend 接入演化动线（P3，前端）

- 入口卡从「部分可用」升格为「演化路径」，描述改为「对已交付本体做 ODP 模式扩展与词表补全」；
- AssetsPage 资产详情页新增「演化」动作 → 携本体 id 跳转 OntoExtendFlow（`ontoextend` 路径已支持 buildPath 记忆，补参数透传即可）；
- evolution 候选列表在资产详情以页签呈现（evolution 五连端点现成）。

### U4 BuildPage 组件化拆分（P2，纯重构零行为变更）

1,098 行拆三层：`BuildPathGrid`（六路径调度+目标卡）｜`CustomBuildFlow`（S1~S4 流程）｜`BuildLayout`（共享上传/质量报告区）。为 U1 重排铺路，也解 OntoChatFlow 同款膨胀的先例压力。

## 4. 后端架构规划（A 系列）

### A1 rest.go 按域拆分（P2，纯重构零行为变更，与 U4 同批）

沿 `rest_ontochat.go` / `rest_overlay.go` / `rest_evolution.go` / `rest_toolchain.go` 已有先例，把 80 端点中剩余的构建域拆出：`rest_build.go`（ai-draft 族+kb+import+merge）、`rest_assets.go`（versions+publish+quality+diff+impact）、`rest_consumption.go`（cq-sparql+vocab+lifecycle）。目标：`rest.go` ≤500 行只留中间件与路由挂载。**与 REQ-328 领取开发同批做**（该需求本就要动 rest.go，拆分后开发体验立刻受益）。

### A2 构建管线编排层（P2，新建最小模块）

抽象统一六段管线：`来源 → 抽取 → 草稿 → 质量门禁（qualitygate 15 项）→ 审查 → 入库`。ai-draft / ontoextend-draft / kb-extract 收敛为管线参数化实例；**REQ-328 的对账留痕挂管线段边界**（一处埋点覆盖三路径）；OntoChat 的 draft 段与 custom 的 S2→S3 段同构对齐。新建代码量预估一个 package（~400 行）+ 三处调用点改写，符合「🆕 数量最小化」。

### A3 OntoChat 会话与草稿持久化强化（P2）

会话恢复从 `{round, draft}` 布尔升为**全量快照链**：每轮 turn 已落库（对话留痕现成），补 draft 快照版本化（沿 versions 快照链既有机制），文件材料引用入库。中断续作、跨设备续作、审计回放三个生产诉求一次满足。复用项：turn 落库 ✅ / 快照机制 ✅ / 🆕 仅 draft 版本表。

### A4 并发与多租户预留（P3 观察项，不预建）

versions 族已有 `If-Match` 乐观并发雏形；spec 编辑补单写者锁即可覆盖当前场景。多租户隔离（命名空间/配额）**等 REQ-262/259 复用规模化信号触发后拍板**，本期不做——与 79 号 §5.3 不做清单口径一致。
