## 1. 现状盘点：单点评估能力已多，缺的是体系性编排

按质量生命周期分层盘点（✅=已交付，📋=已立项待领取）：

| 生命周期时点 | 评估能力 | REQ | 现状 |
| --- | --- | --- | --- |
| 生成时（草稿级） | 双校验修复环（≤3 轮回喂）+ 草稿质量报告卡 + 按报告优化环（前后对照） | REQ-82/247/312 | ✅ |
| 保存/入库时 | 结构校验（引用完整性/命名唯一）+ qualitygate 15 项三维评分落 quality-report artifact | REQ-63/171 | ✅ |
| 导入时 | 有损导入报告 +（零丢失对账+捕获率哨兵） | REQ-235/328 | ✅/📋 |
| 资产态 | 资产质量卡（重新评分）/ CQ→SPARQL 验收（通过率入卡）/ 覆盖测试快筛（默认关）/ owlrl 推理检查档（默认关）/ 公理校验 / 变更影响分析 / 版本 diff | REQ-233①/255/274/269/278/95 | ✅（diff P2） |
| 发布时 | 发布状态机（draft/published+候选采纳自动发布） | REQ-239 | ✅ 状态机有，**发布无质量动作** |
| 运行装载时 | 装载后异步质量快评 + 低分橙标 + 计数硬闸 | REQ-234/305/328 | ✅/📋 |
| 消费态 | 消费观测台（方案消费一览+快照橙标） | REQ-290 | ✅ **无消费质量信号** |
| 演进态 | 自进化闭环（诊断→归因→补丁→配对门控）+ ontoeval 基准 | REQ-207 | 📋 P2 待排期 |

**断层总结（五缺）**：

1. **缺维度完整性**：静态结构维度强（15 检查项），推理档/CQ 覆盖两件已建但**默认关、未成日常**；语义级建模质量（建模合理性）无评估路径；消费侧效果零信号。
2. **缺时点编排**：各时点评什么、评到什么级别（阻断/提示/留痕）未成体系——发布态是明显空白（REQ-239 发布动作不带质量检查）。
3. **缺纵向追踪**：每次评分落 artifact 但**不随版本聚合**——质量随版本演进的趋势线不可见，「改好了没有」只能靠两份报告人工对照。
4. **缺横向比较**：多本体资产之间不可比；REQ-326 列表页质量雷达刚交付，但仅徽标雏形，无排序/过滤/对比动线。
5. **缺消费反馈**：本体质量的最终裁判是消费侧（agent 查询用得好不好），SPARQL 空结果率/查询失败率/验收通过率等信号未回流到质量视图（D-O19 消费观测台的自然延伸位）。

## 2. 评估维度体系：三维评分扩展为五层质量模型

现有 qualitygate 三维（完备 .35/一致 .45/可维护 .20）是 REQ-171 定案，**引擎与权重不动**（沿 72 号判定口径）。建议按「层」而非「权重」扩展——新层独立评估、在质量报告中分节呈现，不并入总分（避免重新校准权重，72 号观察项维持触发驱动）：

| 层 | 评什么 | 手段 | 现状 | 建议 |
| --- | --- | --- | --- | --- |
| L1 结构层 | 引用完整性/命名/孤立概念/层级循环等 15 项 | qualitygate 规则检查 | ✅ 引擎完整 | 不动 |
| L2 推理层 | 逻辑一致性/矛盾/OWL 反模式 | sidecar owlrl（REQ-255② 已建）；OOPS! 34 类陷阱（15 号已登记） | 默认关 | **发布前检查自动开启推理档**；OOPS! 陷阱借清单在 qualitygate 数据驱动机制内扩检查档（沿 26 号「借清单轻量子集、不引 Java 运行时」先例），触发驱动排期 |
| L3 任务层 | 本体能否回答领域问题 | CQ→SPARQL 验收（REQ-255①）+ 覆盖测试快筛（REQ-274）两级判定 | ✅ 已建，手动 | CQ 通过率在质量报告**分节呈现为正式层**（不并入总分）；三件套（273 去重聚类/255 验收/274 快筛）已齐，差的是串联呈现 |
| L4 语义层 | 建模合理性/清晰性/非冗余（超越结构检查） | LLM Judge 深评（沿 REQ-223 三值契约，REQ-207 门控共享） | 观察项 | 维持触发驱动，落点收窄两处：候选采纳门控（REQ-207 排期时）+ 权威本体引入后评审（REQ-316 场景）；成本高不日常跑 |
| L5 消费层 | 实际用起来好不好 | SPARQL 空结果率/查询错误率/验收通过率/低分橙标方案占比 | 零信号 | 新增消费质量信号聚合（§4 P2.3）——「本体好不好，最终看 agent 用得怎么样」 |

理论支撑（32 号综述）：人工在环三证据链+可解释可审计共识+CQ 驱动 SPARQL 评测——本体系全部落在「人工看报告决策、机器只产出报告」的框架内，不引入自动改本体。

## 3. 评估时点编排：生命周期六道关

| 关卡 | 触发 | 评什么 | 阻断级别 | 现状/建议 |
| --- | --- | --- | --- | --- |
| 生成关 | AI 创建/OntoChat 生成 | 双校验环 + 报告卡 | error 回喂≤3 轮，不阻断入库 | ✅ REQ-312 |
| 入库关 | 保存/导入 apply | 结构+门禁快评落 artifact | error 拦截（校验不过不入库）；质量分仅展示不阻断（58 号拍板定案） | ✅；补 C3 三点对照（§4 P1.3） |
| **发布关** | publish/unpublish | 推理档（自动开）+ 门禁全量 + CQ 概览 | **报告级不阻断**——发布出「发布前质量报告」入 artifact，含错误/告警清点与推理检查结果 | 🆕 建议：沿 REQ-239 状态机 hook，publish 端点前置检查动作（strict 本体级开关沿用） |
| 装载关 | 方案 Start | 快评快照 + 计数硬闸 | 硬闸中止启动（对账类）；质量分橙标不阻断 | ✅ REQ-234/328 |
| 消费关 | 对话查询/验收 | 消费质量信号聚合 | 纯观测不阻断 | 🆕 §4 P2.3 |
| 演进关 | 进化候选采纳 | 配对门控（双信号+可选 Judge） | 门控不过不采纳 | 📋 REQ-207 排期承接 |

编排原则沉淀：**对账类硬闸阻断（数据不能静默丢失——REQ-328 口径），质量类只报告不阻断（58 号定案），门控类只拦机器写入（REQ-207 候选采纳）**。三级口径与现有 REQ-239「draft 装载警示不阻断」、REQ-234「低侵入三原则」一脉相承。

## 4. 产品设计建议

### P1 批（高价值低成本，建议立项）

1. **资产级「质量档案」页**（质量卡升级）：现有质量卡（REQ-233①）升级为分段档案——①维度雷达图（REQ-326 列表徽标已有评分数据基础，同源复用）；②Findings 按严重级分组清单；③**版本×综合分趋势线**（评分随版本保存时追加记录，一次迁移+评分时写一行即可，版本快照机制已有）；④评估历史入口（历次 quality-report artifact 列表）。
2. **Findings 修复动线闭环**：每条 finding 附「怎么改」人话指引 + 定位跳转——error→图形编辑定位（沿 REQ-235「前往图形编辑补录」动线先例）/ warning→建议与示例 / info→学习中心方法论卡引用（内容包已有五卡可链）。这是资产级「评估→动作」断点的补齐（草稿级已由 REQ-312 A2 打通，资产级缺同款）。
3. **草稿→入库→当前三点对照**（领取 72 号 C3）：草稿分已随 REQ-312 生成链路存在，入库分在 artifact——质量档案页顶部展示三点演进（草稿分→入库分→当前分），优化有效性可追溯。

### P2 批（触发驱动/随排期）

4. **发布前质量报告卡**（§3 发布关）：publish 动作触发全量检查，报告入 artifact 并在版本历史可见；发布确认对话框预览「本次发布将带 N 个错误/M 个告警」。
5. **多本体横向对比**：资产列表质量雷达（REQ-326）扩展为可排序/过滤，质量分列入表列；fork 前后质量对比动线。
6. **消费质量信号卡**（消费观测台新增页签）：按方案聚合——SPARQL 查询空结果率/错误率（facade 翻译日志已有翻译透视数据基础，REQ-94①）/CQ 验收通过率/低分快照警示占比；阈值触达橙标提示「建议跑覆盖测试」。

### 观察项（维持）

- LLM Judge 语义深评（成本触发驱动，落点收窄见 §2 L4）。
- 维度权重再校准/新维度并入总分（沿 72 号判定口径：等真实使用反馈触发）。

## 5. 流程设计建议：四条闭环

| 闭环 | 链路 | 现状 | 缺口 |
| --- | --- | --- | --- |
| ① 生成→修复 | 报告卡→按报告优化→前后对照 | ✅ REQ-312 已通（草稿级） | — |
| ② 评估→动作 | 资产 findings→定位→修复→重评 | 质量卡只读 | **P1.2 修复动线**补齐资产级断点 |
| ③ 测试→优化 | CQ 失败→归因→补丁建议→一键应用/转进化候选 | 72 号 C1 设计已定 | 领取 72 号 C1（对接 REQ-207 候选状态机，排期联动） |
| ④ 消费→演进 | 消费信号→低效告警→触发覆盖测试/进化诊断 | 零信号 | P2.6 消费质量信号卡打头，触发动作复用既有能力 |

四条闭环共享同一原则：**机器产报告，人做决策，动作走既有动线**（图形编辑/merge 审查/进化候选确认卡），不新增自动改写通道——与 32 号「人工在环」理论共识及 REQ-207「一期只做检测+提醒+人触发」克制项一致。

## 7. 判定口径沉淀

- 「评估体系」类分析的四段顺序：**维度（评什么）→ 时点（何时评）→ 呈现（在哪怎么看）→ 闭环（怎么改进）**；先盘散件再找断层（沿 72 号三段排查法），断层多在编排与透出而非引擎。
- 阻断分级三口径：对账类硬闸 / 质量类只报告 / 门控类拦机器写入——三者不可混淆，混用会把「质量提示」升级成「流程卡死」。
- 与 72 号合并后，评估体系覆盖两态：**草稿级（创建过程）+ 资产级（构建结果）**；后续若提「评估」，先指明是哪一级再对号入座。
