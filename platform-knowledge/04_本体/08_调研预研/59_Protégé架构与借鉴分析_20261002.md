## 0. 项目概况与架构总览

Maven 五模块分层（依赖自上而下）：

| 模块 | 职责 | 我们的对应物 |
| --- | --- | --- |
| protege-common | 通用工具与日志 | 共享 util |
| protege-editor-core | **编辑器框架**：EditorKit/插件框架/工作台/视图容器/偏好 | 主后端+web 前端骨架 |
| protege-editor-owl | **OWL 本体域**：模型管理/OWL 视图族/实体操作/推理呈现 | ontology-service + 本体前端 |
| protege-desktop | 装配（打包分发） | deploy |
| protege-launcher | 启动器 | 启动脚本 |

核心分层：**EditorKit（套件契约）→ Workspace（工作台）→ Tab（标签页，插件化）→ View（视图面板，可组装）**，模型层 OWLModelManager 独立于 UI 层，事件广播贯穿（OWL API ChangeListener）。

## 1. 架构机制深研

### 1.1 EditorKit 抽象与声明式插件框架

- **EditorKit**（editor-core，2006 设计沿用至今）：每类文档一个「编辑器套件」契约——`getId()`（**ID 类型系统**：插件用 `editorKitId` 声明适用性，过滤视图/菜单插件）、`put/get(key, Disposable)`（**资源生命周期登记**：随套件关闭统一释放）、`getModelManager()`（模型层入口）、`getWorkspace()`（UI 层入口）、`handleNew/Load/SaveAs` 族（文档生命周期）。
- **JPF（Java Plugin Framework）声明式扩展点**（plugin.xml，editor-owl 10+ 个）：`inference_reasonerfactory`（推理器工厂）、`explanation` + `inconsistentOntologyExplanation`（解释服务×2）、`ui_editor_description`（类表达式编辑器可插拔，`index` 排序同槽多编辑器）、`moveaxiomskit`（公理搬移套件）、`entity_renderer`、`entitycolorprovider`、`repository`（本体仓库工厂）、`searchmanager`、`io_listener`、`ExtraReasonerMenuAction`。ExtensionMatcher 族（Parameter/EditorKit/Or）做插件过滤组合。
- **菜单槽位注入**：菜单项声明 `path="[AssertedClassHierarchy]/SlotAA-A"`——插件把自己的动作精确插到**指定视图的指定槽位**（Slot 编号排序），按焦点视图动态显隐。

### 1.2 三层工作台与视图能力协议

- **Tab 即插件**（WorkspaceTabPlugin/JPFImpl）：第三方可注册新标签页。
- **WorkspaceViewsTab**（视图容器 Tab）：视图面板可自由组装进同一 Tab，布局由 TabbedWorkspaceStateManager 持久化；CustomWorkspaceTabsManager 允许**用户自建自定义 Tab 并保存布局**——「可编程工作台」。
- **视图能力协议**（接口化能力声明，容器据此装配通用操作）：Copyable/Cuttable/Pasteable/Deleteable、CreateNewTarget/CreateNewChildTarget/CreateNewSiblingTarget（新建动作三态）、Findable、HasExpandAll、HasDisplayDeprecatedEntities、HasCopySubHierarchyToClipboard + ViewClipboard（跨视图剪贴板传递实体/类表达式）。焦点视图实现 Deleteable 则 Edit→Delete 自动可用——**能力声明与操作装配解耦**。
- **七类实体视图族**（view/ 下 cls/objectproperty/dataproperty/annotationproperty/datatype/individual/ontology 七目录）：每类实体层级树+详情的标准视图组。

### 1.3 全局选择同步与多本体管理

- **OWLSelectionManager**（model/selection/）：单一选择源全局广播——层级树选中→图/表/详情/编辑器同屏联动。Protégé 交互的「神经中枢」，二十余年多视图演进的历史答案。
- **OntologyVisibilityManager**：多本体（imports 闭包）场景的活跃本体切换，UI 三策略互斥（仅活跃本体/imports 闭包/全部已加载）。
- 本体仓库工厂（repository 扩展点）：catalog 协议，imports 缺失自动从注册仓库定位加载。

### 1.4 变更、撤销与历史

- **HistoryManager**（model/history/）：变更历史管理；**ReverseChangeGenerator**——从变更集自动生成逆操作（undo 核心，不用手写每个操作的 undo）；**ChangeListMinimizer**——变更列表最小化（把碎变更合并成语义粒度的 undo 步）。
- **轻量 git 集成**（model/git/）：GitRepositoryManager + GitStatusView——本体工作区落在 git 仓库时显示 dirty 状态（仅状态可视化，非版本化方案）。
- 对照：我们版本=保存即快照堆+版本 diff（[03_资产](../03_资产.md)），Protégé 是**细粒度操作 undo**——教学场景两种范式都成立。

### 1.5 解释、推理与度量

- **解释体系可插拔**（explanation/）：ExplanationManager 聚合多个 ExplanationService（插件），不一致本体解释独立扩展点；委托推理器插件给出证明树（为什么矛盾/为什么推出）。**「结论→解释」是独立可插拔层，不绑死推理器**。
- **断言/推断分离呈现**（inference/）：DisplayedInferencesPreferencePanel——推理结果哪些显示**可配置**；PrecomputeAction 推理预计算；StopReasoner/进度 UI。实体详情中推断公理有独立视觉态。
- **度量体系**（metrics/）：Metric 抽象+AbstractIntegerMetric；类/个体/属性计数族、imports 闭包计数族、公理分类计数、**DLExpressivityMetric（自动计算 DL 表达性签名如 ALCHIQ）**。

### 1.6 渲染基础设施与实体操作面

- **短名渲染策略链**：ShortFormProvider 可插拔（注解值→前缀名→IRI 短名聚合），UI 四档一键切换（RenderById / RenderByPrefixedName / RenderByLabel / RenderByProperty 任意注解属性）+ Custom 配置面板。OWLEntityQNameRenderer/PrefixAwareShortFormProvider 底层支撑。
- **富呈现内联开关**：公理注解内联/数据类型显示/图片 URL 缩略图（InlineAnnotation/Datatype/Thumbnail Rendering）、KeywordColourMap 关键字着色、实体颜色提供者插件、面包屑开关、styledstring 富文本。
- **LinkExtractor 外链插件族**：DOI/ISBN/PubMed/OMIM/Orphanet/Wikipedia——正则匹配实体注解值自动链接外部资源（生物医学领域实例）。
- **实体操作全家桶**（plugin.xml 上下文菜单+快捷键）：Add subclass/sibling（E/⇧E）、Duplicate（⇧C）、Change IRI Rename（U）、Convert to Primitive/Defined class（P/D）、Deprecate（五类实体统一弃用流：弃用动作+显示开关+视图能力协议 HasDisplayDeprecatedEntities）、Merge into（五类统一合并）、Copy IRI/OBO Id/Markdown、**CopySubHierarchy ↔ CreateSubHierarchy from tab indented text（层级树与缩进大纲文本双向转换——从大纲批量建层级）**。
- **usage 反向引用**（ui/usage/）：实体被哪些公理使用，按公理类型分组树形+UsageFilter 过滤。

## 3. 可借鉴清单（P 系列，按价值排序）

| # | 借鉴点 | Protégé 证据 | 对应缺口 | 建议落点与优先级 |
| --- | --- | --- | --- | --- |
| **P1** | **跨视图选择同步总线** | OWLSelectionManager 单一选择源全局广播，树/图/表/详情全联动 | 资产详情多视图并存（2D/3D/列表/被引用/图例），M66①② 做了筛选条+单视图内选中聚焦，**无跨视图选中联动**——57 号拍板追加②（邻居高亮/无关淡化）的自然载体 | 前端资产详情域全局 SelectionContext（React context/状态库单源），一处选中处处高亮——REQ-240 可视化增强系自然延伸，中件 **P3**（邻居高亮落地时一并设计，避免二次返工） |
| **P2** | **缩进大纲文本 ↔ 层级双向** | CopySubHierarchy（层级→tab 缩进文本）/ CreateSubHierarchy from tab indented text（缩进大纲→批量建子层级） | 我们「文本→结构」已有 CSV 灌装（列角色推断），缺「**大纲文本→子类层级**」轻量入口——教学场景（从讲义大纲直接建层级）独特契合 | 构建路径 1/图形编辑增「大纲导入」小功能（缩进解析→批量建 concepts+层级），小件 **P3**（教学特色亮点） |
| **P3** | **断言/推断分离的公理级标注** | DisplayedInferences 可配置+推断公理独立视觉态（斜体） | 顶层有数据源切换（仓库/运行态），**图内未区分**「事实」与「推断/伴生生成」——学生学习「哪些是推出来的」缺视觉支撑 | Graph3D/SpecGraph 边/节点推断态样式（虚线/淡化/徽标），与伴生成长图语义对齐——小件 **P3**（与 P1 同轮设计） |
| **P4** | **表达性签名（简化版 DL Expressivity）** | DLExpressivityMetric 自动计算表达性等级签名（ALCHIQ） | 能力雷达五维（M66）之外，缺一个「本体表达力等级」的**教学信号**——我们的 spec 是受限表达力（classes/relations/instances+constraints），可映射简化签名（有无层级继承/约束/等价/关系类型丰富度） | 质量卡或能力雷达附一个表达性徽标（规则映射非推理器计算），小件 **P3**（教学反馈向） |
| **P5** | **显示名渲染策略可切换** | ShortFormProvider 策略链+四档 UI 切换（ID/前缀名/label/任意注解属性） | 我们实体显示名策略固定——教学场景中英 label 混排时无切换能力 | 前端渲染策略偏好（label 优先/ID 优先），小件 **P3**（低优，label 策略已够时不动） |
| **P6** | **实体弃用流（deprecate 而非删除）** | Deprecate 统一动作（五类实体）+显示弃用开关+视图能力协议 | 我们删除即删（三级守卫防误删），无「保留历史概念、标记弃用」的软删除语义——教学演示本体演化（概念被替换但保留溯源）有价值 | spec 概念级 deprecated 标记+视觉态，小件 **P3 可选**（与 REQ-235 数据属性建模同轮评估触发驱动） |
| **P7** | **面包屑路径提示** | breadcrumb trail 开关（当前选中在层级中的路径） | SpecGraph 下钻深层级时缺路径提示 | 微件，并入 REQ-240 系观察池 |
| **P8** | **审计事件聚合（思想档）** | ChangeListMinimizer 把碎变更合并成语义粒度 | 本体资产治理四事件（版本保存/导入/fork/删除）未落审计（[05_消费与审计](../05_消费与审计.md) E6 余项，REQ-224 载荷轮搭车）——落地时**事件粒度合并**思想可直接用（如连续 5 次保存=1 个会话段） | REQ-224 载荷细化时的设计输入，零独立成本 |

## 4. 不建议借鉴（定位边界，诚实声明）

| Protégé 机制 | 为何不借鉴 |
| --- | --- |
| **JPF/OSGi 插件框架与菜单槽位系统** | Java Swing 时代的插件架构，我们 React 常量注册表（PanelView/AGENT_FORM_VIEWS）+Go 接口已同构实现「声明式注册」思想；Web 单体形态无第三方插件诉求，引入即过度设计。**价值=叙事确认**：编辑器可扩展性的通用解（声明式注册+能力过滤）在两个时代两种技术栈收敛到同一形态 |
| **细粒度 undo/逆操作生成（ReverseChangeGenerator）** | 教学场景「保存即快照+版本 diff+回滚」（M65/52 号 A-2）已覆盖核心诉求；细粒度 undo 需操作级状态机，复杂度高收益低 |
| **多本体 imports 闭包工作区/公理搬移套件（moveaxiomskit）/本体仓库 catalog** | 我们单 spec 资产+运行方案部署视图的边界（D-O11）；多本体依赖管理是完整本体工程产品形态，merge/preview 审查已覆盖单次合并诉求 |
| **proof tree 解释树（依赖 OWL 推理器）** | D-O5 既定无 OWL reasoner（Oxigraph 无 OWL RL）；qualitygate 规则级定位+G4 质量透明已是教学场景的合理解释形态 |
| **OBO 生态治理（bioregistry/obofoundry/idrange/namespace）** | 非 OBO 生态，ID 分配体系无场景；外部词表已有 LOV+ODP（路径 5） |
| **桌面形态/全局菜单栏/快捷键全覆盖体系** | Web 形态差异，无对应面 |

## 5. 结论

Protégé 二十余年沉淀的价值面在**「可编程工作台」的机制设计**：EditorKit 套件契约、声明式扩展点、视图能力协议、全局选择同步四件套，让一个 2006 年的架构持续承载到今天的插件生态——与我们「声明式注册表」路线同源互证。对当前本体模块：

1. **最值得吸收的是交互层机制**（P1 跨视图选择总线 / P3 断言推断分离 / P7 面包屑）——它们是 57 号 Topology 拍板追加项（邻居高亮）与 REQ-240 可视化增强系的**同轮设计输入**，建议在 REQ-240 系落地时一并设计，零独立排期成本；
2. **教学特色增量**（P2 大纲建层级 / P4 表达性签名）契合学习平台定位，是 Protégé 二十多年教学应用验证过的功能形态，P3 池观察候选；
3. **架构层无需动作**——插件框架/undo/多本体闭包/OBO 治理六项均超教学定位或已有架构性覆盖，本档的对照结论同时封存「是否引入 Protégé 式重型机制」的后续疑问。

**状态：调研借鉴分析，仅入 08_调研预研 档，未立项**（P1~P7 为 REQ-240 系与 P3 池的设计输入候选，待开发者拍板是否纳入排期）。
