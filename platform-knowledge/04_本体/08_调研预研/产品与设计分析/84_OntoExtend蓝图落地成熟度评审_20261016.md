## 三、三处对齐调整

### A1 管线落点重映射（替代 64 号 §4.1 原落点表述）

三段式语义映射进 buildflow 六段，**新实例名（建议 `cq-rag-draft`）注册 registry**，与 `ontoextend-draft`（ODP/LOV 模式）并列构成双模式；**不建独立旁路**（83 号既定：REQ-340 管线是共同底座）。

- Retriever（元素抽取+检索上下文组装）→ **extract 段**
- Extender（CQ+片段+prefix → LLM 生成+两阶段校验）→ **draft 段**
- Integrator（去重→merge 审查→apply 快照）→ **review+ingest 段**（去重作 preview 前置，沿蓝图 §4.4）

蓝图「不复用现有 OntoExtend 路径 API 名」的决策**保持有效**且有了具体落点：ODP/LOV 留在 ontoextend-draft 实例，CQ 驱动 RAG 用新实例名，互不污染。

### A2 embedding 检索边界明确化（64 号「复用现有向量连接」需写实）

64 号 §4.3 模块 B 复用点写「现有 KB 向量层（REQ-206 连接）、embedding 缓存」，过于乐观——现状是 **ontology-service 内零向量设施**，向量能力在 backend 进程。写实如下：

- **embedding 来源**：backend 模型连接体系（embedding 类型连接，用户可配置协议/密钥）；ontology-service 经既有跨服务 HTTP 通道调用，超时与重试沿现有 LLM 代理口径。
- **向量存储/检索**：ontology-service 进程内**内存余弦 top-k（默认 20）**——元素量级 10²~10³，无需向量库（D-O15 兼容；论文 FAISS 是百万级需求，本项目不需要）。
- **缓存**：元素向量随本体版本缓存（spec 不变不重算）；CQ 向量单次现算。
- **决策点（REQ-343 实现时定）**：embedding 连接未配置/调用失败时——**建议阻断并提示配置**（不静默降级词面检索，防质量劣化不可见）；若实现成本高再评估「词面回退+结果标记」。

### A3 新依据并入（蓝图写作后新增，S1/S2 直接引用）

- **06 号 N2/N3 免实验口径**：检索序列化与 prompt 组装照抄落地，取消 S1 原检索配置实验。
- **[81 号 CQ4OE](81_CQ4OE深度调研_CQ2Term与CQ2Onto原理与借鉴_20261016.md)**：CQ2Onto 结论（LLM 恢复显式词汇类 F₁≈60%、本体结构恢复弱）作 Extender 生成质量的**预期管理与评估口径参考**——生成片段的结构性公理（closure/属性链）不能按论文口径期待过高。
- **REQ-339 演化动线 = OE-2 双模式入口承载**：AssetsPage「演化」钮已接通 OntoExtendFlow，双模式=演化入口加模式选择（ODP/LOV ｜ CQ 驱动 RAG）。
- **REQ-338 快照不复刻**到本路径（单轮生成，StageTrace 足够，见 §二）。
