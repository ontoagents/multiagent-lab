## 2. 不建议借鉴（定位边界，诚实声明）

| 截图要素 | 为何不借鉴 |
| --- | --- |
| **Action Types / Functions**（本体挂操作语义与可执行函数） | Foundry 式「本体即可操作业务层」的应用平台形态——我们的对应物是**智能体工具/技能/连接器**三个独立模块（REQ-120/214 族），本体保持只读查询契约（Q-14 六工具+受控写=伴生/进化两条已治理通道）更符合教学定位；引入本体级 Action/Function 会打破「本体=模型层」边界 |
| **Page Configs**（本体驱动 UI 生成） | 本体直接驱动页面配置=应用生成器，远超「学习本体构建/运行」定位（D-O11） |
| **AI AGENT/TOOLS/DATA/ADMIN 平台分区** | 属平台级产品（其本体是内核），我们已按「智能体/本体/知识库」分模块治理（G-3 导航收敛），不合并 |

## 3. 结论

该系统的价值面在**产品化完成度**：版本发布态（V1）、本体要素一等公民管理（V2）、节点徽标（V4）三处是我们清晰可见的差距，其中 **V1 与 REQ-207 候选态天然互补、成本最低收益最直接**；其「本体挂 Action/Function」的重量级方向不建议跟随——我们的哲学是把「可操作性」放在 agent 工具/技能/连接器层，本体保持模型层纯度（D-O15 以来「轻量自研+边界清晰」的一贯判断）。题材层面「软件工程本体」（V3）对 AI Coding 演示有独特教学价值，建议补入种子。
