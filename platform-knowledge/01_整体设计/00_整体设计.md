# 整体设计

> 本文档是平台**整体级设计**的汇总入口：把散在《02_智能体_技术方案设计》（含原属智能体方案的平台公共部分）、《17_产品_信息架构与界面设计》、《16_部署与运行》中的整体性内容抽取总结于此；各专题细节以源文档为准，本文给结构与指针。

## 1. 产品定位（源：01 §1 / 17 §0）

「AgentLab」——**智能体与本体构建平台**（Go + CloudWeGo Eino/ADK + React + SQLite，单机可部署），双核心：

- **智能体工程**：对话工作台（过程完全可观测）→ 多 Agent 协作 → 知识/技能/本体增强 → 沙箱化执行，能力逐层叠加（详见「智能体」分类）。
- **本体工程**：构建 → 资产 → 运行 → 消费与审计全流程，多条构建路径 + 多引擎运行方案（详见「本体」分类）。

单机定位：刻意不做企业级能力（登录/多租户/计费/插件市场），零 venv 一条命令启动。

## 2. 系统架构：三平面 + 双代理（源：02 §1/§6、16）

| 平面 | 进程/端口 | 职责 |
| --- | --- | --- |
| 主平台 backend | :8080（Hertz） | 智能体装配与运行（Eino ADK）、SSE 事件流、模型能力代理、知识库、设置；反向代理本体两平面 |
| 本体构建平面 ontology-service | :8091 | 本体仓库（spec_json 多形态资产）、LLM 辅助创建、导入审查、质量门禁、工具链 |
| 本体运行平面 runtime-manager | :8090 | 运行方案编排（oxigraph/fuseki 引擎）、统一 MCP facade（onto_* 五工具）、引擎执行后端 |

对接方式：主平台经**反向代理**（同源嵌入本体界面与 API）+ **MCP Client**（facade 五工具挂给 Agent）；一条 `run-dev.sh` 拉起全栈（部署细节见 [16_部署与运行[../](./16_部署与运行.md)）。

## 3. 技术栈总表（源：02 §2.1）

- **语言/框架**：Go 1.22+（各平面统一）；前端 Vite + React 18 + AntD 6。
- **LLM 框架**：CloudWeGo Eino + Eino ADK（ChatModel/Agent/Runner/Interrupt-Resume/Callback）。
- **MCP**：mark3labs/mcp-go + eino-ext components/tool/mcp（本体 facade 接入 + Agent 对外 /mcp 服务化）。
- **存储**：SQLite（业务库，API Key AES-256-GCM 加密）；Qdrant（向量，主）+ SQLite 余弦（fallback）。
- **引擎/可视化**：Oxigraph（SPARQL 型引擎，fuseki 推理对照）；React Flow（编辑态）/ 3d-force-graph（三维浏览）/ WebVOWL（语义记法对照）。
- **协议**：REST + SSE（POST fetch 流式）+ MCP（facade 消费 + Agent 对外服务化）。

完整选型表与依据见 02 §2.1；开源引入台账见 [15_开源项目及论文登记簿](../../docs/15_开源项目及论文登记簿.md)。

## 4. 配置与装配模型（源：02 §6.1/§6.2）

**配置驱动装配**：模型连接 → 智能体 → 项目三层配置全部存库，每次运行按当前配置动态装配 Eino Agent——改配置下一次运行即生效，无需改代码重启。模型连接支持 openai_compat / anthropic 双协议（协议为连接属性，REQ-172/177）；Agent 执行后端可插拔（inprocess / docker / k8s，REQ-122）；推理后端可插拔（eino-adk / claude-code / opencode / aider / deepseek-harness，D-O13）。

## 5. 对话事件协议（SSE，源：02 §8）

事件顺序：`run.started → (skill.loaded) → agent.started → (retrieval) → message.delta* → (tool.call/tool.result | subagent.enter/exit | ontology.query | ontology.unavailable | artifact.saved)* → run.finished|run.error`；事件 JSON 统一 `{type, run_id, ts, data}`。过程完全可观测（调试模式 REQ-117：三档观测级别/model.step 调用链/事件流重放）。

## 6. 全局 IA 与横切规范（源：17）

- **导航**：顶部五业务模块（智能体/项目/本体/知识库/技能）+ 平台知识 + 设置（REQ-99/REQ-111，G-3 收口）；本体模块经反代同源嵌入、内部六栏 IA（D-O11/D-O21）。
- **平台知识页**：目录驱动二级主题树，**页面与 `platform-knowledge/` 目录 1:1**（G-5）——agent 维护的文档人在页面可见（REQ-161/169/184）。
- **横切规范**：模块首屏空态引导（REQ-112）、三态与错误文案规范（REQ-115）、数据导出与生命周期（REQ-113）、绑定目录安全口径（REQ-114）。

## 7. 设计原则（跨模块铁律）

- **开源优先**：向量库（Qdrant）、图引擎（Oxigraph/Fuseki）、前端组件均用现成开源；自研只保留装配层/路由薄层（D-O3/D-O5；边界分析见 [08_本体_开源复用与自研边界分析](../04_本体/08_调研预研/方法论与理论/08_本体_开源复用与自研边界分析.md)）。
- **可插拔抽象**：执行后端/向量存储/运行引擎/推理后端接口先行，实现可替换。
- **诚实降级**：方案未运行、向量库不可用、外部 CLI 缺失时明确提示并降级，主链路不受影响。
- **低侵入扩展**：新能力旁路落地、开关默认关、产物可摘除（REQ-170 伴生本体三原则的泛化）。
