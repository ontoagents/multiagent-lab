# 整体架构与开源演进路线

> 本档回答三个问题：**架构为什么长这样**（从 Q-23 定位逐词导出）、**这套架构对开源成长意味着什么**（可插拔缝=贡献者接口；就绪度实盘）、**接下来往哪走**（E1~E4 演进阶段，全部锚定既有需求池，触发驱动）。
> 治理边界（G-7）：本档是**导航层**——所有演进项的事实源仍是各档需求池/注册表（01 §9/03/11/18/02 §12），本档表内条目一律带指针、不重复登记需求；阶段是叙事组织，不是排期承诺。

## 1. 定位 → 架构的四条推论

定位语（Q-23，2026-10-28 定稿）：**「面向专业个人的工作学习助手——以本体为知识底座：知识不是一堆文档，而是可查询、可审计、可出题的结构化资产（单机自部署）」**。逐词导出架构约束：

| 定位词 | 架构推论 | 落点 |
| --- | --- | --- |
| **个人** | 单用户、单机自部署、零运维：三平面单机进程 + SQLite，无登录/多租户/计费（Q-21 裁判保留，01 §1.3 边界）。**不做水平扩展设计**，复杂度预算全部花在个人价值上 | 00 §2/16 号 |
| **工作学习助手** | 产品面是一等公民，引擎面（智能体工程）与底座面（本体工程）为其服务。三层叙事对应三个演进速率：**产品面最快、引擎面居中、底座面最稳**——演进投入按此分配，不是三线均摊 | 17 §0/01 §9 |
| **知识=可查询、可审计、可出题的结构化资产** | **资产化管线是架构主轴**（§2.2）：「可查询」=检索面（KB+GraphRAG+KG）、「可审计」=溯源面（PROV-O/ontology_hit/事件流）、「可出题」=基准面（CQ 回归+check_answerable）。三词各对应一组已交付能力，缺一段即定位不成立 | 03/04/11/12 |
| **开源** | 架构必须为外部贡献者预留接缝（§3）：协议开放（MCP/A2A/SSE 全部公开规范）+ 可插拔接口（九缝）+ 模块边界（三平面 HTTP 松耦合，89 号 E2 实证 Go 侧干净） | 89 号 |

## 2. 整体架构总览

### 2.1 五层视图（现状事实源）

| 层 | 内容 | 事实源 |
| --- | --- | --- |
| **产品面** | 对话工作台（过程完全可观测）/项目〔将改名工作区〕/本体模块五栏/知识库/技能/平台知识/设置；**助手统一入口与笔记本是下一跳**（01 §9 衍生①、REQ-495） | 17 号/01 §3 |
| **引擎面（智能体工程）** | Eino ADK 配置驱动装配、SSE 事件族、多智能体（Agent-as-Tool/Transfer）、外部成员（cli/a2a/stdio MCP）、沙箱（inprocess/docker/k8s） | 02 号/53~56 号 |
| **底座面（本体工程）** | 构建（六路径+质量门禁）→资产（版本/质量雷达）→运行（oxigraph/fuseki 双引擎+组装载闭包+推理物化）→消费与审计（KG 检索观测+ontology_hit 归因）；KB 子模块（RAG/GraphRAG 自研 KG） | 03/04/11/12 号 |
| **横切面** | 可观测（SSE 事件族/run_event/审计）、质量资产（CQ 回归基准/agenteval/kbeval/装载对账硬闸/冒烟清单）、诚实降级、配置加密（AES-256-GCM） | 00 §5~§7/20 号 |
| **部署面** | 单机 `run-dev.sh` 一条命令零 venv（D-O15）/桌面安装包双平台（Tauri，REQ-321/324）/Docker Compose + Helm | 16 号 |

### 2.2 知识资产管线（定位主轴）

四类知识资产分工（REQ-495 立项分析口径，11 v1.12 §2）：

```
外源知识 ──► 过程知识 ──► 自产知识 ──► 结构化终态
  KB          工作区        笔记本        本体
(连接器导入)  (目录+会话产物) (REQ-495/M304) (spec_json 资产+伴生成长)
```

管线四段：**采集**（KB 连接器四族/文件导入）→ **内化**（检索/引用/伴生抽取）→ **产出**（对话产物/笔记本页面树）→ **沉淀**（本体资产/出题基准）。当前断点与下一跳：①笔记本（M304）把「自产」接进资产层——否则自产知识散落在会话里不可沉淀；②助手统一入口（衍生①）把「使用」变成日常——否则资产无人消费、使用证据为零（58 号评估实锤）。**管线完整性 = 定位兑现度**：任何新特性先问「它接通/加固了管线哪一段」。

## 3. 面向开源的架构资产：可插拔缝清单（贡献者接口盘点）

架构对开源的核心贡献是**每一条缝都有真实实现做样板**——外部贡献者做「第二种实现」时不必读全部代码，对齐接口即可：

| # | 缝 | 现状实现（样板） | 扩展方式 | 典型外部贡献 |
| --- | --- | --- | --- | --- |
| 1 | 模型连接 | openai_compat / anthropic 双协议（REQ-172/177） | 设置页加连接即用 | 新模型供应商适配验证 |
| 2 | 推理后端 | eino-adk / claude-code / opencode / aider / deepseek-harness（D-O13） | 注册表+适配器 | 新 CLI agent 接入（沿 REQ-426 形态） |
| 3 | 执行后端 | inprocess / docker / k8s（REQ-92/122） | 接口实现注册 | gVisor/Kata 沙箱运行时 |
| 4 | 向量存储 | Qdrant 主 + SQLite 余弦 fallback（Q-18） | 接口双向适配（REQ-456 先例） | pgvector/milvus 等实现 |
| 5 | 图引擎 | oxigraph / fuseki 双引擎方案+一键安装 | 引擎方案注册 | 新 SPARQL 引擎 |
| 6 | 连接器 | K8s/SSH/MCP/stdio/cli/a2a + 文档存储第四族（M304） | kind 注册+探测握手 | 新数据源/文档仓库连接器 |
| 7 | 技能包 | SKILL.md 目录式+集合（REQ-371/373） | 目录约定 | 技能包内容创作（非代码贡献入口） |
| 8 | 协议面 | 每 Agent=MCP server（`/mcp`）；A2A 成员互发现；SSE 事件族 | 标准协议，无需改平台 | 外部客户端/编排器消费与集成 |
| 9 | 本体 facade 工具面 | onto_* facade（组作用域化 REQ-482） | 工具注册 | 面向垂直域的查询工具扩展 |

判断：**接缝密度已足够，欠的是接缝的文档化与样例**（每缝的「接口签名+最小样例+测试入口」目前散在 53~56 号与各方案档）——这是 E3「测试地图/架构图」件的实质内容。

## 4. 开源就绪度盘点（2026-10-29 仓库实况）

**已有 ✅**：LICENSE（Apache-2.0）；中英双 README（Key Features+Explore 折叠+Roadmap+Appreciation 完整台账）；官网（GitHub Pages，push main 自动部署）；桌面安装包双平台（client-release.yml 发布仓触发）；平台知识页（agent 维护文档人在页面可见——项目治理本身即演示）；回归冒烟清单+headless smoke 套件（20 号，质量资产）；15 号开源台账（借鉴与拒绝候选全记录，诚实借鉴）；89 号拆分预案（治理清醒：仓内治理先于拆仓）。

**欠账 ✗（逐项核实）**：

| 欠账 | 证据 | 影响 |
| --- | --- | --- |
| CONTRIBUTING.md / CODE_OF_CONDUCT.md / SECURITY.md 缺失 | 仓库根无此三件 | 外部贡献者无第一入口；本仓纪律（REQ 先行/冒烟/诚实边界）没有对外版 |
| issue/PR 模板缺失、无 good-first-issue 通道 | `.github/ISSUE_TEMPLATE` 不存在 | 反馈无结构、任务无低门槛入口 |
| 公共仓无测试 CI 门禁 | workflows 仅 client-release + website-deploy | 测试绿只靠本仓开发纪律保证，外部 PR 无质量闸 |
| 架构图缺失 | README/官网无 overall architecture 图（00 号纯文字） | 30 秒内讲不清系统形态，第一印象折损 |
| 测试地图缺失 | 三平面+web 测试入口散在各档 | 贡献者不知道「改了 X 该跑什么」 |
| 文档双语只覆盖 README | docs/ 与 platform-knowledge/ 全中文 | 早期社区画像=中文读者；英译范围与维护成本需拍板（E3 决策项） |
| 发布节奏未产品化 | 有 tag 能力（client-release.yml）但无 release notes 惯例 | 使用者无法追踪演进、无法选择版本 |

**核心判断**：阻碍不是代码质量，是**贡献者第一公里**——外部人能否 30 分钟内跑起来（✅ run-dev.sh+预设连接+桌面包）、找到第一个能做的事（✗）、把改动安全地提交回去（✗ 无 CI 门禁与测试地图）。

## 5. 演进路线 E1~E4（对的方向，逐阶段）

> 每阶段的每件工作事实源在需求池，触发驱动领取；本节回答的是「为什么这批该先做」。

### E1 定位落地——先把单用户价值做实（**当前阶段**）

目标=**真实使用证据**。58 号评估实锤「使用证据为零是当前真瓶颈」：开发者自己先用起来，是冷启动体验打磨与产品叙事的唯一可信来源。

要件（全部已立项，按依赖序）：
- **冷启动建模体验**（01 §9 衍生④——**定位胜负手**，竞争集全部零建模即用）
- **助手统一入口 + 工作区改名**（衍生①，产品面分层落地）
- **笔记本模块**（REQ-495/M304——自产资产层，管线第三段接通）
- **出题·批改·掌握度闭环**（衍生③——差异化主攻，依赖 E2 底座）
- 体验与底座托底：视觉语言对齐扩散批（M297~M303）、KG 工程化批（M286~M294，M286/M287 已 ✅）

出口判据=开发者日常自用产生第一手使用记录（哪些场景成了/哪些断了），反哺 §9 池优先级。**未形成使用证据前，不启动 E4 类运营动作。**

### E2 资产底座纵深——「可查询可审计可出题」的技术兑现

- KG 工程化深化批 M286~M294（实体稳定 ID ✅/PPR 图排序 ✅/增量更新/claim 溯源 span/消歧合并/维度漂移检测/队列恢复/Rerank 评估件——11 号批次三）
- 跨本体语义完备批 M279~M282 已全数收口（语义桥/装载闭包/推理物化/组作用域归因）
- 本体资产级分层质量评估（CQ4OE 蓝图——README Roadmap 在案行）
- 伴生本体纵深（时间维记忆，Graphiti 对标在案）

判断：没有 E2，E1 的出题闭环没有结构保证（纯 LLM 出题即同质化竞争）、「可审计」叙事不成立。**底座面演进速率最稳但不可以停。**

### E3 开源就绪——贡献者第一公里（触发=E1 使用证据形成 + 首批外部反馈）

| 件 | 内容 | 成本/解锁 |
| --- | --- | --- |
| 贡献者基建包 | CONTRIBUTING.md（REQ 先行/冒烟/诚实边界纪律的对外版）+ issue/PR 模板 + CODE_OF_CONDUCT + SECURITY | 低成本/补齐第一入口 |
| CI 门禁 | 公共仓 go test 三平面 + web tsc/build + 冒烟清单 ★ 主链路子集 | 中/外部 PR 质量闸 |
| 架构可视化 | overall architecture 图（本档 §2 为底稿）进 README/官网 | 低/第一印象 |
| 测试地图 | 三平面+web 各自测试入口/覆盖口径/「改哪跑什么」一页 | 低/贡献者自助 |
| 种子场景包 | 一键导入示例 KB+本体+技能（zero→demo 动线） | 中/演示与试用转化 |
| 发布节奏 | tag + release notes 惯例（client-release.yml 已就位等节奏） | 低/使用者追踪 |
| 双语拍板 | docs/platform-knowledge 英译范围与维护成本（社区画像决定，不预设全译） | 决策项 |

优先序：**CONTRIBUTING + CI 门禁 + 架构图三件先行**（成本最低、解锁面最大）；种子场景包与 E1 冷启动建模共用底层链路，可并线。

### E4 社区与生态——从使用者到共建者（前提=E1 价值成立 + E3 通道打开）

- **本体模板库/权威本体目录**——社区贡献内容资产（非代码贡献的第二入口，与技能包内容创作同构）
- **连接器/推理后端/引擎第三方实现生态**——接口稳定化+兼容性测试套件（§3 九缝的生态化）
- **MCP 生态位运营**——每 Agent=MCP server 是天然集成面：被 Claude Desktop/Cursor 等消费的教程与案例
- **案例与叙事**——真实用户工作学习流案例（E1 使用证据的对外版）
- **治理升级**——多维护者评审流/拆仓触发沿 89 号两阶段预案/社区 REQ 提案流程（18 号注册表对外口径）

判断：跳序做 E4（运营先于价值）是对标分析教训（「被看见靠场景锐利而非引擎通用性」，DeepTutor 复盘）的反面，明令禁止。

## 6. 度量（成长怎么衡量）

三层指标，当前全部为零、如实记录：

| 层 | 指标 | 阶段 |
| --- | --- | --- |
| 使用证据 | 开发者自用频次与场景留存；外部 issue/反馈量 | E1 起 / E3 起 |
| 贡献者 | 外部 PR 数与合入率、good-first-issue 完成率 | E3 起 |
| 用户 | 安装包下载/stars 等 vanity 指标**降权**——场景锐利先于规模 | E4 起 |

治理口径：**度量落档不建系统**——单机产品无遥测（隐私边界即卖点），季度手工盘点注记在本档迭代表（沿 58 号评估轮先例），不立专项。

## 7. 反模式护栏（不做什么，沿既有拍板）

- **不做企业级**：多租户/登录/计费/插件市场不做（Q-21，01 §1.3）；
- **不换底座引擎、不引 Python 运行时**（D-KB6/D-O15）；LightRAG 类不主动推进（D-O15 口径）；
- **不主动扩「流程场景」主张**（过程本体 P2 留观察，Q-23 修正①）；
- **不为开源而开源**：双语全译/社区运营等高成本低确定项全部触发驱动，不预设排期；
- **拆仓先于治理=反模式**（89 号结论：仓内治理先行，拆分按两阶段触发）。
