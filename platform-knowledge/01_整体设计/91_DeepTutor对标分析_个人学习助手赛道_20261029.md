## 2. 功能全景 🟢

- **核心模式（「One runtime for every mode」）**：Chat / Ask Questions / Quiz / Research（带引用报告）/ Visualize / Solve / **Mastery Path（掌握度路径）** / Immersive Reading / Audio Overview / Book 生成 / Video Lesson——单一 orchestrator 支撑全部模式。
- **Learning Notebook**（原 Co-Writer）：块级讨论（Dito block-level discussion）——**REQ-495 笔记本模块的直接对标物**。
- **Partners**：持久 IM 陪伴（飞书/Telegram/Slack/Discord/WhatsApp/WeChat 等 15 渠道）——「a chat that has a personality and a phone number」。
- **My Agents**：会话中实时咨询外部 harness（Claude Code / Codex / Grok CLI / Kimi 等）；导入 ChatGPT/Claude Code/Codex 历史。
- **Knowledge Center**：多引擎 RAG——LlamaIndex / PageIndex / GraphRAG / LightRAG(+Server) / WeKnora / Tencent IMA / MarginNote 4 / Kiwix ZIM / Obsidian vault；GitHub 仓库与文档站同步；`deeptutor kb eval` 检索基准命令。
- **三层记忆**：L1 轨迹 / L2 事实 / L3 综合 + 可视化 Memory Graph；自述「deliberately *not* a hidden vector store」（文件式、可审计的记忆金字塔）。
- **Skills 生态**：EduHub + ClawHub 技能市场，带导入安全门（flagged packages 拒绝导入）。
- **其他**：Task Board、间隔练习（spaced practice）题库、主题系统、语音 TTS/STT、图像/视频生成、NDJSON agent 接口（其他 LLM 可把它当工具驱动）。

## 3. 架构反推 🟢/🟡

- **单 orchestrator + 插件**：一条「ChatOrchestrator」agent loop + Tools & Capabilities 插件模型（v1.0.0-beta.1 一次性 ~20 万行重写 🟢）；子智能体经 `consult_subagent`；MCP servers 接入；沙箱代码执行（runner sidecar → bubblewrap → 受限子进程）🟢。
- **知识面 = 多引擎 RAG，无统一本体**：GraphRAG/LightRAG 只是**可选检索引擎**，不存在统一的领域本体层——出题/掌握度建立在 LLM 直出 + 向量/图检索之上，**无知识点覆盖度保证、无概念子图化的掌握度模型** 🟢。这是与本项目最本质的结构性差异。
- **多用户演进**：auth 默认关闭，可选多用户（per-user 隔离工作区 + admin 授权）🟢——面向学校/自托管社区部署。
- **反面教训**：v1.0 约 20 万行重写 🟢 = 早期快速堆功能后架构债爆发的代价；本项目「工程化成熟度」路线（Q-21）恰是对此坑的免疫，应作为对自托管部署者的卖点讲出来。

## 4. 运营打法 🟢（开源影响力维度，可选借鉴）

## 5. 对本项目的借鉴结论（Q-23 来源，2026-10-28 拍板）

1. **定位层**：通用 agent 引擎 + 一人人看懂的场景叙事 = 被看见的路径；DeepTutor 40k stars 靠场景锐利而非引擎通用性。→ Q-23 定位语「面向专业个人的工作学习助手——以本体为知识底座」+ 分层叙事（智能体工程=引擎/本体工程=差异化知识底座/个人助手=产品面）；「迷你版 Coze」对标论述正式放弃。
2. **差异化层**：DeepTutor（及整个个人知识助手竞争集：NotebookLM / Claude Projects / ChatGPT 记忆 / Obsidian / AnythingLLM / Open WebUI 等）全是向量 RAG 路线，**无本体级结构与审计**——可查询/可审计/可出题的结构化资产是本项目唯一可防守的楔子；**冷启动建模成本是胜负手**（对手全部零建模即用）。
3. **功能层（学习闭环借鉴）**：出题生成 → 批改 → 掌握度追踪的闭环结构值得借鉴；**本体驱动差异化**=从本体出题保证知识点覆盖度与无重复 + 概念子图掌握度（本体层级天然是掌握度模型）——CQ 基准集 / check_answerable / agenteval judge 为现成地基（01 §9 衍生③）。
4. **已落地的直接产物**：Q-23 决策（01 §8）、README Key Features/Explore/Roadmap/Appreciation 结构改造（2026-10-29）、REQ-495 笔记本立项（Learning Notebook 对标）、01 §9 衍生需求四件。
