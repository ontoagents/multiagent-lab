## 一、定位：与既有学习体系的关系（先说清不做什么）

项目**已有两条学习承载线**，本方案是第三条，三者互补不重复：

| 线 | 承载 | 解决的问题 | 状态 |
| --- | --- | --- | --- |
| 操作学习线 | 学习中心栏（七阶段路径+方法论卡+任务卡） | "边做边学"——怎么操作工具建本体 | ✅ 已建成（13 号档 G1~G9 大半落地） |
| 资料归档线 | platform-knowledge/ 128 篇 | "查得到"——调研/设计/实现状态按主题归档 | ✅ 已建成（REQ-161 目录驱动页面树） |
| **知识体系线（本方案）** | 概念/决策/实践知识卡 + 学习路径主档 | **"学得懂"**——把工程材料中蕴含的技术知识提炼为可系统学习、可掌握的认知序列 | ❌ 缺失 |

**本方案的核心主张**：项目材料的学习价值不在"资料本身"，而在三层被过程文档掩盖的知识——**概念**（是什么）、**决策**（为什么这样设计，D-O 决策链独有）、**实践**（怎么落到代码）。把这三层提取出来重组为学习序列，学习者沿路径学习即可掌握本体与智能体技术体系——这是市面教材给不了的（教材有概念无决策，本平台有完整决策链）。

### 2.2 真实缺口（为什么不能直接"学 docs"）

1. **形态错位**：docs 核心文档是 40 万字节级**决策过程记录**（长行、交付注嵌套、面向开发者），认知负荷极高，不是知识体——学习者无法直接消化；
2. **组织错位**：128 篇按"归档主题"组织（给维护者检索用），不按**认知路径**组织——无前置关系、无难度梯度、无掌握自检；

## 四、知识模型与提取方法（最佳方案核心）

### 4.1 三层知识卡

| 卡型 | 回答 | 源提取自 | 篇幅 |
| --- | --- | --- | --- |
| **概念卡** | 是什么（定义/类比/在 DL·知识工程谱系中的位置） | platform-knowledge 调研档 + docs 概念段落 | 300~800 字 |
| **决策卡** | 为什么这样设计（背景/备选/取舍/后果）——**项目独有价值** | D-O 决策 + REQ 交付注 + 方案 §选档论证 | 400~1000 字 |
| **实践卡** | 怎么做（代码落点/流程/常见坑/示例联动） | 53~56 实现状态 + 90 号代码地图 + seeds 任务卡 | 400~800 字 |

### 4.4 知识工程增强：三层资产架构（v1.1 新增，回应「沉淀手段」异议）

主人提出：知识体系沉淀可否借助知识图谱、LLMwiki（DeepWiki 类 LLM 自动生成 wiki）或其他知识工程技术。结论：**可以且建议采用，但三种手段定位不同——分层使用，不替代知识卡**。

| 手段 | 可行性判断 | 定位 |
| --- | --- | --- |
| **知识图谱化** | ✅ 强推荐——KG 底座全套现成：`backend/internal/kg`（实体抽取/社区检测/全局问答管线）+ Oxigraph + 伴生检索 REQ-287 ✅（FTS5 兜底+定义向量+RRF）+ REQ-358 伴生图增强 / REQ-368 双时序底盘 | **L2 承载层**：知识卡→KG 摄取，获得前置图自动编排、断链检测、语义检索；且是终极 dogfooding——用平台自己的本体能力描述平台知识，元本体本身就是六路径教学示例 |
| **LLMwiki（DeepWiki 类自动生成）** | ⚠️ 只作辅助——三个硬伤：①产出是「代码结构解释」，非认知视角学习序列；②全自动生成与「每卡带源指针可回溯」硬纪律冲突（幻觉面不可控）；③百科式平铺，无前置关系/难度分层/自检 | **素材提取辅助**（P3 可选）：对代码仓库跑 DeepWiki 式提取补充实践卡素材，产物须人工核对入卡，不直接承载知识体系 |
| **llms.txt / LLM 可读聚合** | ✅ 轻量顺手 | **L3 服务层之一**：聚合全部知识卡 frontmatter+摘要为 llms.txt 形态，供对话智能体（平台助手）引用知识体系作答 |

**三层资产架构**（单源纪律不变——md 卡始终是事实源，KG/llms.txt 是投影）：

```
L1 人读层（P1）    知识卡 md + 学习路径主档 —— 走 REQ-188 页面树，零代码
L2 图谱层（P2）    知识元本体（Knowledge Ontology：ConceptCard/DecisionCard/PracticeCard
                   + prereq/cites/derivesFrom/supports 边；用平台六路径之一建，本身即教学示例）
                   + 摄取脚本（frontmatter→三元组，~300 行，进 internal/kg 或独立 Oxigraph 图）
L3 服务层（P2~P3） 前置图自动编排 / 断链检测（复用平台校验能力）/ GraphRAG 语义检索（复用 REQ-287 三臂）
                   / llms.txt 聚合 / 知识卡问答接入平台助手
```

**提取分工同步修订**（回应原决策点③异议）：由「Agent 提取+主人逐卡抽检」改为**人机流水线**——①LLM 批量提取（强制带源指针）；②自动校验器（源指针存在性检查/卡模板校验/prereq 断链检测——即 L2 图谱层的免费产物）；③人工只抽检高风险决策卡（D-O/REQ 引用正确性抽样）。瓶颈从「逐卡核对」降为「抽样核对」。
