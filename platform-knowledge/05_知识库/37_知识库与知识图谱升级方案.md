## 1. 方案目标（三句话定位，承 45 号 §1）

1. 知识库是平台内的**证据供给面**——带引用、带来源、带策略标注；检索策略对照是产品价值锚点（LG-11 升级：从「搭出闭环」到「对照多种策略并解释差异」）。
2. KG 六环节从「教学口径」升级到「可用口径」——检索多跳、全局问答真闭环、抽取覆盖与质量（技术路线=**自研增强**，算法借 gonum/递归 CTE/PPR，方法论借 LightRAG/KGGen/iText2KG，35 号 §三）。
3. 边界不变：知识库不拥有本体（消费约束、供给素材）；D-O15/单机基线/零新外部依赖约束下批次一全部 Go 原生实现。

## 6. 风险与边界

| 风险 | 缓解 |
| --- | --- |
| FTS5 trigram 对 <3 字符查询不命中 | 短查询自动跳过词法臂，纯向量兜底（如实标注 strategy） |
| Louvain 引入 gonum 新依赖 | 纯 Go/BSD-3，15 号登记；label propagation 保留为对照实现 |
| KB-5 对话接入改变回答行为 | 取「本地无命中才走社区摘要」的兜底语义，命中正常时行为零变化；SSE 只增字段 |
| KB-10②/KB-11 改动面大 | 排批次一末位，独立提交可回滚；前端改动按 docs/20 S3 冒烟 |
| LLM 成本上升（KB-5 map-reduce / KB-6 并发） | 摘要缓存语义 + 库级预算可配（KB-6 交付时）；token 计数如实呈现 |
