# Jev 决策模型范式：调研与借鉴分析

> **调研对象**：TypeSafe AI 于 2026-09-15 发布的决策模型 **Jev**（System One 类），及其一周内涌现的 13 篇 arXiv 论文、开源平替生态。

## 1. 调研背景

2026-09-15，隐身两年的 TypeSafe AI（创始人 Diogo Almeida，OpenAI 时期 RLHF / InstructGPT 核心贡献者）发布 **Jev**：一个**不生成文本、只输出带校准概率的类型化决策**的模型，同时披露 4000 万美元种子轮。4 天后首批相关研究挂上 arXiv，随后涨到 13 篇，9 月 21 日一天上线 6 篇。

本文选取综述中 4 篇代表工作（已逐一核验为真实 arXiv 论文），并补入 Jev-Mem 的开源实现与一周内出现的开源平替生态，目标是回答三件事：**Jev 到底是什么、它的范式为什么成立、对构建智能体平台有什么可借鉴与必须警惕的地方**。

## 2. Jev 本体：模型定位与接口范式

### 2.1 它不是更小的 LLM，而是另一种输出形状

Jev 借用卡尼曼"快直觉 / 慢推理"的二分，类别名 **System One**：模型名取自经济学家杰文斯（Jevons）。它的核心差异不是参数少，而是**接口只有三样原语，且不做自回归解码**：

| 原语 | 回答什么 | 返回 | 限制 |
|---|---|---|---|
| **Choice** | 从给定选项里选哪个 | 选中项 + 每个选项概率 + 置信度 | 单次最多 255 选项 |
| **Score** | 落在有序量表的哪一级 | 分 + 各级概率 + 置信度 | 2–10 个有序级别 |
| **Noul** | 该陈述是否为真 | 0–1 之间的概率 | 单条陈述 |

调用方送入一段**状态**（文本或 JSON）和预先声明的**问题字典**，Jev **并行一次性**返回答案、概率分布与置信度。三种问题可在同一请求里合并、对同一状态并行求值——这是它快的结构性原因。

### 2.2 两个真正关键的工程属性

1. **并行采样器（非自回归）**：不 token-by-token 生成，所有输出单次查询得出，无输出 token 费用。官方口径 70–500 ms 延迟、输入 $0.042 / 百万 token、输出免费（全部为 TypeSafe 自评）。
2. **校准过的置信度（RLCD 训练）**：训练方法是 **RLCD（Reinforcement Learning for Calibrated Decisions）**，优化目标不是"答案更像人话"，而是"给出 90% 概率时确实约 90% 正确"。**有了这个，代码里就能写阈值，把低置信样本路由给强模型**——这是后面所有论文共同的骨架，也是 Jev 范式的真正支点。

### 2.3 必须直说的可用性边界

- **TypeSafe 至今未公开模型架构与 RLCD 训练细节**；"快 40–200 倍、便宜 40–400 倍"是唯一自评来源，尚无第三方在统一协议下复现。
- **服务未向中国内地开放**（候补名单制早期访问）。已集成进 Vercel AI Gateway、OpenRouter 等第三方网关。
- **"零幻觉"是结构性的、且被误读最多**：Jev 保证的是"不会返回 schema 外的类型"（out-of-schema 在数学上不可能），**不保证选中的选项是对的**。DataCamp 基准显示其与参考答案一致率约 67.8%，而前沿 LLM 约 73–74%；"零格式错误"是真，但"错误决策"非 0。
- 上下文窗口 64k（state + 单条最长问题上限 32k）。

## 3. 一周 13 篇论文：选取 4 篇代表

综述选取的 4 篇几乎同时摸到了"判断从生成里拆出来能省钱，但省下的钱换不回被误差相关性吃掉的那部分准确率"的上下两面。以下数据均来自 arXiv 摘要或综述引用的论文表格。

### 3.1 论文 1 — REFLEX：决策层与生成层分离，强模型调用少 72.7%

- **标题 / 编号**：REFLEX with Jev for Efficient Selective Control in LLM Agents，[arXiv:2609.26532](https://arxiv.org/abs/2609.26532)（2026-09-22，cs.AI）。
- **方法**：把 Jev 放在 Agent 的快速类型化决策层，置信度足够高就直接执行有限决策，置信不足或需开放式生成时才调强 LLM；阈值 τ 是唯一旋钮。对照设得很全：B0 纯强模型、B1 纯 flash、B3 flash→max 级联，REFLEX 记 R1，全跑在同一份冻结的 100 任务 reflex-sim v1.2.0 上，并用 3 族不同回退模型重复验证，外加 RF-5C 五因子控制（60 场景族）与 BFCL、τ²-bench 两个外部基准。
- **数据**：τ=0.5 时成功率 0.95、强模型调用 **1.12 次/任务**，相对 B0 的 4.10 次降低 **72.7%**；B0 自身成功率 0.88，R1 反而更高。
- **量化了"哪些决策能外包"**：工具选择 116 次调用中 **99%** 被 Jev 替换，完成判断 77%，检索决策 56%，澄清类仅 28%——越需语境权衡越难替换。
- **客观局限**：0.95 高于 0.88 要拆开读——附录写明门控捞回 8 个 B0 失败任务、丢 1 个，100 任务净变动撑不起"更省还更好"；外部基准 τ²-bench 多轮任务中 REFLEX 相较廉价生成级联优势有限；208 个错误里 **192 个集中在风险与澄清类**（117+75），检索 / 常规工具选择 / 工作流判断合计 720 次零错误——Jev 接手的恰好是它最擅长的。

### 3.2 论文 2 — Jev-Mem：记忆构建快 6.6 倍，控制平面单设

- **标题 / 编号**：Jev-Mem: System-One-Controlled Agentic Memory for Efficient AI Agents，[arXiv:2609.23986](https://arxiv.org/abs/2609.23986)（2026-09-21，cs.AI/cs.LG）。**有官方开源实现**：https://github.com/libingzheren/Jev-Mem。
- **方法**：把系统一/系统二分工搬进 Agent 记忆——轻量 System-One 控制平面管记忆类型化与关系组织，并在检索期动态做查询路由、检索预算分配、图遍历、候选打分与自适应停止；结构化多关系记忆平面存数据；System-Two 推理平面只在需复杂推理与答案合成时被唤起。过去靠 LLM 生成决定的"这条记忆归哪类、检索多少、何时停"，全部变成带概率的类型化判断。
- **数据**（LoCoMo，GPT-4o-mini 当 judge）：总分 **0.777**，相对最强基线 MAGMA（0.700）**+11.0%**；记忆构建 **158 秒**，是次快系统 Nemori（1044 秒）的 **1/6.6**；平均查询延迟 **0.93 秒**，**−36.7%**。Adversarial 分项 0.962（MAGMA 0.742）。
- **客观局限**：分数由 gpt-4o-mini 充当 judge（非人工）；对照中 MemoryOS 查询延迟 32.68 秒，基线选择影响效率观感；只有 LoCoMo 一个基准，缺真实长程验证；优势构成不均（Adversarial 单项拉升明显，其余四项互有胜负）。

### 3.3 论文 3 — JEV-as-a-Judge：费用 0.36%，最有价值的是适用边界表

- **标题 / 编号**：JEV-as-a-Judge: Accept When Confident, Escalate When Unsure，[arXiv:2609.26550](https://arxiv.org/abs/2609.26550)（v1 2026-09-22，v2 2026-09-27，cs.AI）。
- **方法**：把决策型 judge 定位成经济的**首轮过滤器**而非 LLM judge 替代品；引入盲态人工裁定处理分歧；按判据类型划出"可用 / 升级 / 先验证 / 不支持"四档边界。
- **数据**：凡判据能从文本直接读出，JEV 与 16 个生成式 / 奖励模型 judge 差距在 **3 个百分点内**，费用仅对照的 **0.36%**，中位延迟 0.15 秒；常规偏好 92.2%（GPT-6 93.5%，−1.3）、有证据支撑的事实性 87.5%（+0.8）、最终答案裁定 94.0%（−2.7）。冻结级联接受 53.7% 样本时保留对照 99% 准确率。
- **客观局限**：一旦需检查推导过程（JudgeBench −14.6）或抵抗"写得漂亮但错误"的回答（RM-Bench hard −19.8），差距立刻拉到 15–20 个百分点；以 GPT-5.6 Sol 回退、τ=0.70 接受 81.0% 样本时，准确率 91.0% 对单独 93.3%，掉 2.4 点。

### 3.4 论文 4 — Rubric Judges：级联最多只换回 1.5 个点

- **标题 / 编号**：JEV vs. LLMs as Rubric Judges: Cheaper, Faster, and Wrong in the Same Places，[arXiv:2609.29769](https://arxiv.org/abs/2609.29769)（v1 2026-09-24，v2 2026-09-28，cs.CL，58 页 37 表）。
- **方法**：取 9 个面板（来自 7 个基准）覆盖二值与分级判据，让 Jev 与 3 个 flash 级 LLM judge（Luna / Gemini / DeepSeek）在完全相同判据文本下打分，并采集人类评分者参考；关键设计是级联**不重新调用模型**，而是直接复用已记录判定，精确算出"把不确定的交给 LLM"到底能补回多少。
- **数据**：9 面板合计 Jev Choice 花费 **$0.0633**，Luna 为 29 倍、DeepSeek 66 倍、Gemini 325 倍；墙钟 30–220 倍。27 组配对比较仅 8 组差异显著，Jev 领先多在二值、落后只在分级。
- **核心洞见（全文最值钱）**：所有 judge 与人类标签一致性远低于彼此之间——ELLIPSE 上 judge–judge QWK 0.38、judge–label 仅 0.18；人类评分者参考正确率 51.4%，4 个机器 judge 全落 13–30。Jev 最自信的错误中约 **96%** 的 LLM 判定重复其错（独立误差应约一半）。**级联失效的机制是误差高度相关**：校准能告诉级联"何时该 defer"，但回退模型得在"别处"出错才行——LLM judge 几乎重复 Jev 最自信的错误。即便 oracle 阈值，级联也最多 +2.0~2.7 点。

> **综述原话收束**：Jev 的新意不在"更便宜的分类器"——类型化输出和有限选项分类是几十年前就有的东西。它提供的是**把置信度做成可路由信号的接口范式**，让"什么时候该升级"从 prompt 搬进代码。范式成立还悬着一个前提没被检验：架构与 RLCD 细节未公开、无第三方统一复现；攻击面已开始被系统刻画（选项命名敏感性 AUROC 0.94→0.23、提示注入劫持、自然上下文翻转决策，各有一篇）。这 3 篇攻击面研究属 13 篇论文波次，本文未逐一核验其 arXiv 编号，仅据综述记录发现。

## 4. Jev-Mem 实现原理拆解（最详尽的实现参考）

Jev-Mem 是 4 篇里唯一有完整开源实现的，其架构对"如何给 Agent 加一个轻量控制平面"有直接的借鉴价值。

### 4.1 三平面结构

| 平面 | 职责 |
|---|---|
| **System One：记忆控制** | 记忆类型化、关系判定、查询路由、预算分配、候选打分、证据充分性评估 |
| **Shared Memory：共享记忆** | 原始观测（含文本与 provenance）、四种关系图视图、向量与关键词索引 |
| **System Two：推理** | 从筛选出的证据做最终答案合成 |

**Write → Connect**：每条观测保留文本与 provenance，并打上重叠的 episodic / semantic / procedural / preference 评分；候选搜索找出有界既有记忆集，Jev 判定推断关系，确定性链接（如时间戳顺序）由代码处理。

**Retrieve → Assess → Expand**：向量与关键词搜索提供初始锚点；控制器选有用的图视图、分配遍历预算、给新候选打分；证据足够 / 继续搜索期望价值低 / 触达配置上限时停止；普通代码校验输出并强制图与检索上限。

### 4.2 四种关系视图

共享记忆节点同时参与 **semantic / temporal / causal / entity** 四种图视图，支撑"发生了什么 / 何时 / 为何 / 对谁"四类问题。

### 4.3 关键配置默认值（来自 JevMemConfig）

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `admission_enabled` | `false` | 保留每条有效观测（默认全收，细节日后可能有用） |
| `candidate_top_k` | 10 | 每次写入推断关系的候选上限 |
| `relation_threshold` | 0.60 | 接受推断关系的阈值 |
| `anchor_count` | 30 | 混合搜索播种检索的锚点数 |
| `answer_top_k` / `multihop_top_k` | 40 / 50 | 送回答模型的证据上限 |
| `total_graph_budget` | 80 | 图扩展努力预算 |
| `maximum_nodes` / `maximum_edges` | 60 / 2400 | 遍历工作上限 |
| `maximum_jev_calls` | 16 | 检索网络尝试的 Jev 调用上限 |

### 4.4 可复现的消融开关（实验价值高）

`--no-jev-write`（去掉写入控制）、`--no-jev-read`（去掉读取控制）、省略全部 Jev 配置即 MAGMA 基线、`--rebuild`（重建图）、`--reuse-memory`（复用既有图调检索）。计时分别记录构建 / 存取 / 查询，并落检索轨迹与决策日志——这意味着"控制平面到底贡献了多少"是可被剥离测量的。

### 4.5 本地决策后端与代码组织

- 2026-09-27 起支持 **Laya** 作本地 System-One 后端（`pip install '.[laya]'` / Apple Silicon `.[mlx]`），同一记忆管线可在 Jev 与 Laya 间切换，**无需 TypeSafe API Key**；图、检索策略、System-Two 回答模型共享。
- 代码组织：`jev_mem/`（API+CLI+离线 demo+benchmark）、`memory/`（图/向量存储、控制器、检索、评估）、`utils/`（模型适配器、打分）、`config/`（校验过的实验 profile）、`tests/`（离线回归）。Python 3.11+，依赖 OpenAI 兼容模型生成答案（可离线 mock 跑 pipeline）。

## 5. 开源平替生态（范式成立的最强证据）

Jev 发布一周内出现大量开源平替，共性三点：**(a)** 复刻 Jev 的 `POST /v1/systemone` wire protocol（现有 Jev 客户端改 baseUrl 即可切换）；**(b)** 可自托管、数据不出域；**(c)** 多数随训练包提供 RLCD 训练 / 温度拟合 / 评估。

### 5.1 Laya（最成熟的开源平替）

- 仓库 [NandhaKishorM/laya](https://github.com/NandhaKishorM/laya)（Convai Innovations），**Apache-2.0**，2026-09-18 创建，一周内 2 万+ stars。
- 三个 checkpoint：English（ModernBERT-large 421M，512 ctx）、Multilingual（mmBERT-base 322M，100+ 语言，1024 可扩 8192）、Typed-Decisions（421M，针对决策工作流微调）。内置 **Router()** 按语言/脚本在 <0.5ms 内选 checkpoint。
- 速度：CPU 单问 193–464ms，Tesla T4 32.8ms，批量 7.2ms/问；Apple Silicon **MLX 端口 7.4ms/决策、峰值 <1GB**。
- 集成：Jev 兼容 `POST /v1/systemone`、`laya-serve` HTTP 服务、MCP stdio 服务器、LangGraph 条件边、ONNX、Docker、Nix。
- **关键现实**：base checkpoint 近随机（typed-decisions 基准 0.36 vs 随机 0.318），微调后 typed-decisions 达 **0.766**（Jev 公开 0.727）；选项共享小 token 预算（Banking77：0.425 vs Jev 0.870）；**出厂校准过度自信**——维护者自己在 "Honest limits" 一节写明需微调与重校阈值。

### 5.2 NumericJev（免训练数值解码）

- 论文 [arXiv:2609.28587](https://arxiv.org/abs/2609.28587)，代码 [Bring-AI/jev-numeric](https://github.com/Bring-AI/jev-numeric)。
- 洞察：数值范围选择本身就是决策问题。用**多路决策树**递归细化区间（保留原问题上下文、无参数更新），100 值网格上十路树仅需 2 轮决策；区间归一化 MAE **1.84% vs 直接 choice 5.18%**，比"从含正确答案的候选列表直接选"高 2.93pp。把"类型化决策接口"扩展到任意精度数值输出。

### 5.3 S1Bench 公开榜与 12+ 模型

实时榜（bench.jakecuth.com）已聚集 25 个候选，代表性几档：

| 取向 | 代表 | 规模 / 协议 | 备注 |
|---|---|---|---|
| 最高准确率 | simplejev-qwen38-27b | 27B | 最接近 Jev（~0.775） |
| 平衡 | reflex-4b | 4B，Apache-2.0 | 每秒 7.2 次，−4.9pp 换 3 倍速度 |
| 极致本地速度 | decider-2b | 2B | 每秒 27 次 |
| 最佳校准 | jeff-gpu | 400M GLiFormer | **ECE 0.050** |
| 闭源 API | Jev | — | 0.775，0.42s/项 |

其余还有 Kev（Qwen 骨干 + LoRA 读头，0.8/4/9B，TypeSafe SDK 直连）、Von、OpenThai-SystemOne、SemIf（直接读 LLM logits 做选项打分，MIT）、OpenJev（DiffusionGemma）、LocalJev、NanoJev、AnyJev 等，以及多种 server 实现（Python / Rust / TypeScript）。**结论**：Jev 仍是范式前沿但已非不可替代；小模型跨异构子集泛化差距实打实，单一领域可微调小模型 + 专门阈值，跨域要么上 27B 要么接受准确率损失。

## 6. 核心范式提炼：决策 / 生成分离

把 4 篇论文与开源生态合起来，可提炼出对"造智能体"平台真正可迁移的范式，而非某个具体模型：

1. **把"if"从生成里拆出来**。Agent 里大部分 LLM 调用其实是在做一个 bounded decision（选哪个工具 / 检不检索 / 完没完成 / 这条要不要拦截）。把这些有限决策下沉到类型化决策层，强模型只做生成与复杂推理——这是 REFLEX 与 Jev-Mem 共同验证的。
2. **校准置信度作为一等路由信号**。决策层返回概率分布 + 置信度，代码依据阈值路由（升级强模型 / 落库 / 拦截），而不是把"要不要问强模型"写进提示词。这是 Jev 范式的真正支点，也是它能被一周内复刻的原因。
3. **误差相关性是级联失效的根因**（Rubric Judges 的核心洞见）。"低置信升级给强模型"听起来对，但若回退模型与决策模型**错在同一处**，级联最多换回 1.5~2.7 点。意义：路由不能只靠置信度，**回退模型必须与决策模型误差互补**（不同架构 / 不同训练数据），否则级联是假省钱。
4. **与 System 1/2、speculative decoding 的类比**。快慢分工不是新概念，但 Jev 把它做成"可路由的接口契约"；类比 speculative decoding：小模型先猜、大模型验证——差别是 Jev 把"猜"的接口标准化成 Choice/Score/Noul 并带校准置信。

## 7. 适用边界与风险（务必前置）

| 风险 | 证据 | 对平台的含义 |
|---|---|---|
| **误差相关性** | Rubric Judges：级联最多 +1.5~2.7 点；96% 自信错误被 LLM 重复 | 级联回退模型须与决策模型误差互补，否则路由是假优化 |
| **选项命名敏感性** | 攻击面研究：AUROC 0.94→0.23（仅改选项命名） | 选项文案是分布的一部分，需固定并回归测试 |
| **提示注入劫持 / 自然上下文翻转** | 攻击面研究各一篇（本文未核编号） | 决策层不能替代安全边界，须与注入防护正交 |
| **无公开架构、仅自评数据** | TypeSafe 未公开 RLCD 与架构 | 性能结论以第三方统一基准为准，不盲信官方数 |
| **小模型跨域泛化差** | S1Bench：跨异构子集差距实打实 | 自托管小模型必须按本域数据微调 + 重校阈值 |
| **校准过度自信（开源版）** | Laya base 近随机、出厂过自信 | 阈值须按本域校准，且保留对照开关 |
| **区域可用性** | Jev 不对中国内地开放 | 平台若需本地合规，优先自托管平替（Laya 等） |

## 8. 对"造智能体"平台的借鉴（结合方案，不点名）

> 本节以"以构建智能体为核心、且已具备检索面与语义面双通道的平台"为隐含对象，复用 35 号调研的口径结论：**要"依据"走检索面，要"判定"走语义面**。不具体指认任何项目资产。

**借鉴 A — 为 Agent 决策层引入"快判断"通道。**
把工具选择、检索判定、完成检测、校验门控等有限决策，从"写在提示词里的请求"下沉为类型化决策层的调用。强模型只负责开放式生成与复杂推理。REFLEX 已经量化过哪些能外包（工具选择 99%、完成 77%、检索 56%、澄清 28%）——**越需语境权衡越难替换**，所以决策层该覆盖的是高频、低语境的路由与门控，而非开放式判断。

**借鉴 B — 置信度作为一等路由信号，路由写在代码里。**
决策层返回概率分布 + 置信度，平台用阈值路由：低置信→升级强模型；高置信且低风险→直接执行；涉及不可逆/外部副作用→即使高置信也走二次确认。这把"什么时候该升级"从提示词搬进代码，是可测试、可回归的，而不是依赖模型自觉。

**借鉴 C — 若补长期记忆，记忆系统单设控制平面。**
若平台要补长程记忆（而非每次全量重放历史），Jev-Mem 的范式是直接可抄的：轻量控制器管类型化与图遍历，昂贵自回归生成移出记忆关键路径，重推理只做答案合成。其消融开关（`--no-jev-write/--no-jev-read`）也示范了"控制平面贡献多少"是可被剥离测量的——这点对平台做 A/B 与回归很有用。

**借鉴 D — 把质量校验做成"决策型 Judging + 升级"。**
平台若有资产结构化校验（如 spec 资产的字段/公理/类型校验），可先用决策模型做首轮过滤，低置信升级到强模型，并**画一张按判据类型划分的适用边界表**（JEV-as-a-Judge 最有工程价值的部分）：选项闭合、判据有据可依的任务接近持平；需检查推导过程、分级打分、风格对抗的任务要直接升级，不要硬撑。

**借鉴 E — 决策层与语义层互为补充，不互相吞没。**
决策模型管"选哪个"（执行空间约束），语义/本体层管"这个选择是否允许"（语义校验）。二者职责正交：**决策层做路由与门控，语义层做判定与溯源**。这恰好与"知识库 / 知识图谱 / 本体"三分法中"依据面 vs 判定面"的结论一致——检索面供给证据，语义面供给约束，决策层是连接两者的执行层。不要让决策层去承担语义判定的职责，也不要让语义层去承担高频路由的职责。

**落地形态建议（来自外部实践，非本平台实现）。**
- **决策 Provider 抽象**：参考 NeuroLink 的 `SystemOneDecisionProvider` 实践——把"wire 词汇（如 boolean↔noul 重命名）"与"上下文 size 上限（Jev≈33k vs Laya≈1k，按 checkpoint 变）"下沉到各 provider，上层只暴露统一的 `decide()`，fail-open 错误分类与超时重试放基类。这样闭源 Jev 与开源 Laya 可热切换。
- **开源优先、自托管**：用 Laya 等 Apache-2.0 平替自托管（数据不出域、可微调、Jev 兼容协议），避免依赖不对中国开放的闭源 API。
- **阈值必须按本域校准 + 保留对照开关**：Laya 出厂过自信，任何决策层上线前要在本域数据上重校阈值，并保留"全走强模型"的对照分支以便回归。
- **运行时依赖边界**：若平台主运行时对额外语言生态有硬约束（如不引入其他语言运行时），决策层应以**独立进程/容器**接入，而非嵌入主二进制——这与"富格式摄入按需起独立容器"的既有边界处理一致。
