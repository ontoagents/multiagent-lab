## 1. 一句话结论

**「智能体配置」与「会话配置」的分层事实上已经存在，且方向正确——不需要推翻重来，也不需要把智能体侧板的字段搬走。** 真正有必要做的是四件收口：①把「事实上是会话级」却只活在浏览器里的**模型覆盖**转正为会话行字段（最大缺口）；②把会话级覆盖语义统一为「空=跟随智能体默认」（与既有 tool_approval 对齐）；③给「临时调整配置」一个正式出口（REQ-226 池条目「对话级临时覆盖」至今未交付）；④补运行配置审计缺口（temperature/max_tokens 不进任何事件，回放无法还原）。**同时守住不该下沉的边界**：能力清单、连接器、沙箱与工作目录等授权面，永不下沉会话级。

ChatWindow（web/src/components/ChatWindow.tsx）逐控件盘点后，配置实际分布在**四个层**：

| 层 | 控件 | 存储位置 | 落数据面？ |
| --- | --- | --- | --- |
| 会话行（后端持久） | 知识库 chip（开关/选库/top_k）/ 本体 chip（方案/开关）/ 技能 chip / TraceDrawer 内审批覆盖 Select | conversation 表 | ✅ |
| **前端会话记忆（影子层）** | **模型 chip（REQ-174，`eino.chat.model.{convId}`）** / 观测级别三档（`eino.debug.{id}`）/ 调试事件入库 debug_persist（`eino.convcfg.{id}`）/ 对比状态与窗格选择（`eino.compare.{id}`）/ 对比命名剖面（`eino.compare.profiles.{id}`） | **仅 localStorage** | ❌ 换浏览器/设备即丢；后端与审计不可见 |

关键事实：**模型 chip 是会话级配置，却只存在浏览器里**——「这个会话用的是哪个模型」在数据模型中不存在，只有每次请求时的逐次下发（docs/01 REQ-174 行：`eino.chat.model.{convId}` 会话级记忆 + 单路 RunInput 逐次下发）。

### 2.4 运行时装配语义：实时读、不追溯、快照缺口

- **每次运行实时查库装配**：`resolveRunTarget` → `GetConversation` → `GetAgent`（api/handlers_runs.go:14-49）；恢复路径同样重新装配（chat/runner.go:954-974）。会话创建时**不复制任何 agent 配置**（store.CreateConversation 只存 agent_id 外键，store/conversations.go:92-129）。
- **生效语义已有定案**：Q-6「配置改了，历史对话不追溯，仅对之后的新消息生效」（docs/01 Q-6 ✅）；进行中那一轮用旧值跑完，下一轮立即用新值。
- **审计快照缺口**：`run.started` 恒落库但仅含 model 名/审批档（runner.go:267-287）；装配快照 assembly 只在 debug≥1 且 debug_persist 开启时才落（runner.go:281-286）；**temperature/max_tokens 不进任何事件**——关闭调试的普通会话，事后无法还原「这一轮实际用什么温度跑的」。唯一的整包配置版本化是 REQ-226 的「保存时」快照，与运行无关。

## 3. 分析：是否需要分开

### 3.1 先纠正问题的前提——已经分了，且分得基本对

平台的配置结构事实上已是四层：

```
Agent 定义层（agent 表 31 列）      —— 跨会话持久，定义「这个智能体是谁、默认怎么跑」
会话实例层（conversation 表）       —— 随会话持久，资源绑定 + 少量覆盖位
请求级（RunInput / PaneConfig）     —— 一次运行即逝，实验通道
前端 localStorage（影子层）         —— 浏览器内按会话记忆，数据面不存在
```

这个分层与既有决策完全自洽：Q-6（配置不追溯）、Q-11（资源绑定对话级）、REQ-135②（覆盖合并序 会话>Agent）、REQ-174（模型逐次下发）、REQ-143/144（对比窗格+剖面）。**问题不是「要不要分」，而是分得不彻底：该在会话层的没有落数据面（模型覆盖），覆盖语义两套并行（审批有「跟随」语义、模型没有），临时调整没有正式出口。**

### 3.2 四个真缺口

**缺口①：模型覆盖是影子配置（最实质）。** REQ-174 模型 chip 是使用频度最高的会话级配置，但只存 localStorage：换浏览器/设备即丢；后端完全不知道「这个会话的模型偏好」，无法进审计与回放叙事；与落库的审批覆盖构成两套机制、两种命运。回放侧只有 run.started 恒落的 model 名能事后佐证每轮实际模型——模型偏好本身则无处安放。

**缺口②：覆盖语义不统一。** 会话级覆盖已有正确范式——tool_approval 的 `''=跟随 Agent 级`（REQ-135②，合并序 会话>Agent>全局）。模型覆盖若转正，应对齐同一范式（`''=跟随智能体默认`），而不是发明第三种语义。现状是「localStorage 有值就逐请求下发」，无「跟随」表达。

**缺口③：临时调整无正式出口。** 用户想让某次会话换个温度/改句提示词试试，现有三条路都不正式：①改 agent 本体——污染该智能体的全部会话（且 PUT 整行替换、无草稿态）；②复制一个新 agent——**平台没有智能体复制功能**（无端点无按钮，fork 只存在于本体与流水线）；③对比窗格——能力齐备（窗格级 temperature/instruction/skills 全项覆盖 + 命名剖面 + REQ-144 采纳转正）但定位是无痕实验通道，剖面也存 localStorage，project 会话采纳被禁用。**REQ-226 立项时明确的「对话级临时覆盖产品化」至今未交付**（docs/18 v2.22 交付行只含配置版本+diff+回滚+工作记忆划界；docs/01 §9 池 2026-09-23 条目「对话级临时覆盖 Agent 提示词」仍在池中）——开发者早在 2026-09-23 就把「配置误改真实困扰」登记入池，本分析证实该缺口至今存在。

**缺口④：运行配置审计缺口。** temperature/max_tokens 不进任何事件；装配快照仅在调试档落库。回放/轨迹（M89 TraceDrawer）能看到「用了哪个模型、什么审批档」，看不到「什么温度、多少 token 上限」。对「配置 A/B」（REQ-223 设计里有）与事后归因，这是数据面空洞。

### 3.3 判定准则（四问，可复用于后续任何新配置的归属判定）

1. **换一个会话，这个值天然要不要不同？** 资源绑定与个人偏好类（知识库/本体方案/模型偏好）→ 会话级。
2. **修改意图是「改这个智能体」还是「调整这次对话」？** 前者改定义（agent 侧板），后者动实例（会话层/请求级）。
3. **要不要跨设备可见、进审计与回放？** 要 → 后端会话行；不要 → localStorage 或请求级。
4. **是不是一次性实验？** 是 → 请求级（对比窗格/单次覆盖），天然不该落库。

外加一条安全准绳：**授权与能力面（work_dir/工具清单/连接器/沙箱）永不下沉会话级**——work_dir 是「绑定即授权」的信任边界，会话级放开等于授权面扩散。

## 4. 分类结论：逐字段归属定案表

### 4.1 归属智能体本身（定义与默认——31 列全部保留在 agent，无一迁出）

| 组 | 字段 | 归属理由 |
| --- | --- | --- |
| 身份 | name / description / instruction / logo_url | 「这个智能体是谁」的定义核心；instruction 是人格与行为契约 |
| 模型默认 | model_conn_id / temperature / max_tokens / inference_backend | 「正常情况下怎么跑」的默认值；会话可覆盖默认（见 4.2），但默认值属于定义 |
| Context | context_mode | 上下文预算策略是能力属性，非会话偏好 |
| Harness·环境 | runtime_backend / sandbox_memory / sandbox_cpus / work_dir / verify_command | 执行环境定义；work_dir 尤其为授权面（绑定即授权），不可下沉 |
| Harness·审批默认 | tool_approval / approval_exempt / approval_timeout_hours | 审批策略的默认档；会话已有单值覆盖位（REQ-135②），但豁免清单等细粒度归 agent |
| Loop | max_iteration | 循环预算属能力定义 |
| 能力 | skills / tools | 能力装配边界；会话级只应有开关（enable_skills 已是），不应有清单覆盖 |
| 对外集成 | connectors / mcp_serve | 对外身份与凭据，绑定于智能体本体 |
| 伴生本体 | companion_ontology_id / companion_extract_hint / companion_extract_conn_id / companion_auto_threshold | 伴生绑定写侧权威在 agent（REQ-216/M47 方案 D 已定） |

### 4.2 归属会话独有（实例层——已有四类保留，建议收编一件，可选两件）

**已有（维持，不改动）**：scope/agent_id/project_id/title（身份绑定）；kb_id/enable_kb/top_k/min_score 与 runtime_profile_id/ontology_enabled（资源绑定，Q-11）；enable_skills（REQ-19g）；tool_approval（REQ-135② 覆盖位）；interrupt_state/context_state/todo_json 与 schedule（运行状态）。

**建议收编（P1，影子转正）**：

| 字段 | 现状 | 转正形态 | 理由 |
| --- | --- | --- | --- |
| **model_conn_id 覆盖** | localStorage `eino.chat.model.{convId}` + 逐请求下发 | conversation 增列（`''=跟随智能体默认`），模型 chip 改为「即选即写会话行」，请求时后端自行读会话行 | 补缺口①②；用户可见行为不变，数据面成立；与 tool_approval 同构；「配置随对话保存」（17 号 §3 既有口径）自此在后端为真 |

**可选（P2，观察）**：

| 字段 | 说明 |
| --- | --- |
| temperature 覆盖 | 对比窗格已证明单会话调温诉求；但频度低于换模型，且应与 REQ-226 池条目合并评估，不单独立项 |
| debug_persist / 观测级别 | debug_persist 影响后端落库行为（model.step/assembly 是否入库），严格说有语义；二选一：转正进会话行，或维持 localStorage 但 UI 标注「仅本浏览器记忆」（诚实原则） |
| 对比命名剖面（模型项） | `eino.compare.profiles.{convId}` 若 P1 落地，剖面中模型项可一并转正；整剖面产品化仍属 REQ-144 采纳转正的延伸，观察 |

**不建议上会话级（边界，明确不做）**：

| 项 | 理由 |
| --- | --- |
| instruction 会话级覆盖 | REQ-226 池条目提的「对话级临时覆盖提示词」若产品化，**建议形态是「会话绑定配置版本」（复用 agent_config_version 快照选版本生效）而非自由编辑**——自由编辑会混淆「改的是定义还是本次对话」，且对比窗格已提供无痕实验通道。维持请求级，池内观察 |
| tools / skills / connectors 清单覆盖 | 能力边界应稳定可审计；会话级清单覆盖等于每个会话都可能是一个未登记的新智能体 |
| 沙箱 / work_dir / 审批豁免清单 | 授权面，安全准绳（3.3）一票否决 |
| max_iteration / context_mode 覆盖 | 低频且属能力定义，无诉求证据 |

### 4.3 请求级（维持不落库）与 UI 偏好层

- RunInput.model_conn_id（单次）/ debug_level / debug_persist / panes[]（含窗格级 temperature/instruction/skills/no_history）——对比窗格本就是无痕实验通道，一次运行即逝是正确语义，**不因 P1 收编而改变**（P1 只是把「会话默认模型」从影子层提到数据面，请求级覆盖的优先序仍在其上）。
- 全局 UI 偏好（主题/侧栏宽/抽屉宽/显示粒度/深度思考显隐/对比开关与列数）——与智能体行为无关，维持 localStorage，不属配置分层议题。

### 4.4 覆盖合并序（P1 落地后的统一口径）

```
请求级（RunInput/Pane） > 会话级（conversation，''=跟随） > Agent 默认（agent，空=跟随） > 全局默认连接（chat）
```

与 REQ-135② 审批合并序同构，一处范式两处复用。诚实边界沿 REQ-174 注记不变：docker/外部 CLI 推理后端的模型由其自身配置决定，覆盖（无论请求级还是会话级）不生效，UI 如实标注。

## 5. 演进建议（拍板后按 18 号注册表取号立项）

**P1 最小闭环（一件转正 + 一件审计补齐）**
1. conversation 增 `model_conn_id` 覆盖列（`''=跟随`，迁移 + Update COALESCE 保 nil 语义对齐 enable_skills/tool_approval 先例）；模型 chip 从 localStorage 改写会话行；回归 REQ-174 交互不变。
2. `run.started` 事件 data 增 `temperature`/`max_tokens` 两键（恒落，与既有 model 名同级）——审计缺口④的最小补法，零新表。

**P2（观察/随批）**：温度覆盖列；debug_persist 转正或标注；对比剖面模型项转正；REQ-226 池条目「对话级临时覆盖 Agent 提示词」以「会话绑定配置版本」形态出池评估。
