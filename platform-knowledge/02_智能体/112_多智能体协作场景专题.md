# 多智能体协作场景专题

> **状态：v0.1（2026-10-31）**——首建（开发者指令：「将多agent配合执行复杂任务的使用场景，在平台知识/智能体下创建专题来进行研究和演进」）。专题文档聚焦**功能场景的实现方案形态**（协作模式/角色分工/人机介入点/产物与治理），**不落具体实现手段**（引擎选型/代码锚点/迁移细节不进本档，一律指针到 §五 实现文档）；能力状态权威=docs/02 §12+18 号，本档只写「已具备/立项在途/观察」三档粗粒度。新档无前版。

## 〇、专题定位与口径

- **专题主语**：多 agent 配合执行复杂任务的**使用场景**——谁和谁配合、怎么分工、人在哪里介入、产出什么、如何可信。研究与演进的落点在场景与方案形态，不在实现。
- **双层坐标（开发者 2026-10-31 拍板口径，本专题的顶层分类学）**：
  - **顶层·项目/工作空间多 Agent 团队协作**：用户创建多个智能体 Agent 实体，成员既可为**内置运行时**（进程内完整能力），也可经 **CLI/A2A/MCP 连接器**对接外部智能体；多 Agent 在项目/工作区容器中协作配合完成同一件复杂任务。
  - **底层·单 Agent 内多子 agent 动态工作流**：单个 Agent 内部创建多个不同角色/任务的子 agent，以动态工作流方式配合实现复杂任务（确定性拓扑 → 线性计划 → 动态 DAG 的谱系演进）。
  - **两层正交可组合**：项目中的每个成员 Agent 自身都可配置内部工作流，「团队中的成员自己是一支小队」是两层贯通的自然延伸——现状委派深度=1（成员无子智能体），贯通项列 §六 开放点。
- **收录约定**：本档是场景研究与演进的**导航+账本**；实现细节落各实现文档（§五），本档不复述状态机/迁移/代码锚点；新场景按 §六 四段式追加。

## 一、协作谱系（场景自由度从低到高）

| 谱系档位 | 场景自由度 | 一句话方案形态 | 状态 |
| --- | --- | --- | --- |
| 自由协作（free + agent_as_tool） | 协调者模型自主分解/路由/并行 | 描述即路由：成员 description 是协调者「何时委派给谁」的依据 | 已具备（默认推荐档） |
| 确定性拓扑三档（sequential/parallel/loop） | 装配期静态拓扑 | 按固定顺序/并行/循环装配成员执行，节点级事件+进度条带 | 已具备（loop 有界） |
| 线性计划执行（plan_execute） | 计划一次+逐项执行+重规划 | planner 产任务清单→executor 逐项→replanner 修正（有界循环） | 已具备；WF 批拍板「先双轨，演进终点被 dag 取代」 |
| 动态工作流（dag） | 运行期模型合成拓扑+人确认 | 任务描述→合成 DAG（节点/条件边/并行组）→计划确认卡→执行 | 立项在途（WF 批八件） |

> 两条横贯主线（非档位）：①**对话式→结构化协作**（107 号八域——计划/分歧/上下文/过程资产/运行控制/演示交付的结构化）；②**成员来源混编**（内置/CLI/A2A/stdio 四类成员同队）。二者叠加在任一谱系档位上。

## 二、顶层场景族：项目/工作空间多 Agent 团队协作

> 容器：项目（成员团队+协作配置+共享文件）与工作区（REQ-548~551——项目之上的领域容器，默认库/方案/智能体创建时继承）。本专题将两者视作同一场景族的两种容器粒度。

### S1 混编组队（四类成员一个团队）
- **场景**：一件复杂任务需要平台内 Agent 与外部智能体（本机 CLI 智能体、远端 A2A agent、本地 stdio MCP server）同队干活。
- **方案形态**：成员=连接器统一抽象（内置/CLI/A2A/stdio 四类）；混合编排模板一键建「本地规划者+CLI 编码者+A2A 审查者」三色团队；协作研发场景模板与种子；外部智能体反向互发现平台资产。
- **现状**：已具备。**指针**：00_智能体模块 模块级总表（REQ-416/417/426/431/433/434/446 行）；39 号 A2A 包装器参考。

### S2 协调与路由
- **场景**：任务来了，谁接哪段——路由决策要可解释、可治理。
- **方案形态**：协调者角色+「描述即路由」语义（成员描述=路由依据）；成员能力画像注入（连接器探测+注册表/card 合成画像，协调者按画像在三类成员间裁量路由）；委派走 agent_as_tool 包装轨（transfer 对照轨保留+风险标注）。
- **现状**：已具备（画像路由/transfer 治理定案）。**指针**：56 号 Graph 域事实源；78 号调度分析。

### S3 委派与并行执行
- **场景**：委派出去的活不占死协调者——多成员真并发、失败能兜、跑偏能拉回。
- **方案形态**：后台委派底盘（子会话异步执行+steer/continue/interrupt 全套操控）；委派韧性三件（错误降级回喂/单成员超时/委派单事件）；同轮多委派并行（单委派调用同步等待语义，多委派间并发）；委派深度=1 为现状边界。
- **现状**：已具备；长时子调用异步化立项在途◐（REQ-385 LongRun 评估件已交付）。**指针**：56 号；78 号（实证与建议收口）。

### S4 上下文与资产供给
- **场景**：外部成员没有平台上下文——干活的输入从哪来、产出回哪去。
- **方案形态**：委派外部成员时项目上下文三源注入（项目文件清单/知识库检索/本体 guide 摘要），上下文注入开关显式确认（内容随委派外发的边界）；外部成员可被工作流节点/transfer 轨消费（混合编排全轨）。
- **现状**：已具备。**指针**：00_智能体模块 总表（REQ-430/446 行）；54 号 Context 域。

### S5 过程可视化与跨协议审计
- **场景**：多成员各自跑，过程黑盒不可接受——跨协议（内置/CLI/A2A）过程要一个视角看完。
- **方案形态**：委派时间线/多泳道分色/协作拓扑图/过程树与分级展开；外部成员过程事件统一转译进平台事件面；调用轨迹面板+运行回放（live-回放对称）。
- **现状**：已具备。**指针**：00_智能体模块 总表（REQ-217/284/311/416/428 行）；53 号（事件契约域）。

### S6 治理（审批/沙箱/凭据/成本）
- **场景**：外部成员会执行代码、碰凭据——治理必须与内置成员同一套，不因「外部」降级。
- **方案形态**：外部成员委派纳入审批档（danger/all 均审+豁免透传）；CLI 子进程容器沙箱（三前置闸门）；凭据服务端注入执行环境、不进模型上下文不进工具参数；MCP 工具注解读取收窄审批面。
- **现状**：已具备。**指针**：53 号 Harness 域事实源。

### S7 对外成员输出（反向：平台=协议枢纽）
- **场景**：平台 Agent 作为**外部系统**的成员被调用——协作能力双向而非单向。
- **方案形态**：agent-as-MCP-server（统一端点+token 鉴权）；A2A server 端点（agent card+消息/任务落库+访问授权）；input-required 交互通道（外部侧反问透传给平台用户再回喂）。
- **现状**：已具备；A2A FilePart 富媒体件触发驱动 📋（REQ-447）。**指针**：00_智能体模块 总表（REQ-131/132/369/387/432 行）。

### S8 计划结构化与分歧裁决（立项在途）
- **场景**：对话式协作的计划靠自由文本承载、方案分歧靠协调者自由汇流——复杂任务下计划要可查可控、分歧必经人裁决。
- **方案形态**：DAG 计划与调度（规划者产结构化计划→无环校验→按依赖并行派发→失败策略+汇合聚合+DAG 视图+重启对账恢复）；方案分歧结构化识别（评审 verdict 协议+平台确定性规则判定）→人工裁决卡（A/B/第三案）→结构化回注双方续跑，全过程事件落库。
- **现状**：立项在途（REQ-552/553）。**指针**：107 号 §三/§四。

### S9 过程资产化与运行控制（立项在途）
- **场景**：协作过程本身是资产（复盘/交接/合规）；长任务要能安全暂停、从锚点重做。
- **方案形态**：运行事件流导出为自包含回放文件；多智能体过程账本（参与度/人工介入/耗时归因）；pause 安全点挂起+redo 锚点重放重跑。
- **现状**：立项在途（REQ-555/557/558）。**指针**：107 号 §六/§八/§九。

### S10 研发数据源接入与演示交付（立项在途）
- **场景**：协作的输入要接真实研发数据源；成果要能一键演示给外部人看（含远程可访问）。
- **方案形态**：五类研发数据源统一接入既有连接器体系（不另起炉灶）；演示环境一键灌装+只读凭证+远程部署路径；与主流框架对比提纲（能力自证文档件）。
- **现状**：立项在途（REQ-554/556/559）。**指针**：107 号 §五/§七/§十。

## 三、底层场景族：单 Agent 内多子 agent 动态工作流

> 主体=一个 Agent 的内部编排：子 agent 各担角色/任务，以工作流方式配合。产品宿主=项目协作配置的 workflow_mode 档位族；本档只写形态口径，实现细节见 56 号+79/108/109 号。

### W1 确定性拓扑三档（sequential/parallel/loop）
- **场景**：角色与顺序已知、不需要模型临场编排的流水线（如「起草→审校→定稿」三棒接力）。
- **方案形态**：装配期静态拓扑三原语（顺序/并行/循环）；节点级事件+只读进度条带+HITL 节点标注；loop 有界防死循环。
- **现状**：已具备。**指针**：56 号。

### W2 线性计划执行（plan_execute）
- **场景**：任务可分解为清单，逐项执行、跑偏了修正计划再继续。
- **方案形态**：planner 产任务清单→executor 逐项执行→replanner 修正（循环有界）；预置角色自带提示词；无成员时降级语义诚实标注。
- **现状**：已具备；WF 批拍板「先双轨、演进终点被 dag 取代」（存量零迁移，dag 稳定后另立评估件拍板收口）。**指针**：56 号；docs/18A REQ-455 行。

### W3 动态工作流（dag，立项在途）
- **场景**：任务结构未知——让模型从任务描述合成执行拓扑，人确认后再跑；中途有门禁断言、人审卡点；失败节点可重跑。
- **方案形态**（四层形态口径）：①**schema 与校验**：类型化 DAG schema+校验闭环四项（环检测/悬空边/汇聚语义/变量类型）+类型化变量表（节点间结构化传值）；②**执行引擎**：节点=模型/工具/门禁断言三类，顺序+并行组执行，一等节点生命周期事件（引擎状态机自发非启发式），运行快照+冷恢复+节点级重跑（下游失效语义）；③**拓扑合成**：模型产 DAG+护栏五件（节点数/并行度/单节点与全局预算/门禁重试上限/回边迭代上限），校验失败回喂修复有界、仍败降级线性链保底；④**计划确认卡**：线性步骤列表+分支点译成「如果…就…」问句+只读图+表单化微调（**不做画布**——产品口径 Q-7/REQ-205⑤「可视化只读、不引入编辑器」不反转）。
- **现状**：立项在途（REQ-560 L0 评估 ✅→REQ-562~569 八件 📋 严格串行领取）；go 终裁六子项已拍板（danger 断言=内置断言工具形态/并行组多 HITL 一期串行呈现/plan_execute 先双轨）。**指针**：79 号评审终稿（四层架构+借鉴/重造清单+护栏五件）；108 号 L0 评估（断点量化）；109 号专项评审（切粒度+拍板七条）。

### W4 子 agent 过程观测与人机卡点
- **场景**：子 agent 干到哪一步、卡在哪、哪里必须人拍板——观测与介入要在正确的粒度上。
- **方案形态**：子 agent 进出场事件→轨迹嵌套呈现（现状粒度）；一等节点生命周期事件（WF 批改造点：由引擎状态机自发，替代名称启发式）；门禁断言节点走既有审批三档包装；人审卡点跨重启可恢复；并行组多卡点挂起一期按恢复序串行呈现。
- **现状**：基础已具备（子 agent 事件/轨迹/审批）；一等事件与门禁节点立项在途（REQ-563/564）。**指针**：56 号；109 号。

## 四、横切关注点（两层共用，场景设计的约束面）

- **治理**：审批三档（会话级可覆盖）+全量工具调用审计+运行配置审计；容器沙箱与凭据托管。——53 号
- **韧性**：错误降级回喂（中断类穿透）；单成员超时；挂起-恢复（定向恢复契约）；checkpoint 冷恢复；重启对账（孤儿任务清点）。——53/55/56 号
- **可观测**：事件契约注册表单源；回放与 live 对称；泳道/拓扑/时序条三类过程视图。——53 号+00 总表
- **上下文工程**：预算三档+压缩持久化；注入内容预算复检（动态工作流变量注入纳入复检口径——WF 批立项承诺）；外部成员注入显式确认。——54 号
- **成本护栏**：既有锚点=委派超时 10min/迭代上限缺省 25/loop 上限 3；WF 批新增护栏五件（节点数/并行度/预算/门禁重试/回边上限）。——79 号 §一
- **诚实边界通则**：单机自部署（无分布式调度、无子代理云、无模板市场）；成员产出对协调者=摘要级回传（全文在成员侧）；计划/拓扑合成质量依赖模型结构化输出能力，校验失败如实报错不虚构兜底；审批/审计语义对内外成员一视同仁。——107 号各域诚实边界节

## 六、开放点与演进约定

**开放点（收敛结论回写本节并记 §七）**
